## 변경 배경

이 커밋은 SuperPlatform SSO 인증 설정에서 `internal-api.base-url`이 `server-url`과 항상 동일한 도메인을 사용하는 점을 개선하여 설정 중복을 제거하고 유지보수성을 높이기 위한 변경입니다.

- **목적**: `internal-api.base-url`을 `server-url` 기반으로 자동 derive하여 환경별 yml 파일에서 중복 설정 제거 및 설정 누락 시 기본값 오류 방지
- **도메인**: 인프라 / 설정 (Configuration)
- **변경 방향**: 하드코딩된 기본값과 환경별 중복 정의를 제거하고, `server-url`을 단일 진실 공급원(Single Source of Truth)으로 삼아 자동 파생시키는 방향으로 개선

## [GOOD] 잘된 점

- **설정 중복 제거**: dev 환경 yml에서 `internal-api.base-url`이 `server-url`과 동일한 값으로 중복 정의되어 있었는데, 이를 제거하여 DRY 원칙을 잘 지켰습니다.
- **하위 호환성 유지**: `${SP_AUTH_INTERNAL_API_URL:...}` 환경변수 기반 오버라이드를 그대로 유지하여 기존 환경변수 주입 방식과 충돌하지 않습니다.
- **명확한 주석**: "도메인 중복 방지", "환경 yml에서 server-url만 정의하면 자동으로 따라간다"는 주석이 변경 의도를 명확히 설명하고 있어 유지보수에 도움이 됩니다.

## 변경사항 요약

공통 `application.yml`에서 `internal-api.base-url`의 기본값을 `${SP_AUTH_SERVER_URL:http://localhost:8080}/api/v1`로 변경하고, dev 환경 `application-vs-dev.yml`에서 중복되던 `internal-api.base-url` 설정을 제거했습니다.

### Medium (개선 권장)

1. **중첩 placeholder 치환 순서에 대한 문서화 부재**
   - **위치**: `application.yml` 145번째 줄
   - **내용**: `base-url`의 기본값이 `${SP_AUTH_INTERNAL_API_URL:${SP_AUTH_SERVER_URL:http://localhost:8080}/api/v1}`로 정의되어 있습니다. Spring Boot는 중첩된 placeholder를 재귀적으로 치환하므로 실제로는 문제가 없습니다. 다만, 이 설정을 처음 보는 개발자가 "`SP_AUTH_INTERNAL_API_URL`이 없으면 `SP_AUTH_SERVER_URL`을 쓰고, 그것도 없으면 `http://localhost:8080`을 쓴다"는 의도를 한눈에 파악하기 어려울 수 있습니다. 주석에 이 치환 순서를 명시하면 가독성이 더 좋아집니다.
   - **제안**: 주석에 "fallback chain: SP_AUTH_INTERNAL_API_URL → SP_AUTH_SERVER_URL → localhost:8080" 정도를 추가

## 주요 파일 분석

### `backend/src/main/resources/application.yml`

**변경 내용:**
`internal-api.base-url` 기본값을 `${SP_AUTH_INTERNAL_API_URL:http://localhost:8080/api/v1}`에서 `${SP_AUTH_INTERNAL_API_URL:${SP_AUTH_SERVER_URL:http://localhost:8080}/api/v1}`로 변경.

**변경 전 코드 (145번째 줄):**
```yaml
base-url: ${SP_AUTH_INTERNAL_API_URL:http://localhost:8080/api/v1}
```

**변경 후 코드 (145번째 줄):**
```yaml
base-url: ${SP_AUTH_INTERNAL_API_URL:${SP_AUTH_SERVER_URL:http://localhost:8080}/api/v1}
```

**분석:**
- 변경 전: `SP_AUTH_INTERNAL_API_URL` 환경변수가 없으면 무조건 `http://localhost:8080/api/v1`로 고정. dev 환경에서는 이 값을 항상 재정의해야 했음.
- 변경 후: `SP_AUTH_INTERNAL_API_URL`이 없으면 `SP_AUTH_SERVER_URL` 값을 읽고, 그것도 없으면 `http://localhost:8080`을 사용한 후 `/api/v1`을 붙임.
- 결과적으로 dev 환경에서 `server-url: https://t-auth-superplatform-api.vsaidt.com`만 정의하면 `internal-api.base-url`이 자동으로 `https://t-auth-superplatform-api.vsaidt.com/api/v1`로 결정됨.

**개선 제안:**
없음. 변경 자체는 적절하며, 중첩 placeholder를 통한 자동 derive 방식은 Spring Boot 표준 기능을 활용한 좋은 접근입니다.

### `backend/src/main/resources/application-vs-dev.yml`

**변경 내용:**
`internal-api.base-url` 설정 블록 전체를 제거하고 주석으로 대체.

**변경 전:**
```yaml
superplatform:
  auth:
    server-url: https://t-auth-superplatform-api.vsaidt.com
    client-id: ${SP_AUTH_CLIENT_ID:test-service}
    client-secret: ${SP_AUTH_CLIENT_SECRET:test-secret-1234!}
    internal-api:
      base-url: https://t-auth-superplatform-api.vsaidt.com/api/v1
```

**변경 후:**
```yaml
superplatform:
  auth:
    server-url: https://t-auth-superplatform-api.vsaidt.com
    client-id: ${SP_AUTH_CLIENT_ID:test-service}
    client-secret: ${SP_AUTH_CLIENT_SECRET:test-secret-1234!}
    # internal-api.base-url 은 공통 application.yml 에서 server-url 기반으로 자동 derive.
```

**분석:**
- `internal-api.base-url`이 `server-url`과 동일한 도메인(`https://t-auth-superplatform-api.vsaidt.com`)을 사용하므로, 공통 설정의 자동 derive 로직으로 충분히 커버됩니다.
- 제거된 설정값이 `server-url`과 정확히 일치하므로 기능적 차이는 전혀 없습니다.

**개선 제안:**
없음. 제거 자체가 적절하며, 주석으로 변경 의도를 남긴 점도 좋습니다.
