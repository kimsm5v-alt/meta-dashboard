## 변경 배경

이 커밋은 `MetaAgentService._build_system_prompt` 메서드의 시스템 프롬프트를 전면 개편하여 LLM의 할루시네이션을 방지하고 Neo4j Tool 호출 정책을 명확히 하는 것이 목적입니다. 기존 프롬프트는 "필요 시 위 식별자로 Neo4j Tool을 호출하십시오"라는 모호한 수준의 가이드라인이었으나, 이번 변경으로 데이터 우선순위 체계, 창작 금지 규칙, 근거 표기 의무, 도메인 한정 등 구체적인 운영 원칙을 시스템 프롬프트에 포함시켰습니다.

- **목적**: LLM 할루시네이션 방지 및 Tool 호출 정책 강화
- **도메인**: 비즈니스 로직 (LLM 프롬프트 엔지니어링)
- **변경 방향**: 모호한 가이드라인에서 구체적이고 강제성 있는 규칙 기반 프롬프트로 개선

## [GOOD] 잘된 점

**1. 할루시네이션 방지 규칙의 체계적 도입**

변경된 프롬프트는 4가지 명확한 규칙을 제시합니다:
- **창작 금지**: 컨텍스트에 없는 학생의 개인정보, 성격, 가정환경, 성적 등을 추측하거나 창작하지 말 것
- **불확실성 명시**: 확인할 수 없는 내용은 "제공된 데이터에서 확인할 수 없습니다"라고 명시
- **근거 표기**: 핵심 판단의 근거가 컨텍스트 T점수인지, Neo4j Tool 결과인지 간략히 밝힐 것
- **도메인 한정**: 학습심리정서검사와 무관한 질문에는 범위 외 질문임을 안내

이는 LLM이 임의로 내용을 생성하는 문제를 체계적으로 차단하는 실무적인 접근입니다.

**2. 데이터 우선순위 계층화**

프롬프트는 답변의 근거가 되는 데이터 소스에 명확한 우선순위를 부여했습니다:
1. 학생 컨텍스트 (T점수, 4단계 진단, 상담기록)
2. Neo4j Tool 조회 결과 (LPA 유형 특성, 조절/매개 경로, 집단 평균 T점수)
3. 학습심리정서 도메인 일반 지식 (위 두 소스를 보완하는 수준에서만 제한적 활용)

이러한 계층화는 LLM이 어떤 데이터를 우선 참조해야 하는지 명확히 하여 일관된 답변 품질을 보장합니다.

**3. Tool 결과 빈 값 처리 지침**

Tool 결과가 빈 목록(`[]`)이거나 오류를 반환할 때 "해당 데이터를 현재 조회할 수 없습니다"라고 안내하고 임의로 내용을 창작하지 말라는 구체적인 예외 처리 지침을 포함한 점이 실무적으로 매우 적절합니다. 이는 LLM이 데이터 부재 상황에서도 할루시네이션을 발생시키지 않도록 방어하는 중요한 장치입니다.

## 변경사항 요약

`_build_system_prompt` 메서드의 반환 문자열을 단순한 2-3줄짜리 텍스트에서 마크다운 헤더 구조를 가진 상세한 시스템 프롬프트(역할 정의, 데이터 우선순위, 할루시네이션 방지 규칙, Tool 호출 정책)로 확장했습니다. Tool 호출 조건도 "필요 시"라는 모호한 표현에서 "반드시 Neo4j Tool을 호출하여 실제 데이터를 확보한 후 답변하십시오"라는 강제성 있는 표현으로 변경했습니다.

### Medium (개선 권장)

**1. `profile_block`과 `tool_policy`의 출력 순서로 인한 가독성 저하**

현재 `return` 문에서 `tool_policy`를 먼저 출력하고 `profile_block`을 뒤에 출력하고 있습니다(라인 131-133). 그런데 `profile_block`에는 학생 식별자 정보(`className`, `schoolLevel`)가 포함되어 있고, `tool_policy`는 이 식별자를 전제로 한 호출 정책을 설명합니다. 즉, 독자가 `tool_policy`를 읽을 때는 아직 학생 식별자 정보를 모르는 상태입니다.

**기존 코드 (라인 131-133):**
```python
f"## Neo4j Tool 호출 정책\n{tool_policy}"
f"{profile_block}"
```

**제안하는 수정 코드:**
```python
f"{profile_block}"
f"## Neo4j Tool 호출 정책\n{tool_policy}"
```

**근거**: `read_file`로 전체 메서드(라인 56-136)를 확인한 결과, `profile_block`에는 학생 식별자(`className`, `schoolLevel`)가 포함되어 있고, `tool_policy`는 이를 전제로 한 호출 정책을 설명합니다. 순서를 바꾸면 독자가 식별자를 먼저 인지한 상태에서 정책을 읽게 되어 인지 흐름이 개선됩니다. `else` 분기에서 `profile_block`이 빈 문자열일 때도 단순히 빈 문자열이 먼저 출력될 뿐 기능상 부작용은 없습니다.

**2. `else` 분기에서 불필요한 빈 문자열 삽입**

`else` 분기(라인 93-96)에서는 `profile_block`이 빈 문자열(`""`)로 설정됩니다. 이후 `return` 문에서 `f"{profile_block}"`이 실행되면 결과 문자열에 불필요한 빈 줄이 삽입됩니다. 기능상 문제는 없으나, `else` 분기에서 `profile_block` 자체를 생략하거나 조건부로 포함시키는 방식이 더 깔끔합니다.
