## 변경 배경

이 커밋은 FastAPI 애플리케이션의 생명주기(lifespan) 관리를 도입하여, 서버 시작 시 Neo4j 데이터베이스 연결을 명시적으로 초기화하고 종료 시 안전하게 리소스를 해제하는 기능을 추가합니다.

- **목적**: Neo4j 연결의 명시적 초기화 및 종료 처리를 통해 리소스 누수 방지 및 연결 안정성 확보
- **도메인**: 인프라 (데이터베이스 연결 관리)
- **변경 방향**: 기존에는 로깅 설정 코드가 전역 레벨에 위치하고 연결 관리는 암시적으로 이루어졌으나, `lifespan` 컨텍스트 매니저를 도입하여 애플리케이션 생명주기에 맞춰 명시적으로 관리하도록 개선

---

## [GOOD] 잘된 점

**1. 적절한 리소스 생명주기 관리**
`@asynccontextmanager`를 활용한 `lifespan` 패턴 도입으로, FastAPI의 권장 방식에 따라 startup/shutdown 로직을 명확히 분리했습니다. startup 시점에 `Neo4jConnectionManager.get_driver()`를 호출하여 드라이버를 초기화하고, shutdown 시점에 `await Neo4jConnectionManager.close()`로 리소스를 정리하는 구조가 명확합니다.

**2. 로깅 설정 위치 상향 조정**
`logging.basicConfig`와 `logger` 초기화를 `lifespan` 함수보다 먼저 배치하여, lifespan 내부에서도 로깅이 정상 동작하도록 한 점이 세심합니다. 이는 기존 코드에서 로깅 설정이 `lifespan` 이후에 위치했다면 startup 로그가 출력되지 않았을 문제를 사전에 방지한 것입니다.

**3. 싱글톤 매니저와의 일관성**
`Neo4jConnectionManager`는 싱글톤 패턴과 Lazy-loading 방식(`get_driver()`)을 사용합니다. `lifespan` startup에서 `get_driver()`를 호출하여 드라이버를 초기화함으로써, 이후 모든 쿼리 실행 시점에서는 이미 초기화된 드라이버를 안전하게 사용할 수 있습니다. 이는 `app/tools/neo4j_tools.py`에 정의된 `_execute_query` 함수에서 `Neo4jConnectionManager.get_driver()`를 호출하는 방식과 일관성을 유지합니다.

### Medium (개선 권장)

**1. startup 시 연결 실패에 대한 명시적 처리**

`lifespan` 함수 내부에서 `Neo4jConnectionManager.get_driver()`를 호출할 때, 반환값을 확인하지 않고 있습니다. `get_driver()` 메서드의 구현을 보면 내부에서 예외를 캐치하고 `None`을 반환할 수 있습니다.

```python
# app/tools/neo4j_tools.py - get_driver() 메서드
@classmethod
def get_driver(cls):
    if cls._driver is None:
        uri = os.getenv("NEO4J_URI", "bolt://localhost:7687")
        user = os.getenv("NEO4J_USERNAME", "neo4j")
        password = os.getenv("NEO4J_PASSWORD", "test1234")
        try:
            cls._driver = AsyncGraphDatabase.driver(uri, auth=(user, password))
        except Exception as e:
            logger.error(f"Neo4j 드라이버 초기화 실패: {e}")
    return cls._driver
```

연결 실패 시 `get_driver()`는 `None`을 반환하지만, `lifespan` 함수는 이를 무시하고 정상 진행합니다. 다만, 이후 실제 쿼리 시점에 `_execute_query` 함수에서 `driver is None` 체크를 통해 graceful degradation이 이루어지므로, 현재 설계도 실용적인 선택입니다. 개선 사항으로는 startup 시 연결 실패를 감지하여 더 명시적인 경고 로그를 남기거나, 필요에 따라 서버 시작을 중단하는 옵션을 고려할 수 있습니다.

**2. 불필요한 공백 라인**

기존 로깅 설정 코드가 제거되면서 CORS 미들웨어 추가 이후에 3줄의 공백 라인이 남았습니다. 코드 가독성에 큰 영향을 주지는 않지만, 자동 포매터(pre-commit hook의 black, ruff 등)를 통해 정리하면 좋습니다.
