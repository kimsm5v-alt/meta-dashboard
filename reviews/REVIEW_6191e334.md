**1. midcategory_avg 쿼리의 파라미터 바인딩 순서 가독성 개선**

- **위치 (라인 번호)**: 924~941 (`agent/app/tools/mysql_tools.py`)
- **현재 코드**:

```python
midcat_rows = await _execute_query(
    f"""
    SELECT di.cla_id, s.SECTION_NM AS section_nm, s.SECTION_NM_FULL AS section_nm_full,
           ROUND(AVG(ar.T_SCORE), 1) AS avg_t_score,
           COUNT(DISTINCT ar.ANSWER_IDX) AS student_count
    FROM tb_dgnss_answer_report ar
    JOIN tb_dgnss_section s ON s.SECTION_ID = ar.SECTION_ID
    JOIN tb_dgnss_answer a ON a.ANSWER_IDX = ar.ANSWER_IDX
    JOIN tb_dgnss_result_info ri ON ri.id = a.DGNSS_RESULT_ID
    JOIN tb_dgnss_info di ON di.id = ri.dgnss_id
    JOIN (
        SELECT cla_id, MAX(ord_no) AS ord_no FROM tb_dgnss_info
        WHERE paper_idx = %s GROUP BY cla_id
    ) latest ON latest.cla_id = di.cla_id AND di.ord_no = latest.ord_no
    WHERE di.cla_id IN ({placeholders}) AND di.paper_idx = %s AND {_MID_CATEGORY_SECTION_FILTER}
    GROUP BY di.cla_id, s.SECTION_ID, s.SECTION_NM, s.SECTION_NM_FULL
    ORDER BY di.cla_id, s.SECTION_NM
    """,
    (_LEARNING_PAPER_IDX, *cla_ids, _LEARNING_PAPER_IDX),
)
```

- **문제 분석**: SQL 쿼리에는 3개의 파라미터 플레이스홀더(`%s`)가 있습니다:
  1. 서브쿼리 `WHERE paper_idx = %s` → `_LEARNING_PAPER_IDX`
  2. `WHERE di.cla_id IN ({placeholders})` → `*cla_ids` (N개)
  3. 메인쿼리 `AND di.paper_idx = %s` → `_LEARNING_PAPER_IDX`

  현재 파라미터 튜플 `(_LEARNING_PAPER_IDX, *cla_ids, _LEARNING_PAPER_IDX)`는 이 순서와 정확히 일치하므로 **버그는 아닙니다**. 하지만 `_LEARNING_PAPER_IDX`가 서브쿼리와 메인쿼리에 각각 한 번씩 등장하는데, 그 사이에 `*cla_ids`가 끼어 있어 파라미터와 SQL의 `%s` 위치를 매핑하기 어렵습니다.

  기존 Tool들(`query_teacher_classes_overview` 라인 660, `query_class_risk_students` 라인 841)은 `_LEARNING_PAPER_IDX`가 연속으로 등장하는 패턴(`(_LEARNING_PAPER_IDX, _LEARNING_PAPER_IDX, ...)`)을 사용하는 반면, 여기서는 서브쿼리와 메인쿼리의 `%s` 사이에 `*cla_ids`가 끼어 있어 일관성이 떨어집니다.

- **개선 제안**: SQL 쿼리 내에 주석으로 각 `%s`가 어떤 파라미터에 대응하는지 명시하면 유지보수 시 혼동을 줄일 수 있습니다.

```python
midcat_rows = await _execute_query(
    f"""
    SELECT di.cla_id, s.SECTION_NM AS section_nm, s.SECTION_NM_FULL AS section_nm_full,
           ROUND(AVG(ar.T_SCORE), 1) AS avg_t_score,
           COUNT(DISTINCT ar.ANSWER_IDX) AS student_count
    FROM tb_dgnss_answer_report ar
    JOIN tb_dgnss_section s ON s.SECTION_ID = ar.SECTION_ID
    JOIN tb_dgnss_answer a ON a.ANSWER_IDX = ar.ANSWER_IDX
    JOIN tb_dgnss_result_info ri ON ri.id = a.DGNSS_RESULT_ID
    JOIN tb_dgnss_info di ON di.id = ri.dgnss_id
    JOIN (
        SELECT cla_id, MAX(ord_no) AS ord_no FROM tb_dgnss_info
        WHERE paper_idx = %s          -- [1] _LEARNING_PAPER_IDX (서브쿼리)
        GROUP BY cla_id
    ) latest ON latest.cla_id = di.cla_id AND di.ord_no = latest.ord_no
    WHERE di.cla_id IN ({placeholders})  -- [2..N] cla_ids
      AND di.paper_idx = %s              -- [N+1] _LEARNING_PAPER_IDX (메인쿼리)
      AND {_MID_CATEGORY_SECTION_FILTER}
    GROUP BY di.cla_id, s.SECTION_ID, s.SECTION_NM, s.SECTION_NM_FULL
    ORDER BY di.cla_id, s.SECTION_NM
    """,
    (_LEARNING_PAPER_IDX, *cla_ids, _LEARNING_PAPER_IDX),
)
```

**2. 동일한 서브쿼리가 함수 내에서 3회 반복됨**

- **위치 (라인 번호)**: 882~889, 908~913, 926~933 (`agent/app/tools/mysql_tools.py`)
- **현재 코드**: 동일한 서브쿼리(`SELECT cla_id, MAX(ord_no) AS ord_no FROM tb_dgnss_info WHERE paper_idx = %s GROUP BY cla_id`)가 하나의 함수 내에서 3번 반복됩니다.
- **개선 제안**: 첫 번째 쿼리(classes 조회)에서 이미 `latest.ord_no`를 가져왔으므로, 이 결과를 Python dict로 캐싱하여 두 번째/세 번째 쿼리에서 서브쿼리를 제거할 수 있습니다. 다만 이 경우 `ord_no`가 `None`인 학급에 대한 필터링 로직이 추가로 필요합니다. 현재 구조는 각 쿼리가 독립적으로 실행되므로 MySQL 옵티마이저가 서브쿼리 결과를 캐싱할 가능성도 있어 성능상 큰 문제는 아닙니다. 따라서 제안 수준으로 남깁니다.
