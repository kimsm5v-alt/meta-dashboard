## [GOOD] 잘된 점

**1. DPoP nonce 챌린지 식별 로직이 명확하고 실용적입니다.**

`AuthProxyController.token()` 메서드의 catch 블록에서 `nonce != null` 조건 하나로 "재시도 필요"와 "진짜 교환 실패"를 구분합니다. 응답 메시지도 `"dpop nonce required"`로 구체적이어서, 클라이언트(SDK)가 nonce 재시도 케이스를 정확히 식별할 수 있습니다. 또한 `/refresh` 엔드포인트와 동일한 사유 구분 방식을 채택하여 일관성을 유지했습니다.

```java
// 변경된 코드 (AuthProxyController.java, 90-99번 라인)
String nonce = e.getHeaders().getFirst("DPoP-Nonce");
relayDpopNonce(nonce, response);
if (nonce != null) {
    return ResponseEntity.status(HttpStatus.UNAUTHORIZED)
            .body(Map.of("success", false, "message", "dpop nonce required"));
}
return ResponseEntity.status(e.getStatusCode())
        .body(Map.of("success", false, "message", "token exchange failed"));
```

**2. 예외 기반 상태 코드 추정(statusFromException)의 설계가 견고합니다.**

`QchTraceAspect`의 `resolveStatusCode` 메서드는 기존에 `response.getStatus()`에 의존했으나, 이 값이 AOP finally 시점에 아직 200인 문제를 인지하고 예외 타입 체인(cause 언랩)을 통해 직접 상태 코드를 도출하는 접근으로 전환했습니다. `GlobalExceptionHandler`의 매핑과 동일 기준을 유지하겠다는 주석도 명시되어 있어 유지보수성이 높습니다.

실제로 `GlobalExceptionHandler`의 예외 매핑과 `statusFromException`의 매핑을 비교 검증한 결과, 모든 항목이 일치합니다:
- `AuthFailedException` -> 401 (일치)
- `DataIntegrityViolationException` -> 409 (일치)
- `IllegalStateException` -> 409 (일치)
- `IllegalArgumentException` -> 400 (일치)
- `ClientAbortException` / `AsyncRequestTimeoutException` / `IOException(disconnect)` -> 499 (일치)
- `ErrorResponse` (Spring 표준 웹 예외) -> 자체 status 사용 (일치)

**3. isBenignDisconnect 분리로 false positive를 방지했습니다.**

클라이언트 끊김(499)을 별도 메서드로 분리하여 IOException 메시지 기반 판별 로직을 캡슐화했습니다. `GlobalExceptionHandler`의 `isFromEmitter`(스택 트레이스 기반)와 달리, AOP 레벨에서는 메시지 패턴 매칭을 사용하는 독립적인 판별 로직을 가짐으로써 두 계층이 서로 다른 컨텍스트에서 동작할 수 있게 했습니다.

**4. QchTraceEvent 직렬화 계약 테스트가 매우 적절합니다.**

`@JsonProperty("isError")`를 사용하여 Jackson 3(tools.jackson)에서 `is-prefix boolean` 게터가 `error` 키로 잘못 매핑되는 함정을 방지했습니다. 이에 대한 단위 테스트(`QchTraceEventSerializationTest`)가 추가되어, QCH ingest의 필드 미스매치 회귀를 막았습니다.

```java
// QchTraceEvent.java
@JsonProperty("isError")
private final Boolean isError;

// QchTraceEventSerializationTest.java
assertThat(json).contains("\"isError\":false");
assertThat(json).doesNotContain("\"error\":");  // Jackson is-prefix 함정 방지
```

### Medium (개선 권장)

**1. `relayDpopNonce`의 null-safe 계약이 문서화되어 있지 않습니다.**

`AuthProxyController`의 catch 블록에서 `relayDpopNonce(nonce, response)`가 nonce 유무와 무관하게 항상 호출됩니다. `relayDpopNonce` 메서드 내부에서 null 체크를 할 것으로 예상되지만, 이 계약이 명시적이지 않습니다. 다만, 기존 코드에서도 동일한 패턴(`relayDpopNonce(e.getHeaders().getFirst("DPoP-Nonce"), response)`)을 사용하고 있어 일관성은 유지됩니다.

**수정 코드 제시 불가** -- 기존 패턴과 일관되며, 실제 동작에 영향을 주지 않습니다.

**2. `isBenignDisconnect`의 IOException 메시지 매칭이 로케일 의존적일 가능성이 있습니다.**

`GlobalExceptionHandler.handleIOException`에서는 `isFromEmitter`(스택 트레이스 기반)를 추가로 사용하여 로케일 문제를 보완하고 있습니다. AOP 레벨에서도 동일한 스택 트레이스 기반 판별을 추가할 수 있지만, 이는 `GlobalExceptionHandler`보다 먼저 실행되는 AOP의 특성상 스택 정보를 신뢰할 수 없을 가능성이 있어 의도적인 설계 결정으로 보입니다.

**수정 코드 제시 불가** -- 문맥 파악 불충분. AOP 레벨과 GlobalExceptionHandler 레벨의 실행 시점 차이를 고려할 때 현재 설계가 합리적입니다.

**3. 프론트엔드 `handleActivityDownload`가 `alert`만 호출합니다.**

```typescript
const handleActivityDownload = () => {
    alert('추천 활동 자료 페이지는 추후 구현 예정입니다.');

```

`alert` 대신 토스트/스낵바 컴포넌트를 사용하거나 버튼 자체를 비활성화(disabled) 처리하는 것이 더 나은 UX입니다. 다만 이는 "추후 구현 예정"이라는 명시적인 임시 조치이므로, 현재 상태로도 충분히 용인 가능합니다.

**수정 코드 제시 불가** -- 현재 구현 의도상 적절함. 추후 실제 기능 구현 시 함께 개선하면 됩니다.

## 주요 파일 분석

### AuthProxyController.java

**변경 내용:** DPoP nonce 챌린지(401) 응답을 일반 토큰 교환 실패와 구분하여 `"dpop nonce required"` 메시지 반환

**분석:**
- `nonce` 변수를 지역 변수로 추출하여 가독성을 높였습니다.
- `relayDpopNonce` 호출을 nonce 유무와 무관하게 항상 수행하여, nonce가 있는 경우 헤더를 relay하고 동시에 본문 메시지로도 nonce 필요를 알립니다.
- nonce가 없는 진짜 교환 실패(예: `invalid_grant`)는 기존대로 `"token exchange failed"` 메시지를 반환합니다.
- 테스트 코드도 두 케이스를 모두 검증하여 회귀를 방지했습니다.

### QchTraceAspect.java

**변경 내용:** 예외 기반 상태 코드 추정 로직(statusFromException) 추가, logType/isError 필드 명시 계산

**분석:**
- `resolveStatusCode` 메서드가 예외 발생 시 `response.getStatus()` 대신 `statusFromException(thrown)`을 호출하도록 변경되었습니다.
- `statusFromException`은 예외 타입 체인을 언랩(cause 순회)하여 `ErrorResponse`, `AuthFailedException`, `DataIntegrityViolationException`, `IllegalStateException`, `IllegalArgumentException`, `ClientAbortException`, `AsyncRequestTimeoutException`, `IOException(disconnect)` 순으로 매칭합니다.
- `isError(int status)`는 `status >= 500`일 때만 true를 반환하여, 4xx(예상된 비즈니스 실패)가 에러 지표로 오적재되지 않도록 합니다.
- `logType(int status)`는 5xx->ERROR, 4xx->WARN, 그 외->INFO로 분류합니다.
- `isBenignDisconnect`는 클라이언트 끊김(Connection reset, Broken pipe, aborted)을 499로 분류하여 에러 지표에서 제외합니다.

### QchTraceEvent.java

**변경 내용:** logType, isError 필드 추가

**분석:**
- `logType` 필드는 String 타입으로, QCH ingest가 이 값을 읽어 로그 레벨을 결정합니다.
- `isError` 필드는 Boolean 타입으로, `@JsonProperty("isError")`를 명시하여 Jackson 3의 `is-prefix boolean` 게터 함정(`error` 키로 잘못 매핑)을 방지합니다.
- `@JsonInclude(Include.NON_NULL)`로 인해 null인 필드는 직렬화에서 제외되므로, 기존 QCH ingest와의 하위 호환성이 유지됩니다.

## 최종 평가

**결론**: [WARN] **조건부 승인 (Approved with Comments)**

**종합 의견:**

이 커밋은 전반적으로 높은 품질을 유지하고 있습니다. 특히 `statusFromException`의 예외 타입 체인 언랩 로직과 `@JsonProperty("isError")`를 통한 Jackson 직렬화 함정 방어는 실무 경험이 느껴지는 설계입니다. DPoP nonce 챌린지 식별 개선은 클라이언트-SDK와의 통신 프로토콜을 명확히 했고, QCH trace의 logType/isError 명시 전송은 에러 지표의 정확도를 크게 향상시킬 것입니다. 테스트 코드도 주요 분기를 모두 커버하고 있어 신뢰성이 높습니다.

개선 제안으로 언급된 사항들(relayDpopNonce null-safe 문서화, 프론트엔드 alert 대체)은 사소한 수준이며, 현재 구현으로도 충분히 실무에 통용될 수 있습니다. Critical/High 이슈가 없으므로 조건부 승인합니다.
