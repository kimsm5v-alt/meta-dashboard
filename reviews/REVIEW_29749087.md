## 변경 배경

이 커밋은 **심리검사(Dgnss) 도메인**에서 학생 정보 입력 체계를 확장하고, 프론트엔드-백엔드 간 데이터 흐름을 정비하는 종합적인 변경입니다.

- **목적**: (1) 학생 검사 시작 시 `schoolCode`, `nickname` 등 추가 식별정보를 받아 저장/표시, (2) grade/classNumber 입력값 정규화(normalizeNumericInput), (3) 그룹 조회 API에 schoolCode/memberNo 필드 추가, (4) 프론트엔드에서 StudentInfoStep 컴포넌트를 ExamGuideStep으로 통합, (5) 개발/스테이징 환경의 인증 엔드포인트(vsaidt.com -> vschool.at) 마이그레이션
- **도메인**: API(백엔드 컨트롤러/서비스/매퍼), UI(프론트엔드 React 컴포넌트), 인프라(환경설정)
- **변경 방향**: 학생 입력 정보의 정규화 로직을 서비스 레이어에 추가하여 일관성 확보, 프론트엔드에서 중복 컴포넌트(StudentInfoStep)를 제거하고 ExamGuideStep으로 통합하여 단일화, 그룹 API 응답에 schoolCode/memberNo를 추가하여 학생 컨텍스트 정보 보강

#### 1. `StudentInfoForStart` 인터페이스에 `nickname` 필드 누락으로 인한 기능 미동작

**파일**: `frontend/src/features/exam/api/examService.ts`

**변경 내용 분석**: 백엔드에서는 `DgnssMapper.xml`에 `nickname` 컬럼 저장/조회 로직이 추가되었고, `DgnssService.applyNicknameOverride()`에서 `tb_dgnss_result_info.nickname` 값을 `MEM_NM`으로 오버라이드하는 기능이 구현되었습니다. 그러나 프론트엔드의 `StudentInfoForStart` 인터페이스에는 `nickname` 필드가 정의되어 있지 않아, 사용자가 입력한 닉네임을 API로 전달할 방법이 없습니다.

구체적으로 확인한 코드 흐름은 다음과 같습니다:

- `StudentInfoForStart` 인터페이스(205-212번 라인): `schoolName`, `grade`, `classNumber`, `gender`, `schoolCode`만 정의되어 있고 `nickname`이 없음
- `ExamPage.tsx`의 `studentInfoForStart` 객체 구성(582-588번 라인): `info.name`을 `nickname`으로 매핑하지 않고 있음
- `resetExam` 함수의 두 분기(자기조절학습검사, 학습종합검사): 모두 `studentInfo`의 `nickname`을 `params`에 추가하지 않음

결과적으로 백엔드에서 `applyNicknameOverride()`가 아무리 잘 구현되어 있어도, 프론트엔드에서 nickname 데이터를 보내지 못하면 이 기능은 영원히 동작하지 않습니다.

**위치 (라인 번호)**: 205-212

**기존 코드**:
```typescript
export interface StudentInfoForStart {
  schoolName?: string;
  grade?: number;
  classNumber?: number;
  gender?: 'M' | 'F';
  /** NEIS 표준학교코드 — 학교 검색 선택 시(나이스 연동). 검사쪽 저장용. */
  schoolCode?: string;
}
```

**해결 방안**:
1. `StudentInfoForStart` 인터페이스에 `nickname?: string` 필드 추가
2. `resetExam` 함수의 두 분기(자기조절학습검사, 학습종합검사) 모두에서 `if (studentInfo.nickname) params.append('nickname', studentInfo.nickname)` 추가
3. `ExamPage.tsx`의 `studentInfoForStart` 객체 구성 시 `nickname: info.name || undefined` 추가

#### 2. `resetExam` 자기조절학습검사 분기에서 `totalPages`/`totalQuestions` 하드코딩

**파일**: `frontend/src/features/exam/api/examService.ts`

**변경 내용 분석**: 자기조절학습검사(paperIdx !== '1') 분기에서 `totalPages: 4, totalQuestions: 72`가 하드코딩되어 있습니다. 이 값들은 API 응답에서 동적으로 결정되어야 합니다. 특히 `totalPages`는 `res.resultData.page.totalPages`를 사용해야 하며, `totalQuestions`는 `res.resultData.page.totalElements`를 사용해야 합니다.

**위치 (라인 번호)**: 370-371

**기존 코드**:
```typescript
    return {
```

**해결 방안**: API 응답의 `page` 객체에서 동적으로 값을 가져오거나, 최소한 fallback 값으로 설정해야 합니다. `res.resultData.page?.totalPages ?? 4`와 같은 형태가 더 안전합니다.

### Medium (개선 권장)

#### 1. `normalizeNumericInput` 정규식의 잠재적 문제

**파일**: `backend/src/main/java/com/vs/meta/api/dgnss/service/DgnssService.java`

**변경 내용 분석**: `normalizeNumericInput` 메서드는 `value.trim().replaceAll("[^0-9].*$", "")` 정규식을 사용합니다. 이는 "2학년" -> "2"로 변환하지만, "2-1" 같은 입력은 "2"로만 남고 "-1"이 제거됩니다. 또한 "2023학년도" 같은 입력도 "2023"으로 변환되어 의도치 않은 값이 저장될 수 있습니다.

**위치 (라인 번호)**: 2265-2272

**개선 제안**: 입력값의 첫 번째 숫자 그룹만 추출하거나, 허용 가능한 입력 패턴을 명확히 정의하는 것이 좋습니다. 예를 들어 `replaceAll("[^0-9].*$", "")` 대신 `replaceAll("^(\\d+).*$", "$1")`를 사용하면 첫 번째 숫자 그룹만 추출됩니다. 다만 현재 로직도 실무에서 충분히 통용될 수 있는 수준이므로, 이는 선택적 개선 사항입니다.
