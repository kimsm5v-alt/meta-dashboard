그룹 초대코드 · QR 참여 → 학심정 복귀 플로우

교사가 학심정에서 공유한 QR/링크로 학생이 그룹에 참여하고 학심정으로 복귀하기까지 · 2026-06-17
요지. 교사가 학심정 그룹 상세에서 초대코드/QR/링크를 공유 → 학생이 그 링크로 mypage 그룹참여 페이지에 진입 → (필요 시 로그인·회원가입) → 그룹 합류 → 학심정으로 자동 복귀. 초대코드의 원천은 Auth(IDP)이며, 학심정은 동기화로 받아 표시만 한다. 그룹 합류 처리는 mypage/Auth가 담당하고 학심정은 동기화로 멤버 상태를 반영한다.

3.공유되는 QR / 링크

교사가 그룹 상세에서 공유하는 QR과 "링크 복사"는 동일한 URL이다. 학심정 FE의 buildGroupJoinUrl()이 생성한다.

https://<mypage>/groups/join/{초대코드}?client_id={학심정}&return_to={학심정 origin}/student/exams
  • 초대코드 — Auth 동기화로 학심정이 받은 그룹 코드 (group_info.invite_code)
  • client_id — 학심정 (VITE_SP_CLIENT_ID). mypage "돌아가기" 브랜딩/검증용
  • return_to — 합류 후 복귀할 학심정 학생 검사목록. QR을 만드는 교사의 현재 학심정 origin에서 자동 도출 → dev/운영 자동 일치, 이미 학심정 allowedOrigins 등록값이라 mypage 복귀 검증 통과

4.케이스별 참여 → 복귀 흐름

QR/링크는 같은 URL이라 동작 동일. 차이는 학생의 로그인/가입 상태와 교사 여부뿐.

정상 · 최단케이스 A — 이미 로그인된 학생
진입 즉시 그룹명 미리보기 표시 → "그룹 참여하기" → 합류 → 학심정 복귀.
QR/링크 → mypage 랜딩(그룹명 표시) → joinByCode → 검증된 return_to → 학심정 /student/exams ✓
로그인 필요케이스 B — 미로그인 (기존 회원)
"로그인하고 참여하기" → IdP 로그인 → 콜백 → mypage가 원래 경로(return_to 포함) 복원 → 합류 → 학심정 복귀.
QR/링크 → mypage 랜딩 → login(redirectPath=현재경로) → IdP 로그인 → 콜백 →
mypage 랜딩 복원 → joinByCode → return_to → 학심정 /student/exams ✓
회원가입 필요케이스 C — 미가입 (신규 회원, 이메일/소셜)
가입(통합 개인정보처리방침 동의) → 원래 OAuth로 복귀. 소셜 신규가입은 가입 직후 ST_SESSION 미발급 정책이라 로그인 1회 더 거친 뒤 복귀(IdP 기존 설계). 이후 합류 → 학심정 복귀.
QR/링크 → mypage 랜딩 → login → IdP 회원가입 → (소셜은 로그인 1회 더) →
콜백 → mypage 랜딩 복원 → joinByCode → return_to → 학심정 /student/exams ✓
※ return_to는 로그인·가입·재로그인을 모두 관통해 보존됨(SDK _auth_return_path + OAuth return_to). 소셜 finalize 후 completeLoginRedirect가 원 OAuth로 이어줌.
차단케이스 D — 교사 계정이 참여 시도
로그인까진 되지만 joinByCode에서 서버가 403("교사 계정은 그룹에 학생으로 합류할 수 없습니다") → 랜딩이 메시지만 표시하고 학심정으로 보내지 않음.
QR/링크 → mypage 랜딩 → (로그인) → joinByCode → 403 차단 → 안내 표시 (복귀 X)

약관 동의는 어디서? — 출발점에 따라 다름

약관 검증(SignupAgreementValidator)은 그 가입을 구동한 OAuth client가 consent_required=TRUE RP일 때만 그 RP의 서비스 약관을 필수로 받는다. 통합 개인정보처리방침(privacy)은 가입 경로와 무관하게 항상 필수.

출발점가입 화면에서 받는 약관학심정 서비스 약관 받는 시점
학심정 직접 로그인
(OAuth client = 학심정)		 통합 privacy + 학심정 서비스 약관 가입 시 한 번에 ✅ (clientId=학심정, consent_required=TRUE)
QR/링크 경유
(OAuth client = mypage)		 통합 privacy 만 학심정 첫 진입 authorize의 동의 화면에서 ✅

QR 흐름의 가입은 mypage 화면에서 mypage의 OAuth client로 일어나므로(URL의 client_id=학심정은 mypage 브랜딩/복귀용일 뿐 OAuth client 아님), 그 가입 시엔 학심정 약관이 안 걸린다. 대신 학생이 합류 후 학심정에 처음 authorize할 때 학심정(consent_required=TRUE) 서비스 약관에 미동의 상태면 OAuth2Controller가 CONSENT_REQUIRED → /consent 동의 화면으로 보낸다 (/consent/required가 미동의 항목만 반환 → 이미 받은 통합 약관은 제외, 학심정 약관만).

결론
어느 경로든 학심정 서비스 약관은 반드시 수집된다 (학심정 client consent_required=TRUE + authorize 동의 화면). 차이는 "가입 화면에서 한 번에"(학심정 직접) vs "학심정 진입 시 동의 화면에서"(QR 경유)일 뿐.

5.초대코드 동기화 체인 (표시용)

Auth group_info.invite_code → RP API 응답 inviteCode →
학심정 RpGroupClient 파싱 → GroupUpsertService(insert/update) →
학심정 group_info.invite_code 저장 → 그룹 API → FE 그룹상세 초대코드/QR/링크 표시
  • 부트스트랩 / 변경피드 폴링 / on-demand / 일일 재동기화 어느 경로로 들어와도 저장됨.
  • safeInviteCode: 같은 코드를 다른 그룹이 점유 중이면 null 저장 + 경고 (uk_group_invite_code UNIQUE 충돌로 동기화가 깨지지 않게).
  • 기존 synced 그룹은 Auth 배포 후 그 그룹이 재조회되는 시점(GROUP_UPDATE/on-demand)에 코드가 채워짐 → 그때부터 카드 노출.

7.설계 노트 & 주의

⚠ 배포 / 운영 체크
  • 순서: Auth(inviteCode 노출) 배포 → 학심정 동기화가 코드 수신 시작. 그 전엔 레거시 코드 보유 그룹만 카드 노출(graceful).
  • mypage 프록시: /api/v1/groups/join-info가 BFF SecurityConfig에 permitAll로 열려 있어야 비로그인 그룹명 미리보기 동작 (이메일 초대 info와 동일 패턴, 처리 완료).
  • return_to: 학심정 origin이 Auth OAuth allowedOrigins(redirectUris)에 등록돼 있어야 mypage 복귀 검증 통과.
  • 노출 정보 최소화: 미리보기는 그룹명만(BE는 학교/교사도 반환하나 FE 미표시), 멤버 명단·PII는 노출하지 않음.
  • 미리보기 전역 조회: tenant 없이 코드로 조회(랜덤 8자라 교차 충돌 무시 가능)하되, 실제 합류(joinByCode)는 tenant 스코프 유지 — 미리보기는 비권위적.
  • 역방향 없음: 학심정은 그룹 데이터를 pull/표시만. 쓰기(생성·수정·삭제·합류·제거)는 모두 mypage/Auth.

8.본질은 "평가 링크"가 아니라 "그룹 초대 링크"

별도 기획 문서 20260617-평가-그룹멤버십-인증플로우 [그림1]은 "평가 링크 클릭 → RP가 ①로그인 ②멤버십 2관문 게이트"로 그렸지만, 학심정엔 그런 "평가 링크" 개념도, 비멤버를 자동으로 그룹참여로 보내는 RP 게이트도 없다. 학심정에서 실제로 의미 있는 건 그룹 초대 링크(=이번에 구현한 QR/참여 링크)이며, 본 작업이 구현한 게 바로 그것이다.
