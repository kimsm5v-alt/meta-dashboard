# Meta Dashboard AI 에이전트 테스트 가이드

이 문서는 AI 에이전트 서비스의 안정성을 검증하기 위한 테스트 케이스 종류, 목적 및 실행 방법을 설명합니다.

## 1. 테스트 케이스 종류 및 목적

### 1-1. API 통합 테스트 (test_api_integration.py)
에이전트 서버의 엔드포인트가 정상적으로 작동하고 LLM과 올바르게 연동되는지 여부를 검증합니다.

*   **API Health Check**: 서버가 실행 중이며 기본 루트 엔드포인트(/)에 접근 가능한지 확인합니다.
*   **Context 기반 대화**: 학생 정보나 성적 데이터 등 추가적인 콘텍스트(context_data)를 포함한 질문에 대해 LLM이 이를 인지하고 답변하는지 확인합니다.
*   **대화 메모리 지속성 (Memory Continuity)**: 동일한 세션 ID를 사용할 때, 이전 대화 내용을 기억하고 후속 질문에 답변할 수 있는지 확인합니다.
*   **세션 초기화**: 특정 세션의 대화 이력을 삭제하고 새로운 대화를 시작할 수 있는지 확인합니다.

### 1-2. 개인정보 마스킹 테스트 (test_pii_filter.py)
에이전트가 처리하는 데이터 중 학생 이름, 학번, 연락처 등 민감한 개인정보(PII)가 AI 모델로 전달되기 전 적절히 마스킹되는지 검증합니다.

*   **단일 필드 마스킹**: 이름, 이메일, 전화번호 등 주요 필드에 대한 마스킹 규칙 적용 여부를 확인합니다.
*   **중첩 구조 마스킹**: 딕셔너리나 리스트 내부의 깊은 계층 구조에 포함된 개인정보까지 재귀적으로 탐색하여 마스킹하는지 확인합니다.

## 2. 테스트 실행 방법

### 2-1. 사전 준비
테스트를 실행하기 전, 에이전트 서버가 로컬 환경에서 실행 중이어야 합니다.

```bash
# 서버 실행 (agent 루트 디렉토리에서 실행)
source .venv/bin/activate
python main.py
```

### 2-2. 통합 테스트 실행
서버가 실행 중인 상태에서 별도의 터미널을 열어 실행합니다.

```bash
# 통합 테스트 실행
source .venv/bin/activate
python tests/test_api_integration.py
```

### 2-3. 단위 테스트 실행 (pytest 활용 시)
개별 모듈의 로직을 독립적으로 검증할 때 사용합니다.

```bash
# PII 필터 로직 테스트
pytest tests/test_pii_filter.py
```

## 3. 주의 사항

*   API 통합 테스트 시 실제로 LLM API를 호출하므로, .env 파일에 유효한 GEMINI_API_KEY가 설정되어 있어야 합니다.
*   테스트 실행 결과에 오류가 발생할 경우, 서버 로그를 통해 LiteLLM Router의 에러 메시지나 네트워크 타임아웃 여부를 확인하십시오.
