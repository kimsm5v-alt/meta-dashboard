## 1. 코칭 개요

- 코칭은 학생의 **LPA 유형 + 38개 요인 T점수**를 바탕으로, 그 학생/반에 맞는 **강점 활용·보완 개입 전략**을 제시하는 기능입니다.
- 단위: **개별 코칭**(학생 1명, `/coaching/individual`) / **학급 코칭**(반 단위, `/coaching/class`). 둘 다 GNB `코칭` 메뉴의 서브탭으로 노출됩니다.
- 두 단위는 **근거 데이터도 로직도 서로 다릅니다.**

| 단위 | 근거 | 출처 |
|------|------|------|
| **개별 코칭** | 개인 T점수 ↔ 유형 집단 평균 T점수(Neo4j `GROUP_TSCORE`) 편차로 강점·보완 선별 + 조절경로 | 백엔드 API |
| **학급 코칭** | 반의 **LPA 유형 분포 순위**(1~3위 유형) | 프론트 정적 콘텐츠 |

- **고등학생은 코칭 대상에서 제외**됩니다(전용 LPA 모델 없음 → 강점/약점 분석만). 개별·학급 코칭 화면 모두 고등이면 미지원 안내를 표시합니다.

## 2. 코칭 추천 근거 — 강점·보완 산정

개별 코칭의 강점·보완은 **유형 집단 평균 대비 편차(need)** 로 정합니다. (백엔드 `DgnssGraphService`)

**need(보완 필요도) 계산**

```
deviation = 개인T − 집단평균T                  // 부호 보존(정적 기준 양수=강점, 음수=보완)
정적(긍정) 요인:  need = −deviation            // 개인이 집단보다 낮을수록 need↑
부적(부정) 요인:  need = +deviation            // 개인이 집단보다 높을수록 need↑
```

- `direction`: 편차가 학생에게 유리하면 `positive`, 불리하면 `negative`.
- need 내림차순 정렬 → **상위 = 보완 필요, 하위 = 강점**.

**선별 규칙은 API마다 다릅니다.**

| 파이프라인 | 강점 | 보완 | 조절경로 |
|------|------|------|------|
| **개인화 코칭 v2** (`/st/coaching/{answerIdx}`) — **현재 화면이 쓰는 경로** | need 하위 **2개** | need 상위 **1개** | 보완 top1의 대표 경로 **1개** |
| **학생 분석** (`/st/analysis?graphYn=Y`) — 현재 프론트 소비처 없음(§10) | need 하위 **3개** | need 상위 **3개** | 강점 top1 + 보완 top1 = **2개** |

- 개인/집단 T점수를 확보하지 못하면 **개인 T점수 절대값 기준 상·하위 3개**로 폴백합니다(`absoluteStrengths` / `absoluteWeaknesses`, 집단 비교 없이).
- 고등·미분류(LPA 유형명 없음) 학생은 빈 선별 결과를 반환합니다.

> 참고: 프론트에는 관련도 점수(`relevanceScore = needScore×0.5 + deviationScore×0.3 + betaBoost×0.2`, 유형평균 없으면 `needScore×0.65 + betaBoost×0.35`)로 개입을 랭킹하는 별도 로직도 있으나(「기본 정보」 §5.3), **여전히 어떤 화면에도 연결되지 않은 데드코드**입니다(§10).

## 3. 조절·매개 경로 (개입·지지 전략)

코칭 문구의 근거가 되는 요인 간 관계는 Neo4j 그래프의 두 경로로 표현됩니다.

| 경로 | 의미 | 구조 | 주요 필드 |
|------|------|------|----------|
| **조절 경로(ModerationPath)** | **개입 전략** | X(독립요인) · **Z(조절요인)** → Y(성과=학업성취도) | `pathType, x, z, y, interpretation(해석), strategy(전략), keywordInterp, keywordStrat, zFactorType` |
| **매개 경로(MediationPath)** | **지지 전략** | X → **M(매개요인)** → Y | `x, m, y, pathType, interpretation, strategy` |

- 즉 "이 학생의 **어떤 요인(Z/M)** 을 개선·지지하면 **학업성취(Y)** 로 이어진다"는 인과 근거를 담습니다.
- 관계: `(LPAClass)-[:HAS_MODERATION_PATH]→(ModerationPath)`, `-[:HAS_MEDIATION_PATH]→(MediationPath)`, `-[:GROUP_TSCORE]→(Factor)`.
- 유형은 초·중 6종만(초등: 자원소진형/안전 균형형/몰입자원 풍부형, 중등: 냉소적 무기력형/정서조절 취약형/자기주도 몰입형).

## 4. 개별 코칭 구성 (강점 카드·코칭 카드)

개인화 코칭(v2)은 **강점 top2 요인 + 보완 top1 조절경로**를 뽑아, 교사가 바로 쓸 수 있는 카드로 구성합니다.
(Neo4j로 선별 → RDB에서 코칭 텍스트 조회 → 화면 DTO 조립. `SchoolCoachingService`)

- **강점 카드 (상위 2개 요인)** — 화면 라벨 `인정 1` / `인정 2`
  - `observation` — 강점이 드러나는 관찰 포인트
  - `line` — 학생에게 건넬 **칭찬 멘트**
  - `question` — 강점을 확장하는 **질문** ("더 이야기하고 싶다면 이렇게 물어보세요")
- **보완 코칭 카드 (보완 top1 조절경로)** — 화면 라벨 `맞춤`
  - `zFactor / xFactor / yFactor / pathType / interpretation` — 왜 이 경로가 중요한지
  - `coaching1 { method, line }` — 코칭 방법 + 멘트
  - `coaching2 { action, line }` — 실천 행동 + 멘트
- 문구의 **`[학생명]` 자리는 실제 학생 이름으로 치환**됩니다. 백엔드는 의도적으로 치환하지 않고 내려보내며, 프론트가 `observation`·`interpretation`에만 치환을 적용합니다.
- 조회 키는 `answerIdx`(선택한 차수의 검사 응답). 화면에서 **1차/2차 토글**로 차수를 바꿀 수 있고, 2차 데이터가 없으면 2차 버튼은 `(예정)`으로 비활성화됩니다.
- **고등/미분류 학생은 빈 카드**로 응답하며, 화면은 "코칭 콘텐츠가 아직 준비되지 않았습니다"를 표시합니다. 검사 미완료 학생은 검사 관리로 이동하는 안내 화면이 나옵니다.

> 코칭 문구·멘트 텍스트는 도메인 데이터(DB)에서 나오므로, 챗봇은 이를 **직접 문장으로 생성하지 않고** "학생을 선택하면 실제 카드/문구를 조회해 안내"하는 방식이 정확합니다.

## 5. 학급 코칭 구성 (반 단위)

반 단위 코칭은 **반의 LPA 유형 분포 순위**를 기준으로 전략 카드를 제시합니다.
(⚠️ v1.0에 기술됐던 "11개 중분류 × 반 약점 TOP3" 방식이 아닙니다.)

**유형 순위 산정 (`rankTypes`)**

- 반 학생의 유형 분포를 **인원수 내림차순**으로 정렬.
- **동점이면 지원 필요도 우선순위**로 tie-break (절대 변경 금지 순서):
  - 초등: 자원소진형 → 안전 균형형 → 몰입자원 풍부형
  - 중등: 냉소적 무기력형 → 정서조절 취약형 → 자기주도 몰입형
- **0명인 유형은 분포 범례·STEP 배치 양쪽에서 제외**합니다.
- 순위 상위 3개 유형이 각각 STEP 1~3 카드가 됩니다(§6). 교사가 순위 목록에서 특정 유형을 클릭하면 그 유형이 STEP 1로 올라옵니다.

**전략 카드 구성 (유형별 콘텐츠 7개 필드)**

| 필드 | 내용 | 노출 |
|------|------|------|
| `characteristics` | 유형 특징 본문 ("우리 반 우세 유형 특징") | 1위 유형만 |
| `strategyTitle` | 대표전략 제목 | 모든 STEP |
| `strategyDescription` | 대표전략 리드 | STEP 1만 |
| `actionItems` | 실행 3단계 — 순서 고정: **1) 수업 도입부 2) 학급 운영 3) 교사의 말·피드백** | 모든 STEP |
| `successIndicators` | **2주 관찰 지표 3건** ("2주 후 이런 변화가 보이면 작동 중이에요", 체크박스) | STEP 1만 |
| `noteForOtherTypes` | **"다른 유형에는?" 운영 유의점** — 전원 참여 가능 여부·미반응 학생 대안 | 모든 STEP |
| `advancedStrategies` | 심화 코칭 2건(제목+리드+실천 4단계), 접이식 | STEP 1만 |

- 콘텐츠 출처: `학급전략DB_최종확정_v1.0_260721_JE 1.xlsx`. **초·중 6개 유형 전량 반영 완료**(초등 3종은 2026-08-25 추가).
- 화면에는 유형 분포 **도넛 차트 + 순위 목록**(유형별 설명 툴팁)이 함께 표시됩니다.
- 차수 토글(1차/2차)로 분포 기준 회차를 바꿀 수 있습니다. **1차 대비 악화 영역을 우선 배치하는 로직은 없습니다.**

## 6. 코칭 진행 순서 (STEP)

**STEP 1~3이 화면에 명시적으로 정의되어 있습니다.** (v1.0의 "정식 STEP 스펙 없음" 기술은 무효)

| STEP | 개별 코칭 | 학급 코칭 |
|:----:|-----------|-----------|
| **1** | 학생의 유형과 주요 특징 확인 | 학급 대표 전략 코칭 *(1위 유형 중심)* |
| **2** | 유형 대비 강점 확인과 인정 | 추가 코칭 1 *(2위 유형)* |
| **3** | 맞춤 코칭 제안 확인 및 실행 | 추가 코칭 2 *(3위 유형)* |

- 두 화면 모두 상단에 "코칭 진행 순서" 스텝 스트립을 두고, 아래에 STEP별 타임라인 카드를 배치합니다.
- 학급 코칭 타임라인 헤딩: STEP1 "우선 이것부터 시작하세요" → STEP2 "여유가 생기면 추가로" → STEP3 "더 깊이 있게".
- **코칭 준비 안내**가 각 화면 상단에 고정 노출됩니다.
  - 개별: "학생 진단 검사 결과를 먼저 확인하세요. 검사 결과만으로 판단하기 어려운 부분은 학생과의 대화(질문)를 통해 다시 확인한 후 코칭을 진행하세요."
  - 학급: "우리 반 학습 유형 분포와 우세 유형 특징을 확인하세요."

## 7. 상담 ↔ 코칭 ↔ 생활기록부 연계

- **상담 완료 시** 소요시간·상담 내용(요약)과 함께 **후속 조치(nextSteps)** 를 자유 텍스트로 남깁니다. 필요하면 '후속 상담(follow-up)' 유형으로 다음 상담을 **수동 등록**합니다.
  - ⚠️ nextSteps는 메모일 뿐, **다음 상담·코칭·생기부를 자동 생성하는 시스템 연계는 없습니다.**
- **데이터 참조 수준의 연계는 존재**합니다:
  - **생활기록부 문구 생성**은 상담 기록·관찰 메모를 근거로 활용합니다(관찰 메모=실제 에피소드(Fact) 핵심 근거, 상담 기록=내면적 고민·변화 의지).
  - 상담 연속성: 이전 상담 내용을 참고해 후속 조치 이행 여부를 확인하도록 설계.
  - 생기부 톤 일관성: 기존 저장 문구가 있으면 톤·내용을 참고.
  - AI 어시스턴트 컨텍스트에도 상담 기록의 nextSteps가 `→ 후속: …` 형태로 포함됩니다.
- 학생 개별 화면 우측 패널에 **생기부·상담·관찰(메모) 탭이 통합**되어 있어, 검사 T점수만으로 부족한 맥락을 이 기록들이 보완합니다.

## 8. 코칭 후 효과 점검·변화 확인

- **학급 코칭에는 성공지표가 정의되어 있습니다** — 유형별 `successIndicators` 3건("2주 후 이런 변화가 보이면 작동 중이에요"). 체크박스로 표시되며 STEP 1 카드에만 노출됩니다.
  - ⚠️ 체크 상태를 **저장하는 백엔드는 없습니다**(순수 UI). 세션을 벗어나면 사라집니다.
  - ⚠️ **개별 코칭에는 성공지표가 없습니다.**
- 중장기 효과는 **1차/2차 검사 비교(변화추적)** 로 확인합니다(2차 데이터가 있을 때 '변화 모드' 활성화).
  - 학급: 약점 영역의 악화/해소, 유형 분포 변화, **AI 학급 변화 분석(2차 기준)** 제공.
  - 위험군 목록: 신규/지속/해소/악화 변화 표시.
- AI 프롬프트 차원에서는 "후속 조치 이행 여부 확인", "관찰 메모의 긍정 변화를 칭찬·강화" 같은 지침으로 변화 점검을 보조합니다.

## 9. AI 분석의 코칭 활용 & 관련 API·Tool

**AI 분석 → 코칭 활용 흐름**

- 어시스턴트/총평은 **학습 코치** 페르소나로, 학생의 강점·약점·상담기록을 컨텍스트로 받아 **구체적·실행 가능한 코칭 전략**을 제시하도록 설계돼 있습니다.
- 챗봇은 개입·지지 전략이 필요하면 Neo4j Tool(조절/매개 경로)을 조회해 **개인 T점수 + 집단 평균·전략**을 결합해 답합니다.
- 데이터 해석 도우미에도 "어떤 코칭 전략이 효과적일까요?" 등 코칭 카테고리가 포함됩니다.

**관련 API / 챗봇 Tool**

| 구분 | 엔드포인트/Tool | 용도 | 상태 |
|------|----------------|------|------|
| 개인화 코칭 v2 | `GET /api/dgnss/st/coaching/{answerIdx}` | 강점 카드 2 + 보완 코칭 카드 1 | ✅ 개별 코칭 화면에서 사용 |
| 학생 분석(코칭 포함) | `GET /api/dgnss/st/analysis?...&graphYn=Y` | 학생 결과 + Neo4j 추천 경로(강점/보완 top3) | ⚠️ 서빙되나 화면 미연결 |
| 코칭 데이터 적재 | `POST /api/dgnss/graph/lpa/coaching-v2` | 강점·보완 코칭 패치를 Neo4j에 적재(운영용) | ✅ |
| 챗봇 Tool | `get_moderation_paths` / `get_mediation_paths` | 조절(개입)·매개(지지) 경로 | ✅ |
| 챗봇 Tool | `get_lpa_class_info` / `get_factor_scores` / `get_lpa_overview` | 유형 메타·요인 집단 평균·통합 조회 | ✅ |

> ⚠️ v1.0에 있던 `GET /api/dgnss/graph/classes/{className}/moderation-paths` 와 `GET /api/dgnss/graph/recommendation/by-answer|by-type` 는 **레거시 조회 API 정리로 삭제**되었습니다. 더 이상 존재하지 않으므로 안내하지 마십시오.

**Neo4j Tool 조회 limit 기본값**

| Tool | 기본값 | 최대 |
|------|--------|------|
| `get_moderation_paths` / `get_mediation_paths` | 20 | 100 |
| `get_lpa_overview` | 조절경로 10 · 매개경로 5 | 100 |

## 10. 구현 현황·미확정 항목

**검증 기준: `vs-develop` 9b934b1e (2026-08-31).** 챗봇 답변·기획 판단 시 아래를 유의하세요.

### 구현 완료

- **개별/학급 코칭 화면** — `/coaching/individual`, `/coaching/class` 모두 실제 화면으로 구현. GNB `코칭 > 학급 코칭 / 개별 코칭`.
  - 단, `FEATURES.IA_V2` 플래그 하위에 있습니다(기본값 `true`, localStorage로 오버라이드 가능).
- **개인화 코칭 v2 API(`/st/coaching`)** — 백엔드·프론트 연동 완료. 개별 코칭 화면이 이 API를 소비합니다.
- **코칭 STEP 정의** — 개별·학급 모두 STEP 1~3 명시(§6).
- **학급 코칭 성공지표·운영 유의점** — `successIndicators`(2주 관찰 지표), `noteForOtherTypes`(다른 유형에는?) 콘텐츠 존재(§5).
- **학급전략 콘텐츠** — 초·중 6개 유형 전량 반영 완료.

### 미구현·제약

- **활동지("우리 반 검사 결과 함께 보기")** — 버튼은 있으나 **비활성화**(`활동지 콘텐츠 연동 준비 중입니다`). 코칭 활동의 수업 활용·편집 안내는 아직 없습니다.
- **성공지표 체크 상태 미저장** — 체크박스는 순수 UI이며 저장 백엔드가 없습니다(§8).
- **개별 코칭 성공지표 없음** — 학급 코칭에만 존재합니다.
- **1차 대비 악화 영역 우선 배치 없음** — 학급 코칭은 차수별 유형 분포만 봅니다.
- **상담 후 자동 후속(다음 상담/코칭/생기부) 생성 흐름 없음** — nextSteps 자유 텍스트 + 수동 후속상담(§7).
- **`/st/analysis?graphYn=Y` 코칭 경로는 화면 미연결** — API는 살아 있으나 이를 쓰던 `CoachingStrategy` 컴포넌트와 `useCoachingStrategy` 훅은 현재 **어디에서도 렌더되지 않는 데드코드**입니다.
  - v1.0에 기술된 "운영(prod) 환경 숨김 처리(HSJ-108)" 가드는 **제거되었습니다.** 이제는 환경과 무관하게 미사용 상태이며, HSJ-108 언급은 `reviews/REVIEW_d45b3521.md`에 과거 기록으로만 남아 있습니다.
- **관련도 랭킹(relevanceScore, §2)** — 여전히 **어떤 화면에도 연결되지 않은 데드코드**이며, 그 입력(β 등)은 목업 데이터 기반입니다.
- **코칭 추천 배지의 '시급/보완' 점수 임계값은 없습니다.** '시급'은 4단계 진단 텍스트·상담 일정 `urgent` 유형에만 존재합니다.
  - 배지 구성도 v1.0 기술(강점/보완 2색 고정)과 달라졌습니다 — 현재 개별 코칭은 `인정 1`·`인정 2`(초록) + `맞춤`(빨강)입니다.
- **유형별 총 조절경로 개수**는 코드 상수가 아니라 그래프 시드 데이터에 의존(코드에서 확정 불가). Tool 조회 limit 기본값만 존재(§9).
- 참고: 기획 참조로 언급되던 `docs/meta-test/12_L3_코칭전략_설명서.md`, `docs/EXAM_COUNSELING.md` 는 **저장소에 실재하지 않습니다.** 코칭 근거의 원천은 `agent/docs/NEO4J_ANALYSIS.md`, `docs/요건정의서_META대시보드_v1.1.md`, `backend/docs/lpa/*`, 백엔드 `DgnssGraphService`·`SchoolCoachingService`·`CoachingController` 코드입니다.
