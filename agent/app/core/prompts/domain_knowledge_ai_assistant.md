## 1. AI 기능

### 1.1 AI 서비스 아키텍처

```
┌─────────────────────────────────────────────────────────────┐
│                        클라이언트                             │
│  Frontend (React) / AI Room / 생활기록부 / 데이터 도우미      │
└──────────────────────────┬──────────────────────────────────┘
                           │
          ┌────────────────┴────────────────┐
          │                                 │
          ▼                                 ▼
┌─────────────────────┐         ┌─────────────────────┐
│  AI 에이전트 서버    │         │  프론트엔드 직접호출   │
│  (Python FastAPI)   │         │  (Gemini 직접호출)    │
│                     │         │                     │
│  • /chat (동기)     │         │  • callAI()         │
│  • /chat/stream (SSE)│        │  • callGemini()     │
│  • /chat/{id} (삭제) │         │                     │

           │                               │
           ▼                               ▼
┌─────────────────────┐         ┌─────────────────────┐
│  LiteLLM Router     │         │  Gemini API         │
│  ┌────────────────┐ │         │  gemini-2.5-flash   │
│  │ Primary: GPT-4.1│ │         │  (직접 호출용)       │
│  │ Fallback: Gemini│ │         │                     │
│  └────────────────┘ │         │                     │
└──────────┬──────────┘         └─────────────────────┘
           │
           ├───────────────┐
```

> 에이전트는 Neo4j(LPA 분석)와 MySQL(실제 검사·상담·생기부 데이터)을 **모두** 사용합니다.

### 1.2 AI 서비스 우선순위

| 우선순위 | 서비스 | 모델 | 용도 |
|---------|--------|------|------|
| 1순위 | AI 에이전트 | OpenAI GPT-4.1 | AI Room (대화, Tool Calling) |
| 2순위 (폴백) | AI 에이전트 | Google Gemini (환경변수 지정) | GPT 실패 시 자동 전환 |
| 직접호출 | 프론트엔드 | Google Gemini 2.5 Flash | 분석총평, 생활기록부, 데이터 도우미 등 |

> 프론트엔드 직접호출 경로에서는 Gemini가 **1순위 provider**로 사용됩니다(폴백이 아님).

### 1.3 AI 에이전트 Tool 기능

AI 에이전트는 총 **19개 Tool**(Neo4j 5 + MySQL 12 + 도메인지식 검색 2)을 사용합니다.

**Neo4j Tool — LPA 유형 분석**

| Tool 이름 | 용도 |
|----------|------|
| `get_lpa_overview` | 유형 메타 + 조절/매개 경로 + 요인 평균 일괄 조회(대화 초반 1회 권장) |
| `get_lpa_class_info` | LPA 유형 메타데이터(특성·설명) |
| `get_moderation_paths` | 조절 경로(개입 전략) 목록 |
| `get_mediation_paths` | 매개 경로(지지 전략) 목록 |
| `get_factor_scores` | 유형별 38개 요인 집단 평균 T점수 |

**MySQL Tool — 실제 검사·상담·생기부 데이터**

| Tool 이름 | 용도 |
|----------|------|
| `query_student_lpa_and_scores` | 학생 LPA 유형·38요인 T점수·신뢰도 지표 |
| `query_student_memos` | 학생 관찰 메모 |
| `query_counseling_history` | 상담 이력(학생/학급/교사) |
| `query_counseling_summary` | 상담 건수 집계 |
| `query_school_records` | 생활기록부 |
| `query_class_dgnss_overview` | 학급 검사 진행 현황·LPA 분포 |
| `query_class_midcategory_scores` | 학급 11중분류 반 평균 T점수 |
| `query_class_roster` | 학급 전체 명단(미배정·미제출 포함) |
| `query_class_risk_students` | 학급 위험군/관찰 필요 학생 |
| `query_class_exam_campaigns` | 학급 검사 캠페인 목록 |
| `query_teacher_classes_overview` | 담당 학급 전체 현황 |
| `query_teacher_student_results_summary` | 담당 학급별 학생 검사결과 요약 |

**도메인지식 검색 Tool — 검사로직 정의서 / 교사용 설명서**

| Tool 이름 | 용도 |
|----------|------|
| `search_test_logic_reference` | 검사로직 정의서(요인별 조작적 정의, 문항 구성, T점수 산출식, 등급표, 신뢰도 지표 등) 키워드 검색 |
| `search_teacher_guide` | 교사용 설명서(검사 개념, 척도 정의, 점수 체계, 해석 절차, 리포트 고정문구) 키워드 검색 |

> Tool 등록: `agent/app/tools/__init__.py`(`all_tools_list = neo4j_tools_list + mysql_tools_list + domain_knowledge_tools_list`). 학생/학급/교사 선택 여부에 따라 호출 가능한 Tool이 tool_policy로 제한됩니다(§2.3).

- 학교급 (초등/중등)
- 학년
- LPA 유형
- T점수 (38개)

## 2. AI 어시스턴트 상세

### 2.1 AI Room 기능 요건

#### 2.1.1 컨텍스트 모드

| 모드 | 설명 | 로드되는 데이터 |
|------|------|----------------|
| **전체 반** | 담당 모든 반 데이터 | 반별 평균 T점수, 유형 분포, 관심필요 학생 수 |
| **특정 반** | 선택한 반 데이터 | 학생별 T점수, 유형, 강점/약점 |
| **특정 학생** | 1명 또는 다수 학생 | 38개 T점수, 유형, 상담기록, 관찰메모 |

> 프론트 컨텍스트 모드 3종(`all`/`class`/`student`)은 에이전트의 tool_policy 4종(`teacher`/`class`/`student`/`none`)과 매핑됩니다(§2.3). 대상 식별자가 없으면 `none` 정책으로 폴백합니다.

#### 2.1.2 세션 관리

| 항목 | 정책 |
|------|------|
| **세션 유지** | session_id 기반 대화 연속성 |
| **이력 정본** | 백엔드 DB에 영구 저장(프론트가 매 턴 replay) |
| **인메모리 저장** | Dict (레거시 폴백 경로) |
| **세션 초기화** | `DELETE /chat/{session_id}` 호출 |

#### 2.1.3 빠른 프롬프트 (Quick Prompts)

| 카테고리 | 예시 질문 |
|----------|----------|
| **학급 분석** | "이 반의 전반적인 특성은?", "관심 필요 학생 목록" |
| **유형별 분석** | "자원소진형 학생들의 공통점은?", "유형별 권장 활동" |
| **코칭 전략** | "이 학생에게 맞는 코칭 방법은?", "학부모 상담 포인트" |
| **변화 분석** | "1차 대비 2차 주요 변화", "개선된 영역 분석" |

### 2.2 AI 에이전트 실행 플로우

```
┌────────────────────────────────────────────────────────────────┐
│                    AI 에이전트 실행 플로우                        │
└────────────────────────────────────────────────────────────────┘

1. 요청 수신
   └── POST /chat 또는 /chat/stream
       ├── text: 사용자 질문
       ├── session_id: 세션 식별자
       └── context_data: { profile, context }

2. PII 마스킹
   └── pii_filter.py (지정 필드 마스킹)
       ├── 이름 → 김** / student_A
       ├── 학번 → 2*******
       └── 이메일 → h***@***.com

3. 시스템 프롬프트 구성
   └── role_and_rules + 도메인 참고 문서 + 식별자 블록 + tool_policy(모드별) + 학생 컨텍스트

4. LLM 호출 (LiteLLM Router)
   ├── Primary: OpenAI GPT-4.1
   └── Fallback: Google Gemini (환경변수 지정)

5. Tool Calling 루프 (최대 8회)
   ├── Tool 호출 필요?
   │   ├── Yes → Neo4j/MySQL/도메인지식 검색 Tool 실행 → 결과 추가 → LLM 재호출
   │   └── No → 최종 응답 생성
   └── Tool 타임아웃: 5초/Tool (기본값)

6. 응답 반환
   ├── /chat: JSON { response, session_id, history_count }
   └── /chat/stream: SSE { text, is_final }

7. 대화 이력 저장
   └── 백엔드 POST /api/ai/conversations/{id}/messages
```

### 2.3 시스템 프롬프트 구조

시스템 프롬프트는 `agent/app/core/prompts/`의 마크다운을 조립해 구성합니다(`agent_service.py`의 `_build_system_prompt`). 문구는 코드가 아니라 `.md` 파일에서 관리되어 서버 재시작 없이 반영됩니다.

```
[역할 및 운영 원칙]  ← role_and_rules.md
- 귀하는 비상교육 학습심리정서검사(LPA) 시스템의 상담 보조 AI입니다.
- 데이터 우선순위:
   1. 학생 컨텍스트(T점수, 4단계 진단, 상담기록 등)
   2. Neo4j Tool 조회 결과(LPA 유형 특성, 조절·매개 경로, 집단 평균 T점수)
   3. 학습심리정서 도메인 일반 지식(아래 "학습심리정서 도메인 참고 문서" 섹션, 위 두 소스를
      보완하는 수준에서만 제한적으로 활용)
   4. 검사로직 정의서/교사용 설명서 검색 결과(search_test_logic_reference/search_teacher_guide
      Tool 호출, 위 세 소스로도 부족할 때만 사용)
- 할루시네이션 방지: 창작 금지 / 불확실성 명시 / 근거 표기(T점수·Neo4j) / 도메인 한정

[학습심리정서 도메인 참고 문서]  ← domain_knowledge_{basic_info,operations,ai_assistant}.md
- 검사 개요·운영 정책·AI 기능 정보 등 도메인 일반 지식(우선순위 3)
- 검사로직 정의서/교사용 설명서는 이 문서에 전문이 포함되지 않으며, 필요 시
  search_test_logic_reference/search_teacher_guide Tool로 검색(우선순위 4)

[분석 대상 식별자 블록]
- schoolLevel + predictedType, stdt_id / cla_id / tc_id (모드에 따라 주입)
- 고등학교 학생이면 "중등 규준 기준으로 계산" 고지

[Tool 호출 정책]  ← tool_policy_{none|student|class|teacher}.md 중 모드별 1개
- 학생/학급/교사 선택 여부에 따라 호출 가능한 Tool과 제약을 지정
- 식별자가 없으면 Tool 호출 금지(none), 자유텍스트 실명은 '학생'으로 지칭

[학생 컨텍스트 (마크다운)]
- 프론트가 주입한 T점수·진단·상담기록 등
```

### 2.4 Neo4j Tool 상세

#### 2.4.1 get_lpa_overview

| 항목 | 내용 |
|------|------|
| **용도** | 대화 초반 전체 정보 일괄 조회 |
| **파라미터** | className, schoolLevel, modPathLimit(기본 10), medPathLimit(기본 5) |
| **반환** | 유형 메타데이터 + 조절경로 + 매개경로 + 요인 집단 평균 |
| **권장 사용** | 세션 시작 시 1회 호출 |

**그래프 관계(실제 스키마)**:
```cypher
// LPAClass 노드에서
(c:LPAClass {name: $className, school_level: $schoolLevel})
  -[:HAS_MODERATION_PATH]->(m:ModerationPath)   // 조절 경로
  -[:HAS_MEDIATION_PATH] ->(med:MediationPath)  // 매개 경로
  -[r:GROUP_TSCORE]      ->(f:Factor)            // 요인별 집단 평균 T점수(r.t_score)
```

#### 2.4.2 get_moderation_paths

| 항목 | 내용 |
|------|------|
| **용도** | 조절 경로(개입 전략) 조회 |
| **파라미터** | className, schoolLevel, limit (기본 10) |
| **반환** | `id, pathType, pathColor, x(독립), z(조절), y(성과=학업성취), zFactorType, zNeedDirection, keywordInterp, keywordStrat, interpretation, strategy` |
| **활용** | "어떤 요인을 개선하면 좋을까요?" 질문 대응 |

**반환 예시**:
```json
{
  "paths": [
    {
      "id": "MOD_...",
      "pathType": "촉진",
      "x": "게임 과몰입",
      "z": "수업태도",
      "y": "학업성취도",
      "interpretation": "…(경로 해석)…",
      "strategy": "…(개입 전략)…"
    }
  ]
}
```

#### 2.4.3 get_mediation_paths

| 항목 | 내용 |
|------|------|
| **용도** | 매개(X→M→Y) 경로 조회 |
| **파라미터** | className, schoolLevel, limit (기본 10) |
| **반환** | `x, m(매개), y, pathType, interpretation, strategy` |
| **활용** | "간접적으로 영향을 주는 요인은?" 질문 대응 |

#### 2.4.4 get_factor_scores

| 항목 | 내용 |
|------|------|
| **용도** | 유형별 38개 요인 집단 평균 T점수 조회 |
| **파라미터** | className, schoolLevel |
| **반환** | `factorName, factorType(정적/부적), needScoreDirection, tScore(집단 평균), rawMean` |
| **활용** | 학생 개별 T점수와 집단 평균 비교(강점/보완 판단) |

### 2.5 에러 처리

#### 2.5.1 LLM 관련 에러

| 에러 유형 | 원인 | 처리 방식 |
|----------|------|----------|
| `AuthenticationError` | API 키 인증 실패 | 폴백 모델 시도 → 실패 시 사용자 알림 |
| `RateLimitError` | 요청 제한 초과 | 지수 백오프 재시도 |
| `APIError` | 서비스 연동 오류 | 폴백 모델 시도 |

#### 2.5.2 Neo4j / MySQL 관련 에러

| 에러 유형 | 원인 | 처리 방식 |
|----------|------|----------|
| `ServiceUnavailable` | DB 연결 불가 | 재시도 → 실패 시 "조회 불가" 안내 |
| Tool 타임아웃 | 쿼리 지연(기본 5초) | 빈 결과 반환 후 "현재 조회 불가" 안내 |
| `ClientError` | 쿼리 오류 | 안전한 기본값/빈 결과 반환 |

#### 2.5.3 사용자 응답 메시지

| 상황 | 응답 메시지 |
|------|------------|
| 데이터 부족 | "해당 데이터를 현재 조회할 수 없습니다." |
| 범위 외 질문 | "이 시스템의 학습심리정서검사 범위 외의 질문입니다." |
| Tool 실패 | "상세 데이터 조회에 실패했습니다. 기본 정보로 답변드립니다." |

### 2.6 멀티턴 대화 정책

#### 2.6.1 세션·이력 관리

- 대화 이력의 **정본은 백엔드 DB**이며, 프론트가 매 턴 이전 이력을 함께 전송해 재생(replay)합니다. 에이전트는 기본 **무상태(stateless)** 로 동작하고, 인메모리 세션 저장소(Dict)는 레거시 폴백 경로입니다.
- 세션 초기화: `DELETE /chat/{session_id}`.
- 응답당 Tool Calling 루프 상한: **최대 8회**(초과 시 현재 정보로 응답).

#### 2.6.2 대화 연속성 (예시)

```
사용자: "이 학생의 강점이 뭐야?"
AI: "학생의 강점은 자기효능감(T=62)과 성장마인드셋(T=58)입니다..."

사용자: "그럼 약점은?"   ← 이전 이력(replay)으로 대상 자동 참조
AI: "앞서 분석한 학생의 보완 영역은 시간관리(T=38)와..."
```


### 2.8 페르소나 및 어투

#### 2.8.1 기본 페르소나

```
역할: 비상교육 학습심리정서검사(LPA) 시스템의 상담 보조 AI  (role_and_rules.md 기준)

성격:
- 전문적이면서도 따뜻한 어조
- 데이터 기반의 객관적 분석과 공감적 해석의 균형
- 교사의 전문성을 존중하고 보조 역할 인식

언어 스타일:
- 전문 용어 사용 시 간단한 설명 병행
- 긍정적이고 성장 지향적인 프레이밍(약점도 성장 가능성으로 표현)
- 구체적이고 실행 가능한 제안
```

#### 2.8.2 금지 표현

| 유형 | 금지 표현 | 대체 표현 |
|------|----------|----------|
| **낙인 표현** | 문제아, 열등생, 낙오자 | 성장 중인 학생, 지원이 필요한 학생 |
| **단정 표현** | 절대 안 됨, 불가능, 희망 없음 | 도전적인 영역, 시간이 필요한 부분 |
| **비교 표현** | ~보다 못함, 최하위 | 또래 평균 대비, 성장 여지가 있는 |
| **의료 용어** | ADHD 진단, 우울증 확정 | 전문 상담 권유, 추가 관찰 필요 |

#### 2.8.3 생활기록부 어투 (학교급별)
