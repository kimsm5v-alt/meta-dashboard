# 2. Backend 수정 계획

> JWT RS256 (JWKS 공개키 검증) + Auth 프록시 + 자체 인증 제거

---

## 2.1 핵심 변경

| AS-IS | TO-BE |
|-------|-------|
| 자체 JWT 발급 (HS256, JwtUtil) | Auth 서버 JWT (RS256, JWKS 공개키 검증) |
| 자체 로그인/회원가입 API | Auth 프록시 4개 엔드포인트 |
| JwtAuthenticationFilter (자체) | Spring OAuth2 Resource Server (표준) |
| 자체 refresh_token 테이블 | Auth 서버가 RT 관리 |
| 자체 이메일 인증 (가입용) | Auth 서버가 처리 |
| Admin = user 테이블 ADMIN 역할 | Admin = 별도 admin_account 테이블 |

## 2.2 의존성 추가 (build.gradle)

```gradle
// ===== OAuth2 Resource Server (JWKS JWT 검증) =====
implementation 'org.springframework.boot:spring-boot-starter-oauth2-resource-server'
```

Spring Boot 2.7에서 `spring-boot-starter-oauth2-resource-server`를 추가하면:
- `NimbusJwtDecoder`가 JWKS 엔드포인트에서 RS256 공개키를 자동 페칭
- `HttpSecurity.oauth2ResourceServer().jwt()` 설정 가능
- JWT Claims → `Authentication` 자동 변환

기존 `jjwt` 의존성은 **제거**한다. 학심정에서 JWT를 직접 생성하지 않고, 검증도 `oauth2-resource-server`(Nimbus JOSE)가 처리하므로 jjwt는 불필요.

```gradle
// ===== 제거 =====
// implementation 'io.jsonwebtoken:jjwt-api:0.11.5'
// runtimeOnly 'io.jsonwebtoken:jjwt-impl:0.11.5'
// runtimeOnly 'io.jsonwebtoken:jjwt-jackson:0.11.5'
```

## 2.4 신규 파일 목록

### 2.4.1 AuthProxyController — Auth 서버 프록시

**경로**: `api/sso/controller/AuthProxyController.java`

Hub의 `AuthController`와 동일한 패턴. client_secret을 추가하여 Auth 서버에 전달.

```
POST /api/v1/auth/token          ← SDK handleCallback()이 호출
  → Auth 서버 POST /oauth2/token (form-urlencoded, client_secret 추가)

POST /api/v1/auth/refresh        ← SDK refreshAccessToken()이 호출
  → Auth 서버 POST /api/v1/auth/refresh (JSON 투명 전달)

POST /api/v1/auth/logout         ← SDK logout()이 호출
  → Auth 서버 POST /api/v1/auth/logout (JSON 투명 전달)

POST /api/v1/auth/guest/token    ← 게스트 토큰 발급
  → Auth 서버 POST /oauth2/guest-token (client_secret 추가)
```

구현 참고: `superplatform-auth/docs/auth-client/20260414-integration-kit/sample-backend/AuthProxyController.java`

**주의**: 샘플은 `jakarta.servlet` (Spring Boot 4.0)이므로 `javax.servlet` (Spring Boot 2.7)으로 변환 필요:
- `jakarta.servlet.http.HttpServletRequest` → `javax.servlet.http.HttpServletRequest`
- `jakarta.servlet.http.HttpServletResponse` → `javax.servlet.http.HttpServletResponse`
- `ResponseCookie` 사용은 Spring 5에서도 동일

### 2.4.3 SsoUserService — SSO 로그인 시 학심정 user 자동 생성/동기화

**경로**: `api/sso/service/SsoUserService.java`

SpJwtClaimFilter에서 JWT 검증 성공 후 호출. 학심정 user 테이블에 사용자가 없으면 자동 생성.

```
JWT Claims 수신 (sub=UUID, email, name, gender, userType)
  → sp_user_id로 학심정 user 조회
    → 있으면: email/nickname/gender 동기화 (JWT와 다르면 UPDATE)
    → 없으면: 신규 user INSERT
      - sp_user_id = JWT sub
      - email = JWT email
      - nickname = JWT name
      - gender = JWT gender (있으면)
      - role_code = JWT userType 매핑 (TEACHER→TEACHER, STUDENT→STUDENT)
      - tc_id = 교사면 자동 채번
      - stdt_id = 학생이면 자동 채번
```

### 2.4.5 UserProfileController + CompleteProfileRequest — 추가 정보 입력

### 2.5.1 SecurityConfig.java — 핵심 변경

**현행 (ApiSecurityConfig):**
```java
@Order(2)
public static class ApiSecurityConfig extends WebSecurityConfigurerAdapter {
    private final JwtAuthenticationFilter jwtAuthenticationFilter;

    protected void configure(HttpSecurity http) throws Exception {
        http
            .sessionManagement().sessionCreationPolicy(SessionCreationPolicy.STATELESS)
            .authorizeRequests()
                .antMatchers("/member/login", "/member/signup", ...).permitAll()
                .anyRequest().authenticated()
            .addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class);
    }
}
```

**변경 후:**
```java
@Order(2)
public static class ApiSecurityConfig extends WebSecurityConfigurerAdapter {

    protected void configure(HttpSecurity http) throws Exception {
        http
            .sessionManagement().sessionCreationPolicy(SessionCreationPolicy.STATELESS)
            .and()
            .authorizeRequests()
                // SSO 프록시 (public)
                .antMatchers("/api/v1/auth/**").permitAll()
                // 게스트 관련 (public)
                .antMatchers("/guest/exists", "/guest/auth",
                             "/group/invite", "/group/join-guest").permitAll()
                // 기타 public
                .antMatchers("/swagger-ui/**", "/v3/api-docs/**").permitAll()
                .antMatchers("/actuator/health", "/", "/robots.txt").permitAll()
                .anyRequest().authenticated()
            .and()
            // RS256 JWT 검증 (JWKS)
            .oauth2ResourceServer()
                .jwt()
                    .jwtAuthenticationConverter(jwtAuthenticationConverter());
    }

    private Converter<Jwt, AbstractAuthenticationToken> jwtAuthenticationConverter() {
        return jwt -> {
            String spUserId = jwt.getSubject();
            String email = jwt.getClaimAsString("email");
            String name = jwt.getClaimAsString("name");
            String userType = jwt.getClaimAsString("userType");

            // 학심정 user 자동 생성/동기화는 여기서 또는 별도 필터에서 처리
            // SecurityContext에 spUserId를 principal로 설정

            var authorities = List.of(
                new SimpleGrantedAuthority("ROLE_" + (userType != null ? userType : "USER"))
            );
            return new UsernamePasswordAuthenticationToken(
                new SpAuthenticatedUser(spUserId, email, name, userType),
                null, authorities
            );
        };
    }
}
```

**변경 포인트:**
- `JwtAuthenticationFilter` 제거 → `oauth2ResourceServer().jwt()` 사용
- `jwtAuthenticationConverter()`에서 JWT Claims → `SpAuthenticatedUser` 변환
- permitAll 경로 정리 (자체 인증 URL 제거, SSO 프록시 URL 추가)

```java
public static Long requireCurrentUserNo() {
    SpAuthenticatedUser user = getCurrentSpUser();
    // spUserId → 학심정 user.user_no 조회 (캐시 권장)
    return userMapper.findBySpUserId(user.spUserId()).getUserNo();

public static SpAuthenticatedUser getCurrentSpUser() {
    Authentication auth = SecurityContextHolder.getContext().getAuthentication();
    if (auth != null && auth.getPrincipal() instanceof SpAuthenticatedUser user) {
        return user;
    }
    throw new AuthFailedException("인증 정보가 없습니다.");
}
```

## 2.9 게스트 인증 플로우 상세

### 현행

```
FE: POST /guest/exists { inviteCode, email }
  → BE: 그룹 확인 + 게스트 멤버 확인
FE: POST /member/send-code { email, purpose: "GUEST" }
  → BE: 이메일 인증코드 발송 (EmailVerificationService)
FE: POST /member/verify-code { email, code }
  → BE: 인증코드 검증
FE: POST /guest/auth { inviteCode, email }
  → BE: JwtUtil.generateGuestAccessToken() ← 자체 JWT 발급
  ← { accessToken, refreshToken, stdtId, claId }
```

### 변경 후

```
FE: POST /guest/exists { inviteCode, email }
  → BE: 그룹 확인 + 게스트 멤버 확인 (그대로 유지)
FE: POST /member/send-code { email, purpose: "GUEST" }
  → BE: 이메일 인증코드 발송 (유지 — 게스트 이메일 인증은 학심정이 계속 담당)
FE: POST /member/verify-code { email, code }
  → BE: 인증코드 검증 (유지)
FE: POST /guest/auth { inviteCode, email }
  → BE: GuestTokenService.issueGuestToken(name)
    → Auth 프록시 POST /api/v1/auth/guest/token { name }
    → Auth 서버 POST /oauth2/guest-token { clientId, clientSecret, name }
    ← { accessToken, guestId }
  → BE: group_member INSERT (기존 로직 유지)
  ← { accessToken, stdtId, claId, guestId }
FE: auth.setGuestToken(accessToken)  ← SDK에 게스트 토큰 주입
```

**핵심**: 이메일 인증은 학심정이 유지하고, 토큰 발급만 Auth로 전환.
**주의**: `send-code`, `verify-code` 엔드포인트는 게스트용으로 유지 (EmailVerificationService도 유지).
