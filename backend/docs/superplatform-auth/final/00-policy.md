## 확정 정책

| 항목 | 결정 |
|------|------|
| 오픈 방식 | Auth 서버와 학심정 **동시 오픈** |
| 인증 | Auth 서버 SSO (OAuth2 + PKCE) |
| JWT | **RS256** (Auth 서버 서명, 학심정은 JWKS 공개키로 검증) |
| 회원가입 | Auth 서버 담당 (학심정 자체 가입 없음) |
| 비밀번호 관리 | Auth 서버 담당 (학심정 DB에 password 컬럼 없음) |
| 개인정보 저장 | 학심정 DB에도 저장 (Auth JWT에서 동기화) |
| 서비스 데이터 | 학심정 DB (그룹/상담/검사 등) |
| Admin 인증 | 별도 `admin_account` 테이블, 자체 세션 로그인 |
| 게스트 인증 | 이메일 인증 유지 + **Auth 게스트 토큰** 사용 |
| FE 인증 | Auth Client SDK (CDN UMD 번들) |

## Auth에서 오는 정보 vs 학심정 추가 수집

### 일반 회원 (SSO 로그인)

| 정보 | Auth JWT에서 오는가 | 학심정 추가 수집 | 비고 |
|------|:---:|:---:|------|
| email | O | | JWT `email` claim |
| name | O | | JWT `name` claim → 학심정 nickname으로 사용 |
| userType (교사/학생) | O | | JWT `userType` → 학심정 role_code 매핑 |
| **gender (성별)** | **X** | **필수** | Auth 가입 시 미수집 → 학심정 추가 입력 |
| **role 선택** | **△** | **조건부** | `userType=UNSET`(소셜 가입 등)인 경우 학심정에서 역할 선택 필요 |

### 게스트

| 정보 | Auth 게스트 토큰에 포함 | 학심정 수집 | 비고 |
|------|:---:|:---:|------|
| name (닉네임) | O (`name` claim) | | 게스트 입장 시 입력 → Auth 토큰 발급 시 전달 |
| **email** | **X** (빈값) | **필수** | 학심정이 직접 수집 + 이메일 인증코드 검증 |
| **gender** | X | X | 게스트는 현행도 미수집 → 변경 없음 |

## 최초 로그인 시 "추가 정보 입력" 화면

SSO 로그인 후 학심정에 user가 없으면 (최초 접근) 추가 정보 입력 페이지로 리다이렉트.

```
┌──────────────────────────────────┐
│  서비스 이용을 위해               │
│  추가 정보를 입력해주세요          │
│                                  │
│  ┌── userType=UNSET일 때만 표시 ─┐│
│  │  역할 선택 *                  ││
│  │  ○ 교사  ○ 학생              ││
│  └───────────────────────────────┘│
│                                  │
│  성별 *                          │
│  ○ 남  ○ 여                     │
│                                  │
│  [시작하기]                       │
└──────────────────────────────────┘
```

- 닉네임: Auth `name`을 그대로 사용 (별도 입력 없음)
- 성별: 필수 입력
- 역할: Auth `userType`이 `UNSET`인 경우에만 표시

두 번째 로그인부터는 이미 user가 있으므로 바로 대시보드 진입.

## 게스트 플로우

```
게스트 진입
  → 초대코드 입력 (현행 유지)
  → 닉네임 입력 (현행 유지)
  → 이메일 입력 + 이메일 인증코드 검증 (학심정 자체 — 현행 유지)
  → Auth 게스트 토큰 발급 (name만 전달, email은 학심정 DB에 저장)
  → group_member INSERT (stdt_id 채번, email 저장)
  → FE: auth.setGuestToken(accessToken)
  → 검사 참여

변경되는 것:  토큰 발급 주체 (자체 JWT → Auth 게스트 토큰)
안 변경되는 것: 이메일 수집, 이메일 인증, group_member.email 저장
```

## 게스트 관련 ISMS 참고

게스트 이메일은 학심정 `group_member.email`에 저장된다. 이는 "회원 개인정보"가 아닌 "검사 참여자 연락처"로서, Auth DB가 아닌 서비스 DB에 보관하는 것이 타당하다:
- 게스트는 Auth 서버에 계정이 없음
- 이메일은 검사 결과 발송 목적으로만 사용
- 게스트 → 회원 전환 시 email 매칭에 사용 후 소멸
