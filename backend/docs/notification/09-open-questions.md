## 🔴 Critical — 개발 시작 전 필수

### Q1. S4 그룹 초대 이메일 기능 범위

**현재 상황**:
- 학심정은 `/join/{inviteCode}` 링크 기반 가입만 존재
- 스펙은 "교사가 이메일로 초대 발송"

**확인 필요**:
- 교사가 학생 이메일 목록 입력 → 초대 메일 발송 기능을 신규 개발할 것인가?
- 미가입 이메일이면 가입 유도 메일만? 가입 후 자동 그룹 연결?

**영향**:
- 신규 개발 시 +3일 공수
- MVP 제외 시 S4 알림 이벤트 자체 미구현 (고도화 이월)

---

### Q2. S5 학생 추방 기능 존재 여부

**현재 상황**:
- DB에 `group_member.status = KICKED` enum 존재
- 교사 UI에 추방 기능 구현 여부 미확인

**확인 필요**:
- 교사가 학생을 추방하는 UI/기능이 실제 구현되어 있는가?
- 없다면 기능 추가 + 알림 연동 동시 개발?

**영향**:
- 기능 없음 → MVP 제외, +1일 (별도 개발 시)
- 기능 있음 → 알림 훅 추가만 (0.5일)

---

### Q3. S6 재검사 요청 기능 존재 여부

**현재 상황**:
- 교사가 특정 학생에게 재응시 요청 기능 구현 여부 미확인

**확인 필요**:
- 기능 존재? 없다면 신규 개발 범위?
- 데이터 모델: 어떤 테이블에 요청 기록? 학생이 받으면 재응시 가능 상태로 전환?

**영향**:
- 신규 개발: +2일
- MVP 제외: S6 알림 미구현

---

### Q4. T4 vs T6 — "집계 배치" 정의

**현재 상황**:
- T4: "배정 인원 100% 제출" — 자동 감지 가능
- T6: "집계 배치 완료 시" — **배치 정의 불명확**

**확인 필요**:
- "집계 배치"가 뭔가? (자동 스케줄러? 수동 [검사 종료] 버튼? 관리자 개입?)
- T4와 T6가 실제로 다른 시점인가? 같은 시점이면 통합?

**영향**:
- 배치 정의 확정 → T6 트리거 위치 결정
- MVP에서 T6 제외 or T4와 통합 가능

---

### Q5. S3 결과 공개 시점

**현재 상황**:
- 스펙: "교사가 결과를 학생에게 공개 (또는 자동 공개 시점)"
- 학심정에 "결과 공개" 상태 컬럼 또는 [결과 공개] 버튼 존재 여부 미확인

**확인 필요**:
- 교사가 수동으로 [결과 공개] 누르는 구조?
- 자동 공개라면 언제 (검사 종료 즉시? 종료 + N일 후?)
- 공개 상태 관리 테이블/컬럼 존재?

**영향**:
- 결정 안 되면 S3 구현 불가

---

### Q6. 회원가입 이메일(C1) 중복 발송 가능성

**현재 상황**:
- 학심정 가입 = SSO 회원가입 + 학심정 프로필 등록
- Auth 서버가 자체적으로 가입 축하 메일을 보낼 수 있음

**확인 필요**:
- Auth 팀에 "회원가입 완료 시 Auth 서버가 어떤 메일을 발송하는지" 확인
- 중복되면 학심정 C1 제거
- 중복 아니면 학심정 `createUser()` 성공 후 발송

**영향**:
- 중복 발송 시 사용자 혼란

## 🟠 High — 개발 진행 중 조기 확정

### Q7. T2 학생 그룹 탈퇴 — 어떤 경로 포함?

**옵션**:
- `LEFT` (자발적 탈퇴)만 → 추천
- `KICKED` (교사 추방) 포함?
- `ARCHIVED` (그룹 종료) 포함?

**제안**:
- T2: `LEFT`만
- S5: `KICKED`만
- `ARCHIVED`: 알림 없음 (교사 본인 행동)

**확인 필요**: 위 제안 동의 여부

### Q8. T4 발송 타이밍

**옵션**:
- A: 제출 트랜잭션 내에서 `submitted_count == total_count` 체크 → T3 + T4 동시 발송
- B: 별도 배치로 주기 체크 → 지연 허용

**제안**: 옵션 A (즉시성)

**확인 필요**: 제출과 동시에 "전원 완료" 알림이 쌓여도 UX 문제 없는지

### Q9. T5 / S2 발송 대상 정책

**T5 (교사 대상):**
- 미제출자 **1명 이상** 있으면 발송? (제안)
- 미제출 비율 X% 이상만 발송?

**S2 (학생 대상):**
- 본인이 미제출한 경우에만 발송 (당연)
- 이미 제출한 학생 제외

**확인 필요**: 발송 빈도/대상 정책 최종 확정

---

### Q10. T5 / S2 "D-3" 기준

스펙 문구: "검사 시작 D-3부터 D-1"

**해석**:
- 검사 **마감일** 기준이 자연스러움 (문구의 "%남은 일수%")
- 검사 **시작일** 기준이면 "시작 후 3일 내"로 해석 어색

**제안**: 마감일 기준

**확인 필요**: 의도 확정

## 🔵 법무 검토 — 반드시 선행

### Q17. 닉네임 박제 저장 허용 여부

**쟁점**:
- 개인정보보호법상 "수집 목적 달성 시 즉시 파기" 원칙
- 탈퇴 사용자의 닉네임을 다른 사용자의 알림에 노출해도 되는가?

**확인 필요**:
- 닉네임이 개인정보에 해당하는지
- 탈퇴 시 알림의 닉네임을 마스킹해야 하는지 (예: "탈퇴한 사용자")

**영향**:
- 마스킹 필요 시 → 알림 row에 `actor_user_no` 저장하고 탈퇴 시 일괄 UPDATE 필요
- 설계 변경 범위 큼 → 개발 전 확정 필수
