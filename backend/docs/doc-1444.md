# QCH API 연동 가이드 — 외부 서비스 로그 적재

> **누가** 외부 개발팀 / 협력사 / 다른 부서의 백엔드·프런트 개발자.
> **무엇** QCH(Quality Coverage Hub) 에 로그를 보내는 모든 경로 — HTTP / NATS / 앱 로그.
> **이 문서 한 장만 보고 연동을 끝낼 수 있도록** 작성.
> 내부 DB 컬럼 매핑 / 사고 분석 / 디버깅은 **doc 1490 (내부 검증 가이드)** 가 별도.

---

## 0. 시작하기 전에 — 결정해야 할 3가지

| 결정 | 선택지 | 권장 |
|---|---|---|
| ① 채널 | HTTP POST / NATS publish / 브라우저 app-log | API trace = HTTP 또는 NATS 중 1개, SPA·SDK 일반 로그 = app-log |
| ② 등록 | serviceKey / env / baseUrl 사전 등록 | §1.1 양식으로 운영팀에 신청 |
| ③ 민감정보 | Authorization / 카드 / RRN 등 | §6 redact **외부 책임 — 필수** |

### 채널 선택 가이드

| 경로 | 적합 | 부적합 |
|---|---|---|
| **HTTP POST** `/api/v1/ingest/trace` | 분당 수백~수천 건, 단순함, 즉시 응답 필요 | 분당 만건 이상 초고트래픽, QCH 장애 시 backlog 보존 필요 |
| **NATS publish** `QCH_TRACE_LOG_*` | 고트래픽, fan-out, 비동기 | 분당 수십 건 이하 (broker 운영비용 비효율) |
| **app-log** `/api/v1/ingest/app-log` | 브라우저 JS 에러, 사용자 이벤트, Airflow / 게임 / SDK | API trace (시그니처 자동 매핑 안 됨) |

> **두 채널 동시 사용 금지** — HTTP + NATS 로 같은 trace 보내면 중복 적재됨. 한 채널만 선택.

## 1. 사전 준비 — QCH 운영팀에 등록

### 1.1 신청 양식

QCH 운영팀에 다음 정보를 보낸다 (Teams `#qch-support` 또는 이메일).

```
[QCH 연동 신청]
부서/팀:
서비스명 (한글):
serviceKey   (영문 소문자/하이픈, 예: vlms-extra):
env          (DEV / STG / PROD / MATH_PROD ...):
baseUrl      (env 별 — 테스트 실행 시 호출할 URL):
auth_type    (NONE / JWT / OIDC / HMAC / API_KEY / BASIC / CUSTOM):
연동 채널     (HTTP / NATS / app-log — 복수 가능, trace 는 1개):
NATS 발행 계정 (NATS 사용 시):
OpenAPI URL  (선택 — 호출 안 된 endpoint 도 시그니처에 등록):
allowed_methods (선택):
연락처        (Teams ID / 이메일):
```

### 1.2 등록 후 받는 것

| 항목 | 내용 |
|---|---|
| HTTP 사용 | `https://qch.vsaidt.com/api/v1/ingest/...` 그대로 사용 (별도 토큰 불필요) |
| NATS 사용 | broker URL `nats://log-stream.vsaidt.com:4222` + 6 토픽 PUB 권한 (creds 발급) |
| 테스트 실행 필요 | `service_test_auth` 등록 (JWT tokenUrl/clientId 등 — §5) |

> `serviceKey` 는 사후 변경 비권장 — 기존 데이터 마이그레이션 안 됨. 신중히 결정.

### 2.4 클라이언트 — Java Spring (RestClient)

```java
@Component
@RequiredArgsConstructor
public class QchTraceClient {

    private final RestClient restClient;     // baseUrl = https://qch.vsaidt.com
    private static final String SERVICE_KEY = "vlms-extra";
    private static final String ENV         = System.getenv().getOrDefault("APP_ENV", "PROD");

    public void sendTrace(String method, String endpoint, int statusCode,
                          long durationMs,
                          Map<String, Object> reqHeaders,
                          Object reqBody, Object respBody) {
        Map<String, Object> body = Map.of(
            "serviceKey",     SERVICE_KEY,
            "env",            ENV,
            "method",         method,
            "endpoint",       endpoint,
            "statusCode",     statusCode,
            "responseTimeMs", durationMs,
            "testcoverage",   "Y",
            // "testAllowed", false,    // 옵션 — endpoint 가 자동 테스트에 부적합하면 명시
            "traceId",        MDC.get("traceId"),
            "createdAt",      Instant.now().toString(),
            "payload",        Map.of(
                "queryParams",    Map.of(),
                "requestHeaders", reqHeaders == null ? Map.of() : reqHeaders,
                "requestBody",    reqBody    == null ? Map.of() : reqBody,
                "responseBody",   respBody   == null ? Map.of() : respBody
            )
        );
        try {
            restClient.post()
                .uri("/api/v1/ingest/trace")
                .contentType(MediaType.APPLICATION_JSON)
                .body(body)
                .retrieve()
                .toBodilessEntity();
        } catch (Exception ex) {
            log.warn("QCH trace failed (best-effort): {}", ex.getMessage());
            // ingest 실패는 본 서비스 응답에 영향 X
        }
    }
}
```

`@Around` AOP / `OncePerRequestFilter` 로 모든 컨트롤러 호출에 자동 부착 권장. **반드시 §6 redact 후 보낼 것.**

### 2.5 클라이언트 — Node.js / TypeScript

```ts
async function sendTrace(event: {
  method: string; path: string; status: number; durationMs: number;
  reqHeaders?: Record<string, string>; reqBody?: unknown; respBody?: unknown;
  testAllowed?: boolean;
}) {
  await fetch(`${process.env.QCH_BASE_URL}/api/v1/ingest/trace`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      serviceKey: process.env.QCH_SERVICE_KEY,
      env:        process.env.APP_ENV ?? 'PROD',
      method:     event.method,
      endpoint:   event.path,
      statusCode: event.status,
      responseTimeMs: event.durationMs,
      testcoverage: 'Y',
      testAllowed: event.testAllowed,   // 옵션 (§8) — undefined → 서버에서 true 처리
      createdAt:  new Date().toISOString(),
      payload: {
        queryParams:    {},
        requestHeaders: event.reqHeaders ?? {},
        requestBody:    event.reqBody    ?? {},
        responseBody:   event.respBody   ?? {},
      }
    })
  }).catch(err => console.warn('QCH trace failed:', err));
}
```

## 3. NATS Ingest

### 3.1 사용 시점
- 분당 수천 건 이상의 트래픽
- 본 서비스 응답 속도에 ingest 가 영향 주면 안 됨
- 재처리 / fan-out 필요

### 3.2 토픽 / Subject

| 토픽 | 환경 | 용도 |
|---|---|---|
| `QCH_TRACE_LOG_DEV` | DEV | API trace |
| `QCH_TRACE_LOG_PROD` | PROD | API trace |
| `QCH_SOCKET_ERROR_LOG_DEV` | DEV | 소켓 에러 |
| `QCH_SOCKET_ERROR_LOG_PROD` | PROD | 소켓 에러 |
| `QCH_COVERAGE_LOG_DEV` | DEV | trace shape — 외부 도우미가 testcoverage 마킹 시 |
| `QCH_COVERAGE_LOG_PROD` | PROD | 위 동일 |

### 3.3 메시지 본문

`POST /api/v1/ingest/trace` 와 **완전히 같은 JSON 스키마** (§2.2). `testAllowed` 도 그대로 포함시킬 수 있고, HTTP / NATS 어느 쪽으로 보내든 적재 결과는 동일 — `payload.{queryParams, requestHeaders, requestBody, responseBody}` 모두 채울 것.

### 3.4 자동 적재 보장

QCH 백엔드가 위 6 토픽을 자동으로 subscribe 해서 적재한다. **외부 발행자 입장에선 publish 만 하면 끝** — ack/nak 신경쓸 필요 없음 (현재 core NATS, fire-and-forget).

> 발행 후 적재 확인 방법은 §7 자기검증 참조.

### 3.5 클라이언트 — Java NATS

```java
@Component
@RequiredArgsConstructor
public class QchNatsTracePublisher {

    private final Connection nats;     // io.nats.client.Connection
    private final ObjectMapper objectMapper;

    public void publishTrace(TracePayload trace, String env) {
        String subject = "QCH_TRACE_LOG_" + env.toUpperCase();
        try {
            byte[] body = objectMapper.writeValueAsBytes(trace);
            nats.publish(subject, body);
        } catch (Exception ex) {
            log.warn("QCH NATS publish failed: {}", ex.getMessage());
        }
    }
}
```

### 3.6 클라이언트 — Go

```go
type Trace struct {
    ServiceKey  string                 `json:"serviceKey"`
    Env         string                 `json:"env"`
    Method      string                 `json:"method"`
    Endpoint    string                 `json:"endpoint"`
    StatusCode  int                    `json:"statusCode"`
    TestAllowed *bool                  `json:"testAllowed,omitempty"`
    Payload     map[string]interface{} `json:"payload"`
}

func PublishTrace(nc *nats.Conn, env string, t *Trace) error {
    body, _ := json.Marshal(t)
    return nc.Publish("QCH_TRACE_LOG_"+strings.ToUpper(env), body)
}
```

JetStream durable consumer 가 필요한 경우 `js.Publish(...)` 로 변경.

### 3.7 NATS 권한 (외부 계정에 발급되는 것)

| 계정 | 권한 |
|---|---|
| 외부 서비스 발행 계정 | PUB on `QCH_TRACE_LOG_{ENV}`, `QCH_SOCKET_ERROR_LOG_{ENV}`, `QCH_COVERAGE_LOG_{ENV}` |

> SUB 권한은 QCH 운영팀이 책임. 외부에서 신경쓸 필요 없음.

### 4.1 엔드포인트

### 4.5 브라우저 — vanilla JS 글로벌 에러 핸들러

```html
<script>
  window.QCH_BASE_URL    = 'https://qch.vsaidt.com';
  window.QCH_SERVICE_KEY = 'qch-fe';
  window.QCH_ENV         = 'PROD';

  function sendAppLog(payload) {
    const body = JSON.stringify({
      sourceType: 'BROWSER',
      serviceKey: window.QCH_SERVICE_KEY,
      env:        window.QCH_ENV,
      createdAt:  new Date().toISOString(),
      ...payload
    });
    if (navigator.sendBeacon) {
      navigator.sendBeacon(`${window.QCH_BASE_URL}/api/v1/ingest/app-log`,
        new Blob([body], { type: 'application/json' }));
    } else {
      fetch(`${window.QCH_BASE_URL}/api/v1/ingest/app-log`, {
        method: 'POST', headers: { 'Content-Type': 'application/json' }, body, keepalive: true
      }).catch(() => {});
    }
  }

  window.addEventListener('error', (e) => sendAppLog({
    logType: 'ERROR', component: 'window', code: 'JS_RUNTIME',
    message: e.message,
    raw: { filename: e.filename, lineno: e.lineno, colno: e.colno, stack: e.error?.stack,
           userAgent: navigator.userAgent, url: location.href }
  }));

  window.addEventListener('unhandledrejection', (e) => sendAppLog({
    logType: 'ERROR', component: 'promise', code: 'UNHANDLED_REJECTION',
    message: String(e.reason), raw: { stack: e.reason?.stack, url: location.href }
  }));
</script>
```

```tsx
export function logAppEvent(payload: {
  logType?: 'ERROR' | 'WARN' | 'INFO' | 'EVENT';
  component?: string; code?: string; message?: string;
  raw?: Record<string, unknown>; extra?: Record<string, unknown>;

    method: 'POST', headers: { 'Content-Type': 'application/json' },

  }).catch(() => {});
}

export class QchErrorBoundary extends React.Component<{children: React.ReactNode}> {

      raw: { stack: error.stack, componentStack: info.componentStack }

  render() { return this.props.children; }
}
```

## 5. 테스트 인증 (테스트 실행이 필요한 경우만)

QCH 가 외부 서비스 endpoint 를 직접 호출하는 자동 테스트가 필요할 때 `service_test_auth` 등록.

### 5.1 지원 타입
| auth_type | 설명 | 상태 |
|---|---|---|
| NONE | 인증 없음 | OK |
| **JWT** | tokenUrl + clientId 로 토큰 발급 → Authorization: Bearer | 구현됨 |
| OIDC / HMAC / API_KEY / BASIC / CUSTOM | 미구현 (확장 예정) | 보류 |

### 5.2 JWT 등록 예시

```json
{
  "auth_type": "JWT",
  "auth_config": {
    "tokenUrl":         "https://dev-auth.example.com/jwt",
    "clientId":         "test-runner",
    "clientSecretRef":  "vault://test/sample-api/client-secret",
    "scope":            "api.read"
  }
}
```

QCH 가 토큰 25분 캐시. **secret 평문 직접 전달 금지** — Vault / K8s Secret 참조만.

## 6. 민감정보 / 수집 제한 — **외부 책임**

다음은 적재 전에 **반드시 마스킹 또는 제거**.

| 분류 | 예시 |
|---|---|
| 인증 자격 | password, accessToken, refreshToken, **Authorization 헤더 원문**, Cookie, Set-Cookie, X-Api-Key |
| 결제 | 카드번호, CVV |
| 식별 | 주민등록번호, 여권번호 |
| 의료/금융 | 보호 대상 정보 (ISMS/CSAP 정책) |

`payload.requestHeaders` 가 jsonb 컬럼에 그대로 적재되므로 **반드시 redact 후 보낼 것**.

```ts
// 예시 — fetch wrapper 에서 헤더 redact
const headers = new Headers(init?.headers);
headers.delete('Authorization');
headers.delete('Cookie');
headers.delete('X-Api-Key');
sendTrace({ ..., reqHeaders: Object.fromEntries(headers) });
```

```java
// 예시 — Java
Map<String, String> redacted = new HashMap<>(reqHeaders);
redacted.replaceAll((k, v) ->
    Set.of("authorization", "cookie", "set-cookie", "x-api-key")
       .contains(k.toLowerCase()) ? "***redacted***" : v);
```

> 마스킹 안 하고 보낸 페이로드는 **외부 서비스 책임으로 보안 사고 처리**. 보안팀과 별도 협의 필요.

## 7. 자기검증 — "내가 보낸 trace 가 정말 적재됐는지"

| 단계 | 방법 | 기대값 |
|---|---|---|
| 1. HTTP 응답 확인 | `200 OK` + `code: "TRACE_ACCEPTED"` | 그대로 |
| 2. NATS publish 검증 | 별도 터미널에서 `nats sub <topic>` 띄우고 본인 메시지 보임 | 본인 페이로드 그대로 echo |
| 3. QCH 화면 — 적재된 trace 확인 | `/admin/dev-tools` 의 [최근 적재 trace] 카드 — service_key 필터 | 본인 trace 1건 보임 (1~3초 내) |
| 4. KPI 카운트 | `/monitoring/dashboard` — service 별 KPI | 카운트 +1 |
| 5. 시그니처 등록 확인 | `/tests/analysis/result` — service_key 필터 | 본인 endpoint 가 시그니처에 등록 |

## 8. testAllowed — 자동 테스트 허용 플래그 (옵션)

> trace / app-log 페이로드에 같이 보내는 **선택 boolean 필드**. 외부가 "이 endpoint 를 QCH 자동 테스트 대상으로 써도 되는지" 의도를 표시한다.

### 8.1 동작 요약

| 입력 | 의미 |
|---|---|
| `testAllowed: true` | "이 endpoint 는 자동 테스트 OK" — 일반적인 GET/조회 |
| `testAllowed: false` | "함부로 호출하면 안 됨" — 결제/송금/외부 효과/멱등성 없는 POST |
| 생략 / `null` | 서버에서 `true` 로 기본 처리 |

### 8.2 실제로 어디에 영향을 주나

```
[적재 시점]                                  [최종 결정]
api_logs.test_allowed   ← 매 호출의 입력값 (이력)
app_logs.test_allowed   ← 동일

api_signatures.test_eligible
   ← 시그니처 첫 등록 시 외부 testAllowed 값을 default 로 받음
   ← 그 후 외부 적재가 와도 이 컬럼은 변경되지 않음 (운영 결정 보호)
   ← QCH 운영자가 시그니처 화면에서 토글로 직접 변경 가능

테스트 자산 생성 / 자동 실행 = api_signatures.test_eligible = true 만 대상
```

즉 외부의 `testAllowed` 는 **시그니처가 처음 발견될 때 default 결정에만 영향**을 주고, 이후엔 QCH 운영팀의 판단(시그니처 토글)이 우선한다.

### 8.3 권장 사용

| 상황 | 권장 값 |
|---|---|
| 일반 조회 / 멱등성 보장 endpoint | 생략 (= true) |
| 결제 / 송금 / 외부 효과 발생 / 1회성 발급 | **`false`** 로 명시 |
| 운영팀과 합의된 자동 테스트 대상 endpoint | `true` 명시 |

> 보내는 측이 보수적으로 `false` 로 보내도 운영팀이 검토 후 시그니처 토글로 `true` 로 풀 수 있음 (whitelist 효과). 반대로 `true` 로 보내도 운영팀이 잠그면 테스트에서 제외됨 (blacklist 효과).

### 8.4 동시 채널 발행 시 주의

같은 endpoint 가 여러 채널 / 서비스 인스턴스에서 적재될 수 있다. 시그니처는 한 번 첫 등록되면 그 이후 외부 입력은 시그니처 컬럼에 반영되지 않으므로, **첫 등록 시점의 값만 default 가 된다**. 운영팀 변경 후엔 외부 입력이 시그니처를 덮어쓸 수 없다 — 의도된 동작.

## 9. 자주 묻는 질문 (FAQ)

| 질문 | 답 |
|---|---|
| 같은 trace 를 HTTP + NATS 로 둘 다 보내도 되나요? | **안 됨**. 중복 적재됨. 한 채널만. |
| trace 1건의 적재 응답 시간은? | 평균 < 50ms (DB write 포함). 그래도 본 서비스 응답에 영향 없도록 **best-effort 비동기** 권장. |
| HTTP 5xx 시 자동 재전송? | 클라이언트 책임. 단순 retry 권장 (지수 백오프 N=3). |
| NATS publish 실패 시 자동 재전송? | core NATS 는 fire-and-forget. JetStream durable consumer 도입 시 ack 기반 재시도. |
| 14일 이전 데이터 조회는? | 운영팀에 archive 조회 요청 (`api_logs_all` view). |
| `serviceKey` 변경하고 싶은데? | 운영팀 신청. 기존 데이터 마이그레이션 X — 신규 적재만 새 키로. |
| OpenAPI URL 등록의 효과? | 호출 안 된 endpoint 도 시그니처에 등록되어 커버리지에 반영. |
| `testAllowed=false` 로 보냈는데 자동 테스트 돌더라? | 운영팀이 시그니처 화면에서 `test_eligible=true` 로 토글했을 가능성. 위험 endpoint 면 운영팀과 협의 필수. |
| `testAllowed=true` 로 보냈는데 테스트가 안 돌아요 | 운영팀이 시그니처를 잠갔거나 (`test_eligible=false`), 또는 `test_exclusion_rules` 광역 패턴이 매칭됐을 수 있음. doc 1490 §10 디버깅 트리 참조. |
| `responseBody` 가 큰데 (수십 KB) 다 보내야 하나? | jsonb 256KB 한도. 너무 크면 핵심만 추려서. `extra` 도 동일 한도. |
| `traceId` 는 어디서 만드나? | 본 서비스의 W3C trace-context (`traceparent` 헤더) 또는 MDC 의 traceId 그대로. |
| 환경이 6종 (DEV/STG/PROD/MATH_DEV/MATH_PROD/...) 이상인데? | 운영팀에 env 추가 신청. |
