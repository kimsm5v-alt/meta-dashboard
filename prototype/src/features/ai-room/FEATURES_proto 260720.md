# AI 어시스턴트 기능 명세서

비상교육 **학습심리정서검사** 교사용 AI 어시스턴트 프로토타입의 기능 명세입니다.
다른 프로젝트에서 **재구현**하기 위한 문서로, 프레임워크에 의존하지 않는 동작·치수·상태 규칙을 기술합니다.

구성 요소는 두 가지입니다.

| # | 기능 | 형태 |
|---|---|---|
| A | **플로팅 챗봇** | 서비스 화면 위에 떠 있는 오버레이 어시스턴트 |
| B | **AI 어시스턴트 페이지** | GNB 메뉴로 진입하는 전체화면 단독 페이지 |

---

## 0. 공통 디자인 토큰

CSS 변수로 관리했습니다. 색상 값만 맞춰도 톤이 재현됩니다.

```
/* 브랜드 */
--c-primary:              #6C5CE7   /* 메인 보라 */
--c-primary-light:        #A29BFE
--c-primary-bg:           #F8F7FF   /* 연한 보라 배경(칩/활성 항목) */
--c-primary-border:       #E8E4FF
--c-primary-border-light: #F0EDFF

/* 시맨틱 */
--c-warn:    #E17055    --c-warn-bg: #FEF5EE    --c-warn-border: #FDE4CC
--c-success: #00B894    --c-success-bg: #E8F5E9

/* 중립 */
--c-text: #1a1a2e   --c-text-secondary: #555   --c-text-muted: #999   --c-text-faint: #ccc
--c-bg: #F3F4F8     --c-bg-card: #fff          --c-bg-hover: #FAFAFD
--c-border: #F0EFF5 --c-border-light: #EEEDF5

/* 치수 */
--chatbot-width:       388px                                   /* 코너 패널 기본/최소 폭 */
--gnb-height:          104px                                   /* 상단 GNB 높이 */
--chatbot-full-height: calc(100vh - var(--gnb-height) - 24px)  /* 코너 패널 기본 높이 */
--chatbot-radius:      16px
```

- **폰트**: Pretendard
- **애니메이션**: `slideUp`(패널 등장, 0.28s cubic-bezier(0.16,1,0.3,1)), `bounce`(타이핑 점), `toastIn`, `fadeIn`(딤 배경)

## A. 플로팅 챗봇

서비스 화면(대시보드 등) 위에 떠서, **현재 보고 있는 화면 맥락**으로 질문할 수 있는 어시스턴트.

### A-1. 4가지 보기 모드

| 모드 | 설명 | 치수·동작 |
|---|---|---|
| **버블** | 접힌 진입점 | 52×52, radius 14, 우하단 `right:24 bottom:24`, 보라 배경 + 채팅 아이콘, hover 시 `scale(1.06)` |
| **입력바** | 한 줄 빠른 질문 | 폭 388, radius 14, 우하단. 구성: 로고 → ✂캡처 → 입력창 → 전송 → ⊞ → ✕ |
| **코너** | 기본 대화 패널 | 폭 388(최소·기본), 높이 `100vh - GNB - 24`, radius 16, 우하단 고정. **이동·리사이즈 가능** |
| **전체화면** | 몰입 모드 | 중앙 정렬, 폭 `min(920px, 92vw)`, 상하 `3vh`, radius 18, **뒤에 딤 배경** `rgba(28,22,58,0.42)`. 내용은 **760px로 가운데 정렬**. 이동·리사이즈 불가 |

**모드 전환 규칙**
- 헤더 `⊞` 버튼 → 모드 선택 팝오버. **버블은 목록에서 제외**(닫기 `✕`가 곧 버블 복귀이므로 중복)
- 버블/입력바 상태에서 **질문을 전송하면 자동으로 코너 모드로 전환**
- 전체화면은 대시보드 레이아웃을 **밀어내지 않고 위에 얹힘** (사이드 독 방식은 채택하지 않음)

### A-2. 창 조작 (코너 모드 전용)

| 조작 | 핸들 | 규칙 |
|---|---|---|
| **이동** | 헤더 드래그 | 뷰포트 밖으로 나가지 않도록 clamp |
| **높이 조절** | 상단 모서리 6px (`ns-resize`) | **하단 고정**, 최소 240px |
| **폭 조절** | 좌측 모서리 6px (`ew-resize`) | **우측 고정**, 최소 388px |

### A-3. 추천 질문 — 하이브리드 방식

챗봇 UI 리서치(빈 화면 명확성 + 대화 지속 유도) 결과 채택한 방식입니다.

- **빈 화면(대화 전)**: 인사말 `무엇이 궁금하세요?` + 부제 `화면의 데이터에 대해 물어보세요` + **세로 리스트**
  - 각 행: `이모지 + 질문 텍스트 + → 화살표`, 흰 배경 + 보더, hover 시 보라 틴트
- **대화 중**: 입력창 바로 위에 라벨 `이어서 물어보기`(9.5px 대문자) + **가로 스크롤 알약 칩**
- **화면이 바뀌면 질문 세트도 즉시 교체** (→ 6장 데이터 참조)

### A-4. 메시지 UI

- **사용자**: 우측 정렬 말풍선, `max-width 78%`, radius `14px 14px 4px 14px`, 보라 배경/흰 글씨
- **봇**: 전체 폭 블록(배경 `--c-bg-hover`, 상하 보더), **마크다운 렌더링**(굵게/줄바꿈/목록)
- **참고용 배지**: 봇 답변 하단 `ℹ AI 분석 · 참고용`
- **타이핑 인디케이터**: 점 3개 bounce + `분석 중`

### A-5. 화면 캡처 질문

1. `✂` 클릭 → 전체화면 오버레이(커서 `crosshair`, 딤 0.4)
2. 드래그로 영역 선택 (최소 20×20). 선택 영역은 보라 보더 + `box-shadow: 0 0 0 9999px rgba(0,0,0,.4)`로 구멍 뚫듯 강조
3. 완료 시 코너 모드 진입 + 입력창에 `선택한 영역에 대해 질문: ` 프리필
4. 입력창 위에 `✂ 캡처 첨부됨` 표시, 전송된 메시지엔 `✂ 캡처 포함` 배지

### A-6. 토스트

하단 중앙(`bottom:96`), 어두운 배경, **3초 후 자동 소멸**, 선택적으로 이동 링크 버튼 포함.

## B. AI 어시스턴트 페이지 (전체화면)

GNB의 **AI어시스턴트** 메뉴로 진입하는 단독 페이지. 일반 LLM 서비스(ChatGPT·Claude·Gemini)에 익숙한 구조를 따릅니다.

### B-1. 레이아웃

```
┌──────────────────────────────────────────────────────┐
│ VISANG │ AI 어시스턴트              [← 대시보드로]    │ 56px
├───────────────┬──────────────────────────────────────┤
│ ＋ 새 대화     │  💬 현재 대화 제목                   │ 50px
│ ─────────────  ├──────────────────────────────────────┤
│ 💬 AI 대화     │                                      │
│ 📝 생활기록부  │        (대화 / 생기부 영역)          │
│ ─────────────  │                                      │
│ 오늘           │                                      │
│  · 대화1       │                                      │
│ 지난 7일       │  ─────────────────────────────────   │
│  · 대화2       │  [추천 질문 칩]                      │
│ 이전           │  [＋대상] [칩][칩]                   │
│  · 대화3       │  [입력창]                    [전송]  │
└───────────────┴──────────────────────────────────────┘
      240px                    (내용 max 760px 중앙)
```

**중요**: 모드 선택(AI 대화 / 생활기록부)은 **좌측 LNB**에 두고, **상단 바에는 현재 대화 제목만** 표시합니다.

### B-2. 좌측 LNB (240px, 배경 `--c-bg-hover`)

1. **＋ 새 대화** — 흰 배경 + 보라 보더 버튼
   - 이미 비어 있는 "새 대화"가 활성이면 **중복 생성하지 않고 재사용**
2. **모드 내비** — `AI 대화` / `생활기록부 작성`. 활성 시 보라 배경 + 보라 굵은 글씨
3. **대화 히스토리** — `오늘` / `지난 7일` / `이전` 그룹. 항목은 채팅 아이콘 + 제목(말줄임), 활성 하이라이트, hover 틴트
   - 항목 클릭 → 해당 대화 복원 + 자동으로 `AI 대화` 탭 전환

**대화 데이터 모델**
```js
{ id, title, group: "오늘"|"지난 7일"|"이전", messages: [...] }
```
- 새 대화의 제목은 **첫 질문으로 자동 설정** (22자 초과 시 `…`)
- 각 대화는 독립적으로 메시지를 보관 (전환해도 유지)

### B-3. 탭 1 — AI 대화

**메시지 UI**: 사용자 말풍선(우측) / 봇 답변은 **아바타 + 흰 카드**(보더 + radius 12) + 마크다운 + 참고용 배지.

**대상(학급·학생) 선택 — 입력창에 부착하는 방식**

> 챗봇에서 "질문 대상"을 지정하는 표준 패턴(컨텍스트 칩 + 피커 + 멘션)을 따랐습니다.
> 별도 사이드바를 두지 않아 일반 LLM 레이아웃을 유지합니다.

- 입력창 위 **`＋ 대상`** 버튼(솔리드 보라 알약) → **피커 팝오버**(264px)
  - 학급 드롭다운
  - **학급 전체** 체크박스 — 켜면 **하위 학생 체크박스도 전부 선택**. 반대로 전원 개별 선택 시에도 "학급 전체"가 켜진 것으로 표시
  - 학생 목록: 체크박스 + 번호 + 이름 + `관심` 태그
- 선택 결과는 **삭제 가능한 칩**으로 표시 (`고우진 ✕`). 학급 전체는 `6학년 1반 전체 ✕` 단일 칩
- 입력창에 **`@` 입력 시 피커가 열림** (멘션 패턴, `@`는 입력값에서 제거)
- 대상 미선택도 허용 — 안내문구: `대상을 고르면 해당 학급·학생 기준으로 답합니다 (선택)`
- 전송된 사용자 메시지 위에 `👥 대상명` 표기

**추천 질문(동적)** — 선택 상태에 따라 달라짐
| 선택 상태 | 추천 질문 예시 |
|---|---|
| 학급 전체 | 전체 경향 요약 / 관심 필요 학생 / 강점 TOP 3 |
| 학생 1명 | `{이름}` 결과 종합 해석 / 코칭 전략 / 학부모 상담 화법 |
| 학생 2명 이상 | 공통 관심 영역 / 그룹 지도 전략 / 강점 비교 |

### B-4. 탭 2 — 생활기록부 작성 (교사 행정 지원)

작업형 화면이라 **명시적 폼 방식**을 유지합니다.

1. **대상 학생**: `＋ 학생 선택` 피커(위와 동일) → 선택된 학생들이 칩으로 나열, **클릭해 1명 지정**
2. **문구 유형**: `종합` / `강점 중심` / `행동·태도` 3분할 세그먼트
3. **생성** 버튼 → 검사 결과 기반 문구 초안 생성
4. **결과**: 편집 가능한 `textarea` + 글자 수 + **복사** 버튼(복사 시 `✓ 복사됨` 2초)
5. 하단 고지: `참고용 초안 · 교사 검토 후 사용하세요`
6. 미선택 시 빈 상태: `학생을 선택하세요` 안내

**문구 톤**: 생활기록부 문어체(`~함`, `~음`). 강점을 먼저 쓰고 보완점은 성장 관점으로 서술.

## C. 상단 GNB (호스트 화면)

챗봇이 얹히는 서비스 화면의 네비게이션입니다.

| 1Depth | 2Depth |
|---|---|
| 홈 | — |
| 검사 | 검사관리 · 결과보기 · 학생 상담 · 변화추적 |
| 코칭 | 학급 코칭 · 개별 코칭 |
| 수업 | 수업 자료실 · 나의 자료 |
| **AI어시스턴트** | — (클릭 시 B 페이지 진입) |

- 로고(VISANG)도 **홈**으로 이동
- 1depth는 **헤더 중앙 정렬**, 활성 항목은 보라 글씨 + 하단 인디케이터(2.5px)
- 2depth는 바로 아래 연회색 서브바(42px)에 **중앙 정렬**
- **AI어시스턴트는 강조**: 그라데이션 알약 버튼(`linear-gradient(120deg, #6C5CE7, #8B7CF0)`) + ✨ 아이콘 + 그림자 + hover 부양
- 우측: 알림 벨(뱃지) + 프로필 아바타

```js
// 메시지

{ [화면키]: [ { emoji, text } ] }
```

## E. 화면별 추천 질문 (QA 시나리오 기준)

챗봇이 **현재 화면에 맞춰** 노출하는 질문 세트입니다. 화면 키는 GNB 2depth 라벨과 일치시킵니다.

**홈**
- META 학습종합검사는 어떤 영역을 측정하나요?
- 검사 결과를 처음 보는데, 어디서부터 시작하면 좋을까요?
- 긍정적 요인과 부정적 요인은 어떻게 다르게 해석하나요?
- 검사 결과를 상담이나 수업에 어떻게 연결할 수 있나요?

**검사관리**
- 검사는 학생에게 얼마나 걸리나요?
- 1차, 2차 검사는 보통 언제 실시하나요?
- 검사 전에 학생들에게 안내할 사항이 있나요?
- 검사 결과는 언제부터 확인할 수 있나요?

**결과보기**
- T점수 구간(매우 낮음~매우 높음)은 각각 어떤 의미인가요?
- 우리 반의 강점과 보완점은 어떻게 구분하나요?
- 긍정적 요인이 높으면 무조건 좋은 건가요?
- 우리 반 결과를 요약해줄 수 있나요?

**학생 상담**
- 상담 우선순위는 어떤 기준으로 정해지나요?
- 학기 초 학부모 상담에서 검사 결과를 어떻게 소개하면 좋을까요?
- 상담 시 어떤 표현을 쓰면 좋고, 어떤 표현은 피해야 하나요?
- 상담 기록은 이후 어떻게 활용되나요?

**변화추적**
- 1차 대비 2차에서 점수 변화는 어떻게 해석하나요?
- 점수가 변하지 않은 척도는 문제인가요?
- 변화 결과를 출력하거나 공유할 수 있나요?
- 변화 결과를 학부모에게 어떻게 설명하면 좋을까요?

**학급 코칭**
- 반 전체 결과를 바탕으로 어떤 코칭 방향을 잡을 수 있나요?
- 학업 요구와 학습 자원의 균형은 어떻게 판단하나요?
- SEL 콘텐츠 추천은 어떤 기준으로 이루어지나요?
- 코칭 활동 후 효과를 어떻게 확인할 수 있나요?

**개별 코칭**
- 학습 유형에 따라 코칭 방향이 어떻게 달라지나요?
- 학부모 가이드는 어떤 내용을 담고 있나요?
- 강점을 활용한 코칭이란 구체적으로 어떤 건가요?
- 코칭 전략과 상담 기록은 어떻게 연결되나요?

**수업 자료실**
- 검사 결과에 따라 어떤 수업 자료를 선택하면 좋을까요?
- 맞춤형 큐레이팅은 어떤 기준으로 추천되나요?
- 학년별 성장 로드맵은 어떻게 활용하나요?
- 자료를 직접 만들거나 수정할 수 있나요?

**나의 자료**
- 수업 결과 리포트에서 어떤 점을 확인하면 좋을까요?
- 수업 활동이 검사 결과 변화에 영향을 주었는지 어떻게 확인하나요?
- 세트별, 학생별, 슬라이드별 리포트는 각각 뭘 보여주나요?
- 이 결과를 바탕으로 다음 수업을 어떻게 계획하면 좋을까요?

> **학생 선택 시 변형 질문**(결과보기·학생상담의 개인 단위)은 학생을 고르는 **B 페이지**에 배치하는 것이 적합합니다.

## F. 재구현 시 주의사항 ⚠️

프로토타입 개발 중 실제로 겪은 버그들입니다. **미리 알면 시간을 크게 아낍니다.**

**1. `overflow:hidden` 컨테이너가 팝오버를 잘라먹음**
패널에 `overflow:hidden`이 걸려 있으면, 패널 **바깥 위쪽**으로 뜨는 팝오버(모드 선택 등)가 보이지 않습니다.
→ 팝오버를 **컨테이너 내부(헤더 아래)** 로 배치하거나 Portal로 렌더링하세요.

**2. `position:fixed; inset:0` 래퍼가 뒤 화면 클릭을 막음**
플로팅 챗봇을 전체 화면 래퍼로 감싸면 **호스트 화면이 클릭 불가**가 됩니다.
→ 래퍼 `pointer-events: none`, 실제 패널만 `pointer-events: auto`.

**3. 리사이즈 앵커링 계산**
- 높이 조절(상단 핸들)은 **하단 좌표를 고정**하고 `높이 = 하단 - 마우스Y`
- 폭 조절(좌측 핸들)은 **우측 좌표를 고정**하고 `폭 = 우측 - 마우스X`
- 단, 드래그로 위치를 옮겨 `top/left` 앵커가 된 상태라면 리사이즈할 때 **위치도 함께 보정**해야 반대편이 고정됩니다.

**4. 드래그 핸들과 내부 버튼 충돌**
헤더 전체를 드래그 핸들로 쓰면 헤더 안의 버튼(⊞, ✕)이 눌리지 않습니다.
→ `e.target.closest("button")`이면 드래그 시작을 건너뛰고, 리사이즈 핸들은 `stopPropagation()`.

**5. 리사이즈 핸들끼리 겹침**
상단 핸들과 좌측 핸들이 모서리에서 겹치면 커서가 튑니다.
→ 상단 핸들은 좌우 10px, 좌측 핸들은 상하 10px씩 **안쪽으로 들여** 배치.

**6. 화면 전환 시 상태 유실**
챗봇 모드를 바꿀 때 컴포넌트 트리가 갈라지면 하위 상태가 초기화됩니다.
→ **현재 화면(컨텍스트) 상태는 상위에서 관리**하고 prop으로 내려주세요.

## G. 참고 — 설계 시 근거로 삼은 UX 원칙

- 추천 질문은 **3~5개, 구체적·실행 가능**하게. "무엇이든 물어보세요"는 무용지물
- 추천 질문은 매뉴얼 없이 **봇의 능력 범위**를 알려주는 장치
- 빈 화면(empty state)엔 **핵심 행동 하나만** — 버튼·텍스트 과잉 금지
- 질문 대상 지정은 **컨텍스트 칩 + 피커**가 기본, `@` 멘션은 보조
  (교사 등 비개발자 대상에선 **눈에 보이는 버튼**이 멘션보다 발견성이 높음)
- 검사 해석의 윤리를 UI에 반영: **강점 우선 서술**, **참고용 표기**, **상대평가 안내**
