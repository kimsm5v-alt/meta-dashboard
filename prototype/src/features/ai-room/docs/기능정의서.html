AI 어시스턴트 기능 정의서

META 학습심리정서검사 교사용 AI 어시스턴트 프로토타입 기능 정의서 대상: 개발 리뷰용 | 작성 기준: prototype

0. 개요

교사가 검사 결과 화면 맥락에서 즉시 질문하거나(플로팅 챗봇), 전용 페이지에서 대화를 수행할 수 있는 AI 어시스턴트입니다. 구성은 두 가지입니다.

# 기능 형태 진입점
A 플로팅 챗봇 서비스 화면 위 오버레이 우측 하단 플로팅 버블
B AI 어시스턴트 페이지 GNB 하위 전체폭 단독 화면 상단 GNB의 부엉이 아이콘
  • A와 B는 대화 히스토리를 공유합니다. 플로팅 챗봇에서 나눈 대화가 어시스턴트 페이지 히스토리에 남습니다.
  • 코드 위치: prototype/src/features/ai-room/

현재 구현 성격 (중요)

  • AI 응답은 mock입니다. services/assistantService.ts가 지연 후 정해진 마크다운을 반환합니다. 실제 LLM(Gemini) 연동은 미구현이며, 반환 형태({ content, isReference })만 유지하면 UI 수정 없이 교체 가능합니다.
  • 학급/학생 데이터는 mock입니다(data/mockClasses.ts, 3개 반). 실제 API 연동 필요.
  • 화면 캡처는 영역 선택까지만 구현(실제 픽셀 캡처 아님). 상세는 A-5 참고.

1. 공통 사항

1-1. 데이터 모델 (types.ts)

interface ChatMessage {
  id: string;
  role: 'user' | 'bot';
  content: string;          // 마크다운 문자열
  targets?: string;         // 질문 대상 표기 (예: '6학년 1반 전체')
  hasCapture?: boolean;     // 화면 캡처 첨부 여부
  isReference?: boolean;    // 'AI 분석 · 참고용' 배지
}

interface Conversation {
  id: string;
  title: string;
  group: '오늘' | '지난 7일' | '이전';
  messages: ChatMessage[];
  screen?: string;          // 플로팅 챗봇에서 질의한 화면 라벨 (예: '결과보기')
}

// 봇 응답 (API 교체 시 이 형태만 유지)
interface BotResponse { content: string; isReference?: boolean; }

1-2. 대화 히스토리 공유 스토어 (utils/conversationStore.ts)

  • 모듈 레벨 스토어 + useSyncExternalStore 구독. A/B가 동일한 대화 목록을 공유합니다.
  • API: conversationStore.get(), .subscribe(), .update(updater), useConversations()
  • 주의: 새로고침 시 초기 시드로 리셋(영속화 미구현). 실제 구현 시 서버/스토리지 연동 필요.

1-3. AI 서비스 경계 (services/assistantService.ts)

함수 역할 교체 지점
askAssistant(question, context?) 대화 응답 → 실제 LLM 호출로 교체
generateSchoolRecord(name, tone) 생기부 문구 초안 (생기부 탭은 현재 '준비 중')
getTargetQuestions(...) 대상별 추천질문 현재 미사용(참고용)

1-4. 화면 컨텍스트 · 화면별 추천 질문 (utils/useScreenContext.ts, data/screenQuestions.ts)

  • 현재 라우트에서 화면 키를 파생(pathToScreenKey)해 화면 라벨과 추천 질문을 제공합니다.
  • 결과보기·학생상담은 LNB에서 학생 선택 시 학생 단위 질문으로 교체됩니다(resolveScreenQuestions(screenKey, hasStudent)).
화면 라우트 학생 선택 반영
홈 / 검사관리 / 변화추적 / 학급코칭 / 수업자료실 각 라우트 —
결과보기 /exam/result ✅
학생 상담 /exam/counseling ✅
개별 코칭 /coaching/individual (학생 단위 고정)

1-5. 개인정보(PII) 정책

  • 정책상 이름·학번·생년월일·학교명은 AI 전송 시 마스킹 대상입니다(프로젝트 공통 규칙).
  • 현 프로토타입은 mock 응답이라 실제 전송/마스킹 로직 미적용. 실제 API 연동 시 shared/utils/piiMasking.ts 등과 연계 필요.

2. A. 플로팅 챗봇

파일: components/floating/FloatingChatbot.tsx (+ CaptureOverlay.tsx, Toast.tsx) 마운트: app/LayoutV2.tsx에서 보호 화면 위에 오버레이 (단, /ai-assistant 화면 제외)

A-1. 보기 모드 (4종)

모드 설명 치수·동작
버블 접힌 진입점 52×52, 우하단 고정. 클릭 시 코너 모드로 열림
입력바 한 줄 빠른 질문 폭 388. 로고·캡처·입력·전송·⊞·✕
코너 기본 대화 패널 폭 388(최소), 높이 100vh−GNB−여백. 이동·리사이즈 가능
전체화면 몰입 모드 min(920px,92vw), 딤 배경, 내용 760 중앙. 이동·리사이즈 불가
  • 모드 전환: 헤더 ⊞ 팝오버(버블 제외). ✕는 세션 종료 후 버블 복귀.
  • 버블/입력바에서 질문 전송 시 자동으로 코너 모드로 전환.

A-2. 창 조작 (코너 전용)

  • 이동: 헤더 드래그(뷰포트 clamp). 높이: 상단 핸들(하단 고정, 최소 240). 폭: 좌측 핸들(우측 고정, 최소 388).

A-3. 추천 질문 (하이브리드)

  • 빈 화면: 인사말 + 화면 캡처 CTA(강조) + 화면별 추천 질문 세로 리스트.
  • 대화 중: 입력창 위 이어서 물어보기 가로 칩. 이미 물어본 질문은 제외.
  • 화면 이동/학생 선택 시 질문 세트 즉시 교체(1-4 참조).

A-4. 메시지 UI

  • 사용자: 우측 말풍선. 봇: 전체폭 블록(--c-bg-hover 배경 + 상하 보더) + 마크다운 + AI 분석 · 참고용 배지.
  • 타이핑 인디케이터: 점 3개 + 분석 중.

A-5. 화면 캡처 질문

  1. ✂ 캡처 클릭 → 전체화면 crosshair 오버레이(질문할 영역을 드래그하세요 · ESC로 취소).
  2. 드래그로 영역 선택(최소 20×20). 선택 영역 크기(w×h) 기록.
  3. 완료 시 첨부 미리보기 카드(영역 비율 썸네일 + {w}×{h}px) 표시, 입력창 placeholder가 이 영역에 대해 무엇이 궁금하세요?로 전환.
  4. 전송 메시지에 캡처 포함 배지.
  • 미구현: 실제 화면 픽셀 캡처(현재 영역 선택·치수만). 실제 구현 시 html2canvas 등 또는 백엔드 캡처 연동 필요.

A-6. 히스토리 저장 (화면 태그)

  • 챗봇에서 첫 질문 시 공유 스토어에 대화 생성, 질의한 화면 라벨을 screen으로 태그. 이후 메시지는 해당 대화에 누적.
  • ✕(세션 종료) 시 로컬 대화는 초기화(히스토리에는 이미 저장). 재오픈 시 새 대화로 시작.

A-7. 현재 화면 표시

  • 헤더에 🖥 {화면명} 배지로 현재 보고 있는 화면을 표시.

3. B. AI 어시스턴트 페이지

파일: pages/AIRoomPage.tsx (+ AssistantChatTab.tsx, SchoolRecordTab.tsx) 라우트: /ai-assistant (레거시 /ai-room → 리다이렉트)

B-1. 진입 · 레이아웃

  • GNB의 부엉이 아이콘 클릭 → /ai-assistant. 상단 GNB는 그대로 유지되고, 좌측 스코프 사이드바·서브탭은 숨긴 채 전체폭으로 렌더(LayoutV2가 라우트 인지 처리).
  • 구조: 좌측 LNB(240px) + 본문(현재 대화 제목 바 + 탭 콘텐츠).

B-2. 좌측 LNB

  1. ＋ 새 대화 — 비어있는 '새 대화'가 있으면 재사용.
  2. 모드 내비 — AI 대화 / 생활기록부 작성.
  3. 대화 히스토리 — 오늘 / 지난 7일 / 이전 그룹. 항목 hover 시 ⋮ 메뉴:
    • 제목 편집(인라인 입력, Enter 저장/Esc 취소), 삭제(활성 대화 삭제 시 자동 전환, 전부 삭제 시 새 대화 생성).

B-3. 탭 1 — AI 대화

  • 메시지 UI: 사용자 말풍선 / 봇은 부엉이 헤더 + 전체폭 블록 + 마크다운 + 참고용 배지.
  • 대상 선택: 입력창 위 ＋ 대상(솔리드 보라 알약) → 대상 선택 모달(3-1). @ 입력 시에도 모달 오픈. 선택 결과는 학급 단위 요약 칩(6학년 1반 전체, 6학년 2반 3명, ✕로 제거). 전송 메시지에 👥 대상명 표기.
  • 대화 내보내기: 제목 바 우측 ↓ 내보내기 → 대화 내용을 마크다운(.md) 파일로 다운로드(질문/답변/대상/질의화면 포함).

3-1. 대상 선택 모달 (components/TargetPicker.tsx)

다중 학급 + 대인원 대응 모달(720px).

  • 좌: 학급 목록 — 최상단 전체 학급(모든 학급 일괄) + 학급별 체크박스(학급 전체) · 부분 선택 표시(indeterminate) · 인원수(n/total). 행 클릭 시 우측에 해당 학급 학생 노출.
  • 우: 학생 그리드 — 2~3열 + 검색(이름 필터) + 전체 선택/해제(현재 검색 결과 일괄).
  • 하단: 선택 N명 요약 + 전체 해제 + 완료. 배경 클릭·ESC로 닫기.
  • 선택 모델: TargetSelection = { byClass: Record<classId, studentIds[]> } (학급 전체는 전원 id로 표현).

B-4. 탭 2 — 생활기록부 작성 (준비 중)

  • 현재 '준비 중인 기능입니다' 안내 + 화면 블러 가림 처리로 노출(SchoolRecordTab 위에 오버레이).
  • 정식 오픈 시 오버레이 제거 + 실제 생성 로직 연동.

5. 개발 이관 시 확인사항

  1. AI 응답 연동: askAssistant를 실제 LLM 호출로 교체. 반환 형태({ content, isReference })·마크다운 유지 시 UI 무수정.
  2. 학급/학생 데이터: mockClasses.ts → 실제 API. TargetSelection(classId→studentIds) 구조 확인.
  3. 히스토리 영속화: conversationStore는 메모리 스토어. 서버/스토리지 연동 필요.
  4. 화면 캡처: 실제 픽셀 캡처 방식 결정(FE 라이브러리 vs 백엔드).
  5. PII 마스킹: 실제 전송 경로에 마스킹 적용.
  6. 생활기록부: 오버레이 제거 시점·실제 생성 로직.
  7. 공용 영역 의존: app/LayoutV2.tsx, app/routesV2.tsx(라우트·스코프 시스템)와 결합. 스코프의 selectedStudent를 플로팅 챗봇 추천질문에 사용.
