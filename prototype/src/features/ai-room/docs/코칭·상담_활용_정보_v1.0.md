## 1. 코칭 개요

- 코칭은 학생의 **LPA 유형 + 38개 요인 T점수**를 바탕으로, 그 학생/반에 맞는 **강점 활용·보완 개입 전략**을 제시하는 기능입니다.
- 단위: **개별 코칭**(학생 1명) / **학급 코칭**(반 단위).
- 근거 데이터의 두 축:
  - **개인 T점수**(프론트가 주입) ↔ **유형 집단 평균 T점수**(Neo4j `GROUP_TSCORE`) 비교로 강점·보완을 선별.
  - 요인 간 인과 관계(**조절/매개 경로**, Neo4j)로 "무엇을 건드리면 학업성취에 도움이 되는가"를 제시.
- **고등학생은 코칭 대상에서 제외**됩니다(전용 LPA 모델 없음 → 강점/약점 분석만).

## 2. 코칭 추천 근거 — 강점·보완 산정

실제 서빙 경로(백엔드)는 **유형 집단 평균 대비 편차(need)** 로 강점·보완을 정합니다.

**need(보완 필요도) 계산**
```
정적(긍정) 요인:  need = 집단평균T − 개인T     // 개인이 집단보다 낮을수록 need↑
부적(부정) 요인:  need = 개인T − 집단평균T     // 개인이 집단보다 높을수록 need↑
deviation = 개인T − 집단평균T                  // 양수=강점 방향, 음수=보완 방향(정적 기준)
```

**선별 규칙**
- **보완점 = need 상위 3개 요인** (집단 대비 가장 불리한 쪽)
- **강점 = need 하위 3개 요인** (집단 대비 가장 유리한 쪽, 강한 순으로 제시)
- **코칭 경로 = 강점 최상위 1개 + 보완 최상위 1개 = 2개** — 각 요인이 조절요인(Z)인 대표 조절경로(ModerationPath)를 붙임.
- 개인/집단 T점수를 확보하지 못하면 **개인 T점수 절대값 기준 상·하위 3개**로 폴백(집단 비교 없이).

> 참고: 프론트에는 관련도 점수(`relevanceScore = needScore×0.5 + deviationScore×0.3 + betaBoost×0.2`, 유형평균 없으면 `needScore×0.65 + betaBoost×0.35`)로 개입을 랭킹하는 별도 로직도 있으나(「기본 정보」 §5.3), **현재 어떤 화면에도 연결되지 않은 상태**입니다(§10). 실제 화면 서빙은 위 편차 선별 방식입니다.

## 3. 조절·매개 경로 (개입·지지 전략)

코칭 문구의 근거가 되는 요인 간 관계는 Neo4j 그래프의 두 경로로 표현됩니다.

| 경로 | 의미 | 구조 | 주요 필드 |
|------|------|------|----------|
| **조절 경로(ModerationPath)** | **개입 전략** | X(독립요인) · **Z(조절요인)** → Y(성과=학업성취도) | `pathType, x, z, y, interpretation(해석), strategy(전략), keywordInterp, keywordStrat, zFactorType` |
| **매개 경로(MediationPath)** | **지지 전략** | X → **M(매개요인)** → Y | `x, m, y, pathType, interpretation, strategy` |

- 즉 "이 학생의 **어떤 요인(Z/M)** 을 개선·지지하면 **학업성취(Y)** 로 이어진다"는 인과 근거를 담습니다.
- 관계: `(LPAClass)-[:HAS_MODERATION_PATH]→(ModerationPath)`, `-[:HAS_MEDIATION_PATH]→(MediationPath)`, `-[:GROUP_TSCORE]→(Factor)`.
- 유형은 초·중 6종만(초등: 자원소진형/안전 균형형/몰입자원 풍부형, 중등: 냉소적 무기력형/정서조절 취약형/자기주도 몰입형).

## 4. 개별 코칭 구성 (강점 카드·코칭 카드)

개인화 코칭(v2)은 **강점 top2 요인 + 보완점 top1 조절경로**를 뽑아, 교사가 바로 쓸 수 있는 카드로 구성합니다. (Neo4j로 선별 → DB에서 코칭 텍스트 조회 → 카드 조립)

- **강점 카드 (상위 2개 요인)**
  - `observation` — 강점이 드러나는 관찰 포인트
  - `line` — 학생에게 건넬 **칭찬 멘트**
  - `question` — 강점을 확장하는 **질문**
- **보완 코칭 카드 (보완 top1 조절경로)**
  - `zFactor / xFactor / yFactor / pathType / interpretation` — 왜 이 경로가 중요한지
  - `coaching1 { method, line }` — 코칭 방법 + 멘트
  - `coaching2 { action, line }` — 실천 행동 + 멘트
- 문구의 **`[학생명]` 자리는 실제 학생 이름으로 치환**됩니다(프론트에서 치환).
- 대상: 조회는 `answerIdx` 기준. **고등/미분류 학생은 빈 카드**로 응답합니다.

> 코칭 문구·멘트 텍스트는 도메인 데이터(DB)에서 나오므로, 챗봇은 이를 **직접 문장으로 생성하지 않고** "학생을 선택하면 실제 카드/문구를 조회해 안내"하는 방식이 정확합니다.

## 5. 학급 코칭 전략 (반 단위)

반 단위 코칭은 **반의 약점 영역(중분류)** 을 기준으로 전략 카드를 제시합니다.

- 11개 중분류(긍정적자아·대인관계능력·메타인지·학습기술·지지적관계·학업열의·성장력·학업스트레스·학습방해물·학업관계스트레스·학업소진)별 **전략 템플릿**을 두고, 각 템플릿은 `아이콘·제목·설명·실행 활동 4개`로 구성됩니다.
- **반 약점 TOP 3**(반 평균 기준 보완 영역)에 해당하는 전략을 최대 3개 노출.
- 각 전략의 **실행 활동은 체크리스트(체크박스)** 로 표시해 진행 여부를 체크할 수 있습니다.
- **1차·2차 비교(변화 모드)** 에서는 **1차 대비 악화(신규 진입)된 약점 영역을 우선 배치**합니다.

> 학급 코칭 전략은 반 프로파일(클라이언트 산출) 기반으로 동작하며, 개별 코칭의 Neo4j 경로와는 별개 로직입니다.

## 6. 코칭 진행 순서

- 정식으로 정의된 **단계(STEP) 스펙은 없습니다.** 화면 흐름으로만 순서가 암시됩니다.
- 개별 코칭 화면의 흐름: **① 강점/보완점 카드 확인 → ② 코칭 경로 펼치기**(`X × Z → Y`) → **"왜 이 경로가 중요한가요?"(해석)** → **"구체적 실행 전략"(전략을 문장 단위 번호 스텝으로 제시)**. 라벨은 '강점 코칭 / 보완 코칭'.
- 권장 운영 순서(설계 취지 기준): **학생 유형·특징 확인 → 강점 인정·활용 → 보완점 개입(조절경로 전략) 실행 → 관찰·상담 기록 → 다음 회차에서 변화 확인**. (단, "유형 확인 → 강점 → 보완"의 공식 단계 정의는 코드/문서에 없음 — §10)

## 7. 상담 ↔ 코칭 ↔ 생활기록부 연계

- **상담 완료 시** 소요시간·상담 내용(요약)과 함께 **후속 조치(nextSteps)** 를 자유 텍스트로 남깁니다. 필요하면 '후속 상담(follow-up)' 유형으로 다음 상담을 **수동 등록**합니다.
  - ⚠️ nextSteps는 메모일 뿐, **다음 상담·코칭·생기부를 자동 생성하는 시스템 연계는 없습니다.**
- **데이터 참조 수준의 연계는 존재**합니다:
  - **생활기록부 문구 생성**은 상담 기록·관찰 메모를 근거로 활용합니다(관찰 메모=실제 에피소드(Fact) 핵심 근거, 상담 기록=내면적 고민·변화 의지).
  - 상담 연속성: 이전 상담 내용을 참고해 후속 조치 이행 여부를 확인하도록 설계.
  - 생기부 톤 일관성: 기존 저장 문구가 있으면 톤·내용을 참고.
- 학생 개별 화면 우측 패널에 **생기부·상담·관찰(메모) 탭이 통합**되어 있어, 검사 T점수만으로 부족한 맥락을 이 기록들이 보완합니다.

## 8. 코칭 후 효과 점검·변화 확인

- 코칭의 효과는 **1차/2차 검사 비교(변화추적)** 로 확인합니다(2차 데이터가 있을 때 '변화 모드' 활성화).
  - 학급: 약점 영역의 악화/해소, 유형 분포 변화, **AI 학급 변화 분석(2차 기준)** 제공.
  - 위험군 목록: 신규/지속/해소/악화 변화 표시.
- **코칭 후 효과 점검 전용 성공지표·체크리스트의 정식 정의는 없습니다.** 학급 코칭 전략의 '실행 활동 체크박스'(§5)가 유일한 체크 수단입니다.
- AI 프롬프트 차원에서는 "후속 조치 이행 여부 확인", "관찰 메모의 긍정 변화를 칭찬·강화" 같은 지침으로 변화 점검을 보조합니다.

## 9. AI 분석의 코칭 활용 & 관련 API·Tool

**AI 분석 → 코칭 활용 흐름**
- 어시스턴트/총평은 **학습 코치** 페르소나로, 학생의 강점·약점·상담기록을 컨텍스트로 받아 **구체적·실행 가능한 코칭 전략**을 제시하도록 설계돼 있습니다.
- 챗봇은 개입·지지 전략이 필요하면 Neo4j Tool(조절/매개 경로)을 조회해 **개인 T점수 + 집단 평균·전략**을 결합해 답합니다.
- 데이터 해석 도우미에도 "어떤 코칭 전략이 효과적일까요?" 등 코칭 카테고리가 포함됩니다.

**관련 API / 챗봇 Tool**
| 구분 | 엔드포인트/Tool | 용도 |
|------|----------------|------|
| 학생 분석(코칭 포함) | `GET /api/dgnss/st/analysis?...&graphYn=Y` | 학생 결과 + Neo4j 추천 경로 |
| 개인화 코칭 v2 | `GET /api/dgnss/st/coaching/{answerIdx}` | 강점 카드 + 보완 코칭 카드 |
| 학급 조절경로 | `GET /api/dgnss/graph/classes/{className}/moderation-paths` | 유형별 개입 전략 목록 |
| 유형/응답 기반 추천 | `GET /api/dgnss/graph/recommendation/by-answer/{answerIdx}` · `.../by-type` | 관련도 순 추천 |
| 챗봇 Tool | `get_moderation_paths` / `get_mediation_paths` | 조절(개입)·매개(지지) 경로 |
| 챗봇 Tool | `get_lpa_class_info` / `get_factor_scores` / `get_lpa_overview` | 유형 메타·요인 집단 평균·통합 조회 |

## 10. 구현 현황·미확정 항목

코칭은 **설계 로직과 실제 노출 상태의 차이가 큽니다.** 챗봇 답변·기획 판단 시 아래를 유의하세요.

- **개별/학급 코칭 화면(GNB)** 은 현재 **미구현 placeholder**(`/coaching/individual`, `/coaching/class` = "다음 구현 단계에서 연결").
- **개별 학생 코칭 전략(Neo4j 편차 선별, §2·§4)** 은 API로 서빙되지만, 프론트에서 **운영(prod) 환경에서는 숨김 처리**되어 있습니다(데이터 이슈, HSJ-108). 고등/미지원 학생도 제외.
- **개인화 코칭 v2 API(`/st/coaching`, §4)** 는 백엔드는 구현됐으나 **프론트 소비처가 없습니다**(현재 화면 미연결).
- **관련도 랭킹(relevanceScore, §2 참고)** 로직은 **어떤 화면에도 연결되지 않은 데드코드**이며, 그 입력(β 등)은 목업 데이터 기반입니다.
- **코칭 추천 배지의 '시급/보완' 점수 임계값은 없습니다.** 코칭 배지는 강점/보완 2색 고정이며, '시급'은 4단계 진단 텍스트·상담 일정 `urgent` 유형에만 존재합니다.
- **유형별 총 조절경로 개수**는 코드 상수가 아니라 그래프 시드 데이터에 의존(코드에서 확정 불가). Tool 조회 limit 기본값만 존재(응답당 5, 목록 20, 최대 100).
- **코칭 진행 STEP 정의 / 전원 참여·유형별 적합성 가이드 / 코칭 활동의 수업 활용·편집 안내 / 코칭 후 성공지표**는 **코드·문서에 정의가 없습니다**(UNDEFINED).
- **상담 후 자동 후속(다음 상담/코칭/생기부) 생성 흐름 없음** — nextSteps 자유 텍스트 + 수동 후속상담(§7).
