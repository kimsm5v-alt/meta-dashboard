# 학습종합검사 기반 행동특성 및 종합의견 작성 지원 — 통합 명세

> **버전**: v1.0  
> **최종 수정**: 2026-07-24  
> **목적**: META 학습종합검사 결과 + 교사 관찰 입력을 결합하여, AI 기반 행동특성 및 종합의견 참고 문구를 생성하는 프로토타입 구현 가이드  
> **기능 성격**: 생활기록부 입력 완료본을 만드는 기능이 아니라, 검사 결과와 교사의 관찰 선택을 바탕으로 참고 문구를 추천하는 작성 지원 기능

---

## 1. 개요

### 1.1 화면의 역할

META 학습종합검사(학습심리정서검사) 서비스 내에서, 교사가 학생의 **행동특성 및 종합의견** 초안을 생성할 수 있도록 돕는 도구이다.

### 1.2 핵심 공식

```
검사 결과 요약 (강점 TOP3 + 보완 TOP3)
+ 교사 추가 입력 (관찰 요인 · 상황 · 행동 · 변화·지속 정도 · 구체적 장면)
= AI 참고 문구 생성
```

### 1.3 핵심 UX 원칙

1. 교사에게 긴 관찰 기록 작성을 요구하지 않는다.
2. 검사 결과는 학생의 행동을 단정하는 근거가 아니라, **관찰 주제를 추천하는 참고자료**로 사용한다.
3. 교사는 실제로 관찰한 요인과 행동만 선택한다.
4. 선택형 입력을 기본으로 하고 자유 입력은 선택 사항으로 제공한다.
5. AI 문구는 별도 확인 체크박스나 강제 수정 절차 없이 바로 복사할 수 있다.
6. 본 화면에서 나이스로 직접 등록하지 않는다.

### 1.4 법적 근거

| 근거 | 내용 |
|------|------|
| 초·중등교육법 제25조 | 학교생활기록의 작성 근거 |
| 2026학년도 기재요령 제16조 ①항 | "학년 동안 지속적으로 관찰한 학생의 행동특성을 바탕으로, 학생을 총체적으로 이해할 수 있는 종합의견을 학급 담임교사가 문장으로 입력한다" |
| 2026학년도 기재요령 개정사항 | "AI를 활용하여 생성한 자료를 서술형 항목에 그대로 입력하는 행위" 금지. 보조 수단 활용 시 "학생의 실제 수행과는 무관한 허위 또는 과장 기재 여부" 확인 필요 |
| META 교사용 설명서 특장점 3 | "학습 동기·습관 등을 객관적으로 평가해 생활기록부 작성 시 구체적이고 신뢰도 높은 근거 자료로 활용" |

### 1.5 기존 구현 현황

| 항목 | 상태 |
|------|------|
| 상담 기록 CRUD API | ✅ 구현 완료 |
| 관찰 메모 CRUD API | ✅ 구현 완료 |
| T점수 계산 | ✅ 기존 시스템 |
| LPA 분류 알고리즘 | ⚠️ 프론트엔드에서만 계산 |
| 생활기록부 문구 저장 API | ❌ 미구현 |
| AI 캐시 API | ❌ 미구현 |

### 1.6 기능 범위

#### 포함

- 학급 선택 및 학급별 작성 현황 확인
- 학급 전체 / 일부 학생 선택
- 강점 요인 TOP3, 보완 요인 TOP3 노출 및 요인별 관찰 질문
- 실제 관찰한 요인 선택
- 관찰 상황 · 행동 · 변화·지속 정도 선택
- 구체적 장면 자유 입력 (선택)
- 학생 1명 개별 생성, 선택 학생 다중 생성, 학급 전체 일괄 생성
- 일괄 생성 3가지 방식: 검사 결과 기반 초안 / 공통 상황 반영 / 학생별 관찰 확인
- AI 추천 문구 생성 (다른 표현 / 짧게 / 자세히 / 복사)
- 생성 결과 저장 (자동 저장 + 명시적 저장)
- 저장한 문구 확인 · 수정 · 재생성
- 직전 저장 문구 확인 및 복원
- 학생별 생성 실패 재시도
- 금지어 자동 검증
- PII 마스킹/복원

#### 제외

- 나이스 직접 연동 및 자동 입력
- 공식 누가기록 또는 보조부 관리
- 관찰 날짜 관리
- 교사별 승인·결재 프로세스
- 최종 확인 체크리스트 / 수정 후에만 복사 가능하도록 하는 제한
- 학생별 전체 수정 이력과 복잡한 버전 관리
- 검사 T점수, 백분위, LPA 유형의 직접 기재

## 2. 전체 화면 구조

본 기능은 3개 화면으로 구성한다.

```
[화면 1] 학급 작성 현황 (진입점)
   │
   ├── 학생 1명 클릭 ──→ [화면 3] 학생별 작성·확인·수정
   │
   └── 학생 N명 선택 + "선택 학생 문구 만들기"
          │
          ├── 1명 선택 ──→ [화면 3] 학생별 작성·확인·수정
          │
          └── 2명 이상 ──→ [화면 2] 다중·일괄 생성 설정 및 결과
                              │
                              └── 학생별 수정 ──→ [화면 3]
```

## 3. 화면 1 — 학급 작성 현황

### 3.1 화면 목적

- 학급 내 학생별 검사 결과와 작성 상태를 한 화면에서 확인한다.
- 전체 학생 또는 일부 학생을 선택하여 문구를 생성한다.
- 저장된 문구를 다시 열어 확인하고 수정한다.

### 3.2 상단 요약

```
5학년 2반 행동특성 및 종합의견 작성 지원
전체 25명 · 미작성 11명 · 초안 있음 10명 · 수정됨 4명 · 생성 실패 0명
```

### 3.3 학생 목록 표시 항목

```
[전체] [미작성] [입력 중] [초안 있음] [수정됨] [생성 실패]

[□ 전체 선택]                                    [선택 학생 문구 만들기]
┌────┬──────┬──────────┬────────────┬────────────┬──────────┬───────┐
│선택│ 학생 │ LPA 유형  │ 강점 TOP3   │ 보완 TOP3   │ 작성 상태 │ 작업  │
├────┼──────┼──────────┼────────────┼────────────┼──────────┼───────┤
│ □  │김학생│자기주도형  │공감, 수업   │시간관리     │미작성     │[작성] │
│ □  │이학생│정서취약형  │계획, 효능감 │정서조절     │초안 있음  │[확인] │
│ □  │박학생│냉소무기력  │성장, 관계성 │시험준비     │수정됨     │[수정] │
└────┴──────┴──────────┴────────────┴────────────┴──────────┴───────┘
```

| 항목 | 내용 |
|------|------|
| 선택 | 체크박스 |
| 번호·학생명 | 학번 + 이름 |
| LPA 유형 | 유형명 배지 (색상 코드 적용) |
| 강점 TOP3 | 검사 결과 기반 강점 요인 (초록 태그 칩) |
| 보완 TOP3 | 검사 결과 기반 보완 요인 (주황 태그 칩) |
| 작성 상태 | 미작성, 입력 중, 생성 중, 초안 있음, 수정됨, 생성 실패 |
| 최근 저장 | 저장 일시 |
| 작업 | 작성, 확인, 수정, 재시도 |

### 3.4 LPA 유형별 배지 색상

| 학교급 | 유형명 | 색상 코드 |
|--------|--------|----------|
| 초등 | 자원소진형 | #E74C3C |
| 초등 | 안전 균형형 | #3498DB |
| 초등 | 몰입자원 풍부형 | #2ECC71 |
| 중등 | 냉소적 무기력형 | #E74C3C |
| 중등 | 정서조절 취약형 | #F39C12 |
| 중등 | 자기주도 몰입형 | #2ECC71 |

### 3.5 강점·보완 요인 TOP3 추출 로직

11_코칭경로_랭킹알고리즘.md에 정의된 로직을 따른다.

```
1. LPA 유형별 GROUP_TSCORE(집단 평균 T점수) 조회
2. 편차 = 학생 개인 T점수 − 집단 평균 T점수
3. 정적요인(positive) 중: 편차 상위 3개 → 강점 요인
   정적요인(positive) 중: 편차 하위 3개 → 보완 요인
   부적요인(negative) 중: 편차 상위 3개 → 보완 요인
4. 강점 요인 → 초록 태그 / 보완 요인 → 주황 태그
```

### 3.6 학생 선택 방식

#### 전체 선택

- 현재 학급의 생성 가능 학생 전체를 선택한다.
- 검사 결과가 없는 학생은 선택 대상에서 제외하거나 비활성 상태로 표시한다.
- 이미 저장된 문구가 있는 학생이 포함되면 생성 전에 처리 방법을 선택하게 한다.

```
선택한 학생 중 4명은 저장한 문구가 있습니다.

○ 저장한 문구가 없는 학생만 생성
○ 모든 학생을 생성하고 기존 문구는 유지
○ 모든 학생을 생성하고 기존 문구를 교체
```

#### 일부 선택

```
3명 선택됨
[선택 해제] [선택 학생 문구 만들기]
```

### 3.7 학생 클릭 동작

- 미작성 / 입력 중 / 생성 실패 → 화면 3(학생별 작성)으로 이동
- 초안 있음 / 수정됨 → 화면 3(학생별 확인·수정)으로 이동

### 3.8 필터와 정렬

| 종류 | 옵션 |
|------|------|
| 상태 필터 | 전체 / 미작성 / 입력 중 / 초안 있음 / 수정됨 / 생성 실패 |
| 정렬 | 번호순(기본) / 이름순 / 작성 상태순 |

### 3.9 선택 인원별 추천 안내

| 선택 인원 | 추천 안내 |
|---:|---|
| 1명 | 학생별 관찰 정보를 입력하여 생성하는 방식을 추천 |
| 2~5명 | 학생별 관찰 정보 확인 방식을 추천 |
| 6명 이상 | 검사 결과 초안 또는 공통 상황 반영 방식을 추천 |
| 학급 전체 | 검사 결과 초안을 먼저 생성하고 필요한 학생만 보완하는 방식을 추천 |

추천은 안내로만 제공하며 생성 방식을 강제하지 않는다.

## 4. 화면 2 — 다중·일괄 생성 설정 및 결과

### 4.1 생성 방식 선택

학생을 2명 이상 선택하고 "선택 학생 문구 만들기"를 누르면 방식 선택 화면이 나온다.

```
선택한 25명의 문구를 어떻게 만들까요?

○ 검사 결과만으로 초안 만들기
○ 공통 상황을 추가하여 만들기
○ 학생별 관찰 정보를 확인한 뒤 만들기

[취소] [다음]
```

### 4.2 방식 A — 검사 결과 기반 초안

#### 용도

- 학급 전체 학생의 초안을 빠르게 생성할 때
- 교사가 이후 학생별로 필요한 문구만 보완하려 할 때

#### 사용 데이터

- 학생별 강점 TOP3, 보완 TOP3
- 학교급
- 검사 결과 해석 정보

#### 생성 원칙

- 검사 점수를 실제 행동으로 단정하지 않는다.
- "친구를 배려함"과 같이 직접 관찰이 필요한 사실을 새로 만들지 않는다.
- 검사 결과를 통해 확인할 수 있는 특성, 강점, 성장 가능성 중심으로 표현한다.
- 학생별 검사 결과에 따라 각각 다른 문구를 생성한다.
- 동일 학급 학생의 문구가 지나치게 동일하지 않도록 문장 구조를 다양화한다.

#### 안내 문구

```
검사 결과를 바탕으로 만든 참고 문구입니다.
학생의 실제 학교생활 모습을 확인한 뒤 활용해 주세요.
```

### 4.3 방식 B — 공통 상황 반영

#### 용도

- 학급 프로젝트, 발표 수업, 학생자치, 체육대회 준비 등 여러 학생이 함께 참여한 활동을 반영할 때

#### 입력 항목

```
공통 상황
[모둠 활동] [발표·의사소통] [학급 역할]
[어려운 과제·도전 상황] [기타]

활동 또는 장면
[학급 프로젝트 발표 준비________________________]

공통 행동
[각자 맡은 역할을 수행함]
[친구의 의견을 경청함]
[공동의 목표를 위해 협력함]
```

#### 적용 대상 설정

```
이 행동을 누구에게 적용할까요?

○ 선택한 학생 전체
○ 학생별로 선택
```

- "선택한 학생 전체"는 교사가 명시적으로 선택한 경우에만 적용한다.
- 공통 상황이 모든 학생에게 동일한 행동을 의미하지 않도록 주의한다.
- 학생별 적용을 선택하면 학생 목록에서 해당 행동의 적용 여부를 빠르게 체크한다.

### 4.4 방식 C — 학생별 관찰 정보 확인

#### 용도

- 2~5명 등 소수 학생을 선택했을 때
- 학생마다 실제 관찰한 요인과 행동을 확인한 뒤 생성할 때

#### 스테퍼 화면

```
1 / 3 김학생

검사 결과
강점 [타인공감능력] [수업태도] [성장마인드셋]
보완 [시간관리] [점검능력] [자기정서조절]

실제로 관찰한 요인
[타인공감능력] [수업태도]

관찰 상황
[모둠 활동]

관찰 행동
[친구의 의견을 경청함]
[도움이 필요한 친구를 지원함]

[이전] [건너뛰기] [다음 학생]
```

#### 하단 액션

```
[입력한 학생만 생성] [선택 학생 전체 생성]
```

### 4.5 생성 진행 상태

```
25명의 문구를 만들고 있습니다.

18 / 25 완료

김학생     완료
이학생     완료
박학생     생성 중
최학생     대기
```

### 4.6 일부 실패 처리

- 학생별 생성 작업을 독립적으로 처리한다.
- 일부 학생이 실패해도 완료된 결과는 유지한다.
- 실패 학생만 다시 생성할 수 있다.

```
완료 23명 · 실패 2명

[실패한 학생만 다시 만들기] [결과 확인]
```

```
│ 요인 설명 및 관찰 질문 → [관찰함] 선택                       │

│ ③ AI 추천 문구 또는 저장한 문구                              │
```

- 보완 요인 중 2차에서 T점수가 상승한 요인은 "개선 중" 표시 추가
- 이 데이터는 AI 문구 생성 시 "성장 서사" 재료로 자동 활용됨

### 5.2 ① 검사 결과 영역 — 요인 카드

```
검사 결과에서 살펴볼 요인

강점 TOP3
[타인공감능력] [수업태도] [성장마인드셋]

보완 TOP3
[시간관리] [점검능력] [자기정서조절]
```

#### 요인 카드 구성

각 요인을 탭하면 펼쳐지는 카드에 다음 내용을 제공한다.

- 구분: 강점 / 보완
- 요인명
- 한 줄 설명
- 관찰 질문
- 선택 상태

```
강점 | 타인공감능력

상대방의 감정과 입장을 이해하고 공감하는 능력

친구의 감정이나 입장을 이해하고 배려한 모습을
관찰한 적이 있나요?

[관찰함]
```

#### 관찰 질문 예시

| 요인 | 관찰 질문 |
|------|---------|
| 타인공감능력 | 친구의 감정이나 입장을 이해하고 배려한 모습이 있었나요? |
| 자기정서조절 | 속상하거나 어려운 상황에서도 감정을 조절하며 대응한 모습이 있었나요? |
| 성장마인드셋 | 실수하거나 실패한 뒤 다시 시도한 모습이 있었나요? |
| 시간관리 | 과제 시작, 준비물, 마감 시간을 스스로 관리한 모습이 있었나요? |
| 점검능력 | 자신의 결과물을 다시 확인하고 고치거나 보완한 모습이 있었나요? |
| 수업태도 | 설명을 경청하거나 질문·발표 등으로 수업에 참여한 모습이 있었나요? |
| 계획능력 | 해야 할 일을 순서대로 정하거나 계획한 모습이 있었나요? |
| 친구 정서지지 | 친구의 고민을 들어주거나 힘든 친구를 도운 모습이 있었나요? |
| 자아존중감 | 자신의 장점을 알고 자신감 있게 행동한 모습이 있었나요? |
| 자기효능감 | 어려운 상황에서도 포기하지 않고 해볼 수 있다는 태도를 보인 적이 있었나요? |
| 활기 | 수업이나 활동에 밝고 적극적인 태도로 참여한 모습이 있었나요? |
| 몰두 | 과제나 활동에 깊이 집중하여 몰두한 모습이 있었나요? |
| 의미감 | 학습이나 활동의 목적을 이해하고 스스로 의미를 부여한 모습이 있었나요? |
| 관계성 | 친구들과 협력하며 공동체에 소속감을 느끼는 모습이 있었나요? |

#### 선택 정책

- 강점·보완 요인을 합쳐 최대 3개 선택 권장
- 선택하지 않은 요인은 AI 입력값에 포함하지 않음
- 보완 요인은 부족함을 단정하는 문구가 아니라, 관련된 노력이나 변화가 관찰된 경우에 선택하도록 안내

#### 도움말

```
검사 결과는 학생의 모습을 이해하기 위한 참고자료입니다.
학교에서 실제로 관찰한 요인만 선택해 주세요.
```

### 5.3 ② 교사 관찰 입력 영역

교사가 직접 입력하는 영역이다. 요인 선택 결과에 따라 관련 상황·행동이 추천 노출된다.

#### Step 1 — 관찰 상황

**질문**: "어떤 상황에서 관찰했나요?"

- 칩 또는 체크 버튼, 복수 선택 가능
- 최대 2개 선택 권장, 최소 1개 필수

| 코드 | 노출 문구 |
|------|---------|
| CLASS_PARTICIPATION | 수업 참여 |
| TASK_PREPARATION | 과제·학습 준비 |
| GROUP_ACTIVITY | 모둠 활동 |
| PRESENTATION_COMMUNICATION | 발표·의사소통 |
| PEER_RELATIONSHIP | 친구 관계 |
| CLASS_ROLE | 학급 역할 |
| CHALLENGE | 어려운 과제·도전 상황 |
| ETC | 기타 |

기타 선택 시 추가 자유 입력 20~40자 제공 (예: 체육대회 준비, 학생자치 활동)

#### Step 2 — 관찰 행동

**질문**: "어떤 모습을 보였나요?"

- 관찰 상황과 선택 요인에 따라 추천 행동을 우선 노출
- 복수 선택 가능, 최소 1개 필수, 최대 4개 권장
- 행동 문구는 성격을 단정하는 형용사형보다 관찰 가능한 동사형으로 제공

##### 상황별 행동 옵션

**수업 참여**

- 설명을 집중하여 들음
- 궁금한 내용을 질문함
- 자신의 의견을 적극적으로 발표함
- 다른 사람의 발표를 경청함
- 교사의 피드백을 반영함
- 수업 활동에 꾸준히 참여함

**과제·학습 준비**

- 해야 할 일을 순서대로 정함
- 준비물을 스스로 챙김
- 정해진 시간 안에 과제를 마침
- 결과물을 다시 확인함
- 부족한 부분을 스스로 수정함
- 계획에 맞게 학습을 진행함

**모둠 활동**

- 맡은 역할을 성실히 수행함
- 친구의 의견을 끝까지 들음
- 자신의 생각을 이해하기 쉽게 설명함
- 서로 다른 의견을 조율함
- 도움이 필요한 친구를 지원함
- 모둠의 목표 달성에 기여함

**발표·의사소통**

- 자신의 생각을 근거와 함께 설명함
- 상대방의 질문에 적절히 답함
- 다른 사람의 의견을 경청함
- 이해하기 쉬운 표현을 사용함
- 피드백을 반영하여 내용을 보완함
- 발표 과정에서 맡은 역할을 수행함

**친구 관계**

- 친구의 감정을 이해하려고 함
- 친구의 고민이나 이야기를 들어줌
- 어려움을 겪는 친구를 도와줌
- 갈등이 있을 때 상대의 입장을 살핌
- 자신의 감정을 말로 표현함
- 대화를 통해 관계를 회복함

**학급 역할**

- 맡은 역할을 잊지 않고 수행함
- 공동으로 사용하는 물품을 정리함
- 학급 활동 준비에 참여함
- 필요한 일을 먼저 찾아 수행함
- 다른 학생과 역할을 나누어 협력함
- 정해진 약속과 규칙을 지키려고 노력함

**어려운 과제·도전 상황**

- 쉽게 포기하지 않고 다시 시도함
- 어려운 부분에 대해 도움을 요청함
- 기존 방법이 효과적이지 않을 때 다른 방법을 찾음
- 실수를 확인하고 수정함
- 피드백을 받아 결과물을 개선함
- 어려움이 있어도 끝까지 참여함

##### 검사 요인 → 행동 추천 매핑

선택한 요인에 따라 관련성이 높은 행동 옵션을 상단에 우선 노출한다.

| 검사 요인 | 추천 행동 |
|----------|---------|
| 시간관리 | 해야 할 일을 순서대로 정함, 과제를 정해진 시간 안에 마침, 준비물을 스스로 챙김, 계획에 맞게 활동함 |
| 자기정서조절 | 속상한 감정을 말로 표현함, 감정이 가라앉은 뒤 다시 활동에 참여함, 갈등 상황에서 충동적으로 반응하지 않음, 대화를 통해 문제를 해결하려 함 |
| 성장마인드셋 | 실수한 뒤 다시 시도함, 어려운 과제에도 꾸준히 참여함, 피드백을 받아 결과물을 수정함, 새로운 방법을 시도함 |
| 타인공감능력 | 친구의 이야기를 끝까지 들음, 친구의 감정과 입장을 살핌, 어려움을 겪는 친구를 도와줌, 친구가 참여할 수 있도록 기다리거나 지원함 |
| 점검능력 | 결과물을 다시 확인함, 빠뜨린 내용을 찾아 보완함, 목표 달성 여부를 스스로 확인함, 자신의 수행 과정을 돌아봄 |
| 수업태도 | 교사의 설명을 집중하여 들음, 수업에 필요한 준비물을 챙김, 질문이나 발표에 참여함, 수업 활동을 끝까지 수행함 |
| 자아존중감 | 자신의 장점을 알고 있음, 실패해도 다시 도전함 |
| 자기효능감 | 어려운 상황에서도 포기하지 않는 끈기를 보임, 새로운 도전을 두려워하지 않음 |
| 계획능력 | 해야 할 일을 순서대로 정함, 계획에 맞게 학습을 진행함 |
| 활기 | 수업 활동에 꾸준히 참여함, 자신의 의견을 적극적으로 발표함 |
| 몰두 | 어려움이 있어도 끝까지 참여함, 맡은 역할을 성실히 수행함 |
| 관계성 | 서로 다른 의견을 조율함, 모둠의 목표 달성에 기여함 |

> 프로토타입에서는 우선 주요 요인만 매핑하고, 이후 38개 전체 요인으로 확장할 수 있다.

도움말:
```
선택한 요인과 관련된 행동을 우선 보여드려요.
```

#### Step 3 — 변화·지속 정도

**질문**: "이 모습은 어떻게 나타났나요?"

- 단일 선택, 선택 사항
- 선택하지 않으면 AI가 변화나 지속성을 임의로 추가하지 않음

| 코드 | 노출 문구 | AI 표현 예시 |
|------|---------|------------|
| CONSISTENT | 꾸준히 보임 | 지속적으로 실천함 |
| MORE_FREQUENT | 최근 더 자주 보임 | 최근 관련 행동이 더욱 자주 나타남 |
| IMPROVING | 점차 좋아지고 있음 | 점차 스스로 실천하는 모습이 나타남 |
| WITH_SUPPORT | 도움을 받으면 수행함 | 안내를 바탕으로 수행하려 노력함 |
| SITUATIONAL | 특정 상황에서 두드러짐 | 관련 상황에서 강점이 두드러짐 |

#### Step 4 — 구체적인 장면 (선택 입력)

**질문**: "구체적인 장면이 있다면 적어주세요. (선택)"

- 단일 텍스트 영역
- 권장 길이: 100자 이내
- 날짜 입력 없음

##### 학교급별 플레이스홀더

| 학교급 | placeholder |
|--------|------------|
| 초등 | 예) 쉬는 시간에 우는 친구에게 먼저 다가가 다독여주는 모습이 인상적이었음 |
| 중등 | 예) 모둠 수학 프로젝트에서 어려워하는 친구에게 풀이 방법을 설명해 주는 모습이 인상적이었음 |
| 고등 | 예) 물리 수행평가에서 실험 결과가 예상과 다르자, 변인을 재설정하여 실험을 재설계하는 탐구 자세를 보임 |

##### 입력값 활용 원칙

- 교사가 입력한 장면은 AI 문구에서 가장 구체적인 근거로 우선 활용
- 입력 내용에 없는 사실을 AI가 추가하지 않음

도움말:
```
구체적인 장면을 입력하면 학생의 특성이 더 잘 드러나는 문구를 만들 수 있어요.
```

#### 생성 버튼 활성화 조건

- 요인 1개 이상 선택
- 관찰 상황 1개 이상 선택
- 관찰 행동 1개 이상 선택

비활성화 안내:
```
실제로 관찰한 요인과 행동을 1개 이상 선택해 주세요.
```

#### 권장 완료 시간

- 학생 1명 개별 작성: 약 1~2분
- 학생 2~5명 빠른 입력: 학생당 약 30초~1분
- 최소 입력: 요인 1개 + 상황 1개 + 행동 1개
- 권장 입력: 요인 1~3개 + 상황 1~2개 + 행동 2~4개

## 6. 학교급별 옵션 차이

### 6.1 공통 원칙

- 아래 구분은 서비스 UX 제안이며, 학교생활기록부 지침의 필수 입력 항목 차이를 의미하지 않음

### 6.2 초등학교

#### 우선 상황

1. 수업 참여
2. 친구 관계
3. 모둠 활동
4. 학급 역할
5. 과제·학습 준비

#### 표현 원칙

- 일상적이고 구체적인 행동, 짧고 쉬운 표현
- 기본생활과 관계 행동 중심

#### 우선 행동 예시

- 준비물을 스스로 챙김
- 친구의 말을 끝까지 들음

- 감정을 말로 표현함
- 어려운 문제를 다시 풀어봄
- 규칙과 약속을 지키려고 노력함
- 도움이 필요한 친구를 도와줌

### 6.3 중학교

#### 우선 상황

1. 과제·학습 준비
2. 모둠 활동
3. 친구 관계
4. 수업 참여
5. 학급 역할

#### 표현 원칙

- 자기주도성, 협력과 의견 조율, 감정 및 관계 조절, 피드백 반영

#### 우선 행동 예시

- 학습 계획을 세우고 조정함
- 과제 수행 과정을 스스로 점검함
- 모둠의 의견을 조율함
- 피드백을 반영하여 결과물을 개선함
- 갈등 상황에서 상대의 입장을 고려함
- 맡은 역할을 책임감 있게 수행함
- 어려움이 있을 때 적절하게 도움을 요청함

### 6.4 고등학교

#### 우선 상황

1. 과제·학습 준비
2. 어려운 과제·도전 상황
3. 발표·의사소통
4. 모둠 활동
5. 학급 역할

#### 표현 원칙

- 자기관리, 장기 과제 수행, 학습 과정 점검, 공동체 역할, 근거 중심 의사소통

#### 우선 행동 예시

- 과제의 우선순위를 정함
- 장기간 과제를 계획적으로 수행함
- 자신의 학습 과정과 결과를 점검함
- 피드백을 분석하여 개선함
- 공동의 목표를 위해 역할을 수행함
- 의견 차이가 있을 때 근거를 들어 조율함
- 실패 원인을 돌아보고 새로운 방법을 적용함

## 7. AI 생성 규칙

### 7.1 입력에 포함할 정보

```json
{
  "school_level": "middle",
  "selected_factors": [
    { "code": "타인공감능력", "category": "strength" },
    { "code": "수업태도", "category": "strength" }
  ],
  "selected_situations": ["GROUP_ACTIVITY"],
  "selected_behaviors": [
    "친구의 의견을 끝까지 들음",
    "도움이 필요한 친구를 지원함"
  ],
  "continuity_code": "CONSISTENT",
  "free_text": "모둠 수학 프로젝트에서 어려워하는 친구에게 풀이 방법을 설명해 주는 모습이 인상적이었음",
  "growth_data": {
    "has_second_test": true,
    "improved_factors": ["자기정서조절", "계획능력"],
    "t_score_changes": { "자기정서조절": 6, "계획능력": 4 }
  },
  "generation_source": "INDIVIDUAL_OBSERVATION",
  "action": "generate"
}
```

### 7.2 생성 원칙

1. 교사가 선택하거나 입력한 정보만 사용한다.
2. 검사 결과만으로 학생의 행동을 단정하지 않는다.
3. T점수, 백분위, LPA 유형명은 문구에 포함하지 않는다.
4. 검사 요인명을 그대로 나열하기보다 관찰 가능한 행동으로 표현한다.
5. 진단명, 낙인성 표현, 단정적인 부정 표현을 사용하지 않는다.
6. 교사가 입력하지 않은 구체적 활동명이나 사실을 새로 만들지 않는다.
7. 보완 요인은 부족함 자체보다 노력, 변화, 지원에 따른 수행을 중심으로 표현한다.
8. 기본 결과는 1~2문장으로 생성한다.
9. 초등은 구체적이고 친절한 표현, 중등은 자기주도성과 협력, 고등은 자기관리와 과정 점검을 상대적으로 강조한다.
10. 모든 결과는 교사의 참고 문구로 제시한다.

### 7.3 학교급별 문체 규칙

#### 초등학교

- 문체: 학부모가 읽기에 친절한 서술형 (~함, ~임), 부드럽고 따뜻한 어조
- 강조점: 성장과 격려 중심, 발달단계 고려, 기본생활습관·교우관계·정서 안정 우선
- 금지: 성적 비교, 가정환경 암시, 사교육 언급

#### 중학교

- 문체: 객관적인 사실에 근거한 전문적 어조, 구체적 활동과 결과 명시
- 강조점: 인성 및 자기주도성, 자유학기제 연계, 협업·관계 역량, 메타인지
- 금지: 교내상 기재(2024~), 공인어학시험, 특정 학교명

#### 고등학교

- 문체: 신뢰감을 주는 개조식 서술형 혼용, 역량 입증 구체적 사례 중심
- 강조점: 학업역량·전공적합성·발전가능성, 회복탄력성, 대입 평가 관점
- 금지: 대학명, 논문 게재, 특허, 소논문(2024~)

### 7.5 검사 결과 기반 초안 생성 시 추가 원칙

교사 관찰 입력 없이 검사 결과만으로 생성하는 경우 (일괄 생성 방식 A) 아래 규칙을 추가 적용한다.

- 검사 점수를 실제 행동으로 단정하지 않는다.
- "친구를 배려함"과 같이 직접 관찰이 필요한 사실을 새로 만들지 않는다.
- 검사 결과를 통해 확인할 수 있는 특성, 강점, 성장 가능성 중심으로 표현한다.
- 학생별 검사 결과에 따라 각각 다른 문구를 생성한다.
- 동일 학급 학생의 문구가 지나치게 동일하지 않도록 문장 구조를 다양화한다.

## 10. 상태 관리

### 10.1 학생별 상태 정의

| 상태 코드 | 노출 문구 | 설명 | 배지 색상 |
|----------|---------|------|---------|
| EMPTY | 미작성 | 생성하거나 저장한 문구가 없음 | 회색 |
| INPUTTING | 입력 중 | 옵션 또는 자유 입력을 일부 작성함 | 주황 |
| GENERATING | 생성 중 | AI 문구 생성 진행 중 | — |
| DRAFT | 초안 있음 | 생성 문구가 저장됨 | 파랑 |
| EDITED | 수정됨 | 교사가 저장 문구를 수정함 | 초록 |
| FAILED | 생성 실패 | 해당 학생 문구 생성에 실패함 | 빨강 |

> 나이스 최종 입력 상태를 관리하는 기능이 아니므로 "완료" 또는 "확정" 상태는 사용하지 않는다.

### 10.2 상태 전이

```
EMPTY ──[관찰 입력 일부 저장]──→ INPUTTING
INPUTTING ──[AI 생성 요청]──→ GENERATING
GENERATING ──[생성 완료]──→ DRAFT
GENERATING ──[생성 실패]──→ FAILED
DRAFT ──[교사가 문구 직접 수정 후 저장]──→ EDITED
DRAFT ──[관찰 입력 수정 후 재생성]──→ DRAFT
DRAFT ──[다른 표현/짧게/자세히]──→ DRAFT
EDITED ──[다른 표현/짧게/자세히]──→ DRAFT
EDITED ──[관찰 입력 수정 후 재생성]──→ DRAFT
FAILED ──[재시도 → 생성 완료]──→ DRAFT
```

## 11. 저장·확인·수정

### 11.1 저장 원칙

- 교사의 입력값과 수정 중인 문구는 자동 저장한다.
- AI 생성 결과를 보관할 때는 명시적인 "저장" 버튼을 제공한다.
- 일괄 결과는 "선택 저장"과 "전체 저장"을 제공한다.
- 저장은 나이스 등록이나 최종 확정을 의미하지 않는다.

### 11.2 자동 저장 대상

- 선택한 검사 요인
- 관찰 상황
- 관찰 행동
- 변화·지속 정도
- 자유 입력
- 수정 중인 문구
- 일괄 생성 설정의 공통 상황

### 11.3 자동 저장 표시

```
자동 저장됨
```

저장 중:
```
저장 중...
```

저장 실패:
```
자동 저장하지 못했습니다.
[다시 저장]
```

### 11.4 명시적 저장

학생별 화면: `[저장]`

일괄 결과 화면: `[선택 저장] [전체 저장]`

저장 완료:
```
문구를 저장했습니다.
```

### 11.5 저장한 문구 확인

학급 작성 현황에서 "초안 있음" 또는 "수정됨" 학생의 "확인" 버튼을 누른다.

```
김학생 작성 내용

작성 상태: 수정됨
최근 저장: 2026.07.24 14:32

검사 결과
강점 TOP3
[타인공감능력] [수업태도] [성장마인드셋]

선택한 관찰 정보
[모둠 활동]
[친구 의견 경청]
[친구 지원]
[꾸준히 보임]

저장한 문구
┌─────────────────────────────────────────────┐
│ 모둠 활동에서 친구들의 의견을 경청하고...    │
└─────────────────────────────────────────────┘

[관찰 정보 수정] [다른 표현] [짧게] [자세히]
[복사] [문구 수정]
```

### 11.6 문장 직접 수정

"문구 수정"을 누르면 일반 텍스트 편집기로 전환한다.

- 수정 중인 내용은 자동 저장한다.
- "저장" 시 작성 상태를 "수정됨"으로 변경한다.
- 수정하지 않아도 복사할 수 있다.
- 금지어 검증이 실시간으로 동작한다.

### 11.7 관찰 정보 수정 후 재생성

"관찰 정보 수정"을 누르면 기존 선택값을 유지한 상태로 작성 화면으로 이동한다.

입력 정보 변경 후 다시 생성할 때 저장 방법을 선택한다.

```
기존 저장 문구가 있습니다.

○ 기존 문구를 유지하고 새 문구 만들기
○ 기존 문구를 새 문구로 교체하기
```

### 11.8 직전 문구 확인 및 복원

복잡한 전체 버전 관리는 제공하지 않고 현재 문구와 직전 저장 문구만 관리한다.

```
[이전 문구 보기]
```

```
이전 저장 문구
2026.07.23 16:20 저장

[현재 문구로 복원]
```

복원 시 현재 문구는 직전 문구로 이동한다.

### 11.9 기존 문구가 있는 학생의 일괄 생성

일괄 생성 대상에 저장한 문구가 있는 학생이 포함된 경우 다음 중 하나를 선택한다.

- 저장한 문구가 없는 학생만 생성
- 새 문구를 생성하되 기존 저장 문구 유지 (기본값)
- 새 문구 생성 후 기존 문구 교체

### 12.3 저장 정책

- 자동 저장은 `StudentWritingDraft`에 현재 입력 상태를 반영한다.
- 명시적 저장 시 `savedText`를 갱신한다.
- 기존 `savedText`는 `previousSavedText`로 이동한다.
- 재생성 결과는 `generatedText`에 먼저 저장하고, 교사가 저장할 때 `savedText`로 반영한다.

## 부록 B — 설계상 유의사항

### 공식 자료에서 확인한 원칙

- 학교생활기록부 서술형 항목은 교사가 평소 학생을 직접 관찰·평가한 내용을 바탕으로 작성하는 것이 원칙이다.
- AI를 활용하여 생성한 자료를 학교생활기록부 서술형 항목에 그대로 입력하는 행위는 유의 대상이다.
- 생성형 AI는 윤문 등의 보조 수단으로 활용할 수 있으나, 최종 입력 전 허위·과장 여부와 기재요령 준수 여부를 확인해야 한다.
- 2026학년도에는 행동특성 및 종합의견의 누가기록 여부와 방법을 학교장이 정한다.

### 본 프로토타입의 해석

- 본 기능은 나이스 입력 화면이 아닌 참고 문구 생성 화면이므로, 강제 확인 체크박스와 수정 후 복사 제한은 적용하지 않는다.
- 검사 결과는 관찰 질문을 제공하는 참고자료로만 사용한다.
- 교사의 선택형 입력을 통해 실제 관찰 여부를 보완한다.
- 서비스 내 입력값을 공식 누가기록 또는 학교생활기록부 보조부로 간주하지 않는다.
