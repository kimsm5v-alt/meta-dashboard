# 생활기록부 작성 지원 기능 정의서

> META 학습심리정서검사 교사용 **생활기록부(행동특성 및 종합의견) 작성 지원** 프로토타입 기능 정의서
> 대상: 개발 리뷰용 | 작성 기준: prototype

---

## 0. 개요

교사가 학급 학생들의 검사 결과(강점·보완 요인)를 바탕으로 **행동특성 및 종합의견(생활기록부)** 문구를 손쉽게 작성하도록 지원하는 기능입니다. 검사 결과에서 관찰할 요인을 고르고, 실제 관찰한 모습을 선택하면 AI가 참고 문구를 제안합니다.

| # | 화면 | 진입점 |
|---|------|--------|
| **1** | 학급 현황(학생 목록) | 검사 GNB > **생활기록부 작성** 탭, 좌측 LNB에서 반 선택 |
| **2** | 학생별 작성 | 목록에서 학생 클릭 또는 수정/작성 버튼 |
| **3** | 일괄 생성 | 목록에서 2명 이상 선택 → `선택 학생 문구 만들기` |

- 검사 하위 서브탭: **검사관리 · 결과보기 · 변화추적 · 생활기록부 작성** 중 마지막 탭.
- 라우트: `/exam/record` — 코드 위치: `prototype/src/features/school-record/`
- **학급·학생 선택은 좌측 LNB(스코프)와 연동**됩니다. 자체 드롭다운 없음.

### 현재 구현 성격 (중요)

- **문구 생성은 mock**입니다. `service.ts`의 `generateRecordText` / `generateTestOnlyDraft`가 지연 후 규칙 기반 문장을 조합해 반환합니다. **실제 LLM(Gemini) 연동은 미구현**이며, 반환 형태(`{ text, referencedTags }`)만 유지하면 UI 수정 없이 교체 가능합니다.
- **학급/학생·상담 기록 데이터는 mock**입니다(`data.ts`). LNB 스코프(`app/LayoutV2.tsx`)의 s1~s26 로스터와 동일하게 맞춰져, 모든 반이 같은 26명 로스터를 공유합니다.
- **금지어(기재 유의 표현) 검증은 클라이언트 정규식**으로 동작합니다(§6).
- **저장·자동저장은 메모리 상태**입니다. 새로고침 시 초기화(영속화 미구현).

## 1. 공통 사항

### 1-1. 데이터 모델 (`types.ts`)

```ts
type DraftStatus = 'EMPTY' | 'INPUTTING' | 'GENERATING' | 'DRAFT' | 'EDITED' | 'FAILED';
type GenerationSource = 'TEST_ONLY' | 'COMMON_CONTEXT' | 'INDIVIDUAL_OBSERVATION';

interface ObservationInput {         // 교사 관찰 입력
  factorCodes: string[];             // 선택한 요인(강점/보완)
  situationCodes: string[];
  behaviorCodes: string[];           // 선택한 관찰 행동
  continuityCode?: string;
  freeText?: string;                 // 구체적 장면(자유 입력)
  counselingRefs?: string[];         // 문구에 반영할 상담 기록 id
}

interface RecordStudent {
  id: string;
  scopeId: string;                   // LNB(스코프) 학생 id(s1~) — 사이드바 선택 연동
  no: number; name: string; className: string; schoolLevel: '초등'|'중등'|'고등';
  lpaType: string;                   // LPA 유형
  strengths: string[];               // 강점 요인 TOP 3
  improvements: string[];            // 보완 요인 TOP 3
  status: DraftStatus;
  input: ObservationInput;
  generatedText?: string; savedText?: string; previousSavedText?: string;
  savedAt?: string;                  // 최근 수정일
  source?: GenerationSource;
}

interface RecordClass { id: string; group: string; name: string; schoolLevel; students: RecordStudent[]; }
interface CounselingRecord { id: string; date: string; category: string; summary: string; }
interface FactorInfo { description: string; question: string; recommendedBehaviors: string[]; }
```

### 1-2. 작성 상태 3분류 (`shared.tsx` · `displayStatus`)

| 내부 status | 표시 | 배지 | 목록 액션 |
|---|---|---|---|
| `DRAFT` · `EDITED` | **작성 완료** | emerald | 수정 |
| `INPUTTING` · `GENERATING` | **작성 중** | amber | 수정 |
| `EMPTY`(그 외) | **미작성** | gray | 작성 |

### 1-3. AI 서비스 경계 (`service.ts`)

| 함수 | 역할 | 교체 지점 |
|------|------|-----------|
| `generateRecordText(student, input, action, counselingTexts)` | 관찰 기반 문구 생성/재생성 | → 실제 LLM 호출로 교체 |
| `generateTestOnlyDraft(student)` | 검사 결과만으로 초안(일괄 방식 A) | → 실제 LLM 호출로 교체 |
| `checkForbiddenWords(text)` | 기재 유의 표현 검출 | 유지(정책 규칙) |
| `countChars(text)` | 공백 제외 글자 수 | 유지 |

`RecordAction = 'generate' | 'rewrite' | 'shorten' | 'expand'` (현재 UI는 generate·rewrite 사용).

### 1-4. LNB(스코프) 연동 (`SchoolRecordPage.tsx`)

- `useLayoutContext()`의 `selectedClass` / `selectedStudent`를 구독합니다.
- 반 선택 → 해당 학급 현황, 학생 선택 → 그 학생 작성 화면(수정/작성과 동일).
- 표에서 학생/버튼 클릭 시에도 `selectStudent(classId, scopeId)`로 **LNB 하이라이트를 동기화**합니다.
- 뒤로가기: 학생 화면 → 학급 목록(`selectClass`), 학급 헤더 뒤로 → 전체(`selectAll`).

### 1-5. 개인정보(PII) 정책

- 정책상 이름·학번·학교명은 AI 전송 시 마스킹 대상(프로젝트 공통 규칙).
- **현 프로토타입은 mock 생성이라 실제 전송/마스킹 로직 미적용**. 실제 API 연동 시 `shared/utils/piiMasking.ts`와 연계 필요.

## 2. 화면 1 — 학급 현황(학생 목록) (`ClassStatusView.tsx`)

검사 탭 규격(제목 24 / 부제 14 / 섹션 카드)에 맞춘 반 상세 화면입니다.

### 2-1. 헤더
- **← 뒤로 + 반 이름(예: 2-3반) + `학교명 · 학교급 학년 반`** 부제(`schoolInfo.ts`).
- 우측 액션: **문구 미리보기 · 문구 다운로드 · 선택 학생 문구 만들기**.

### 2-2. 학생 목록 표 (카드)
- 카드 헤더: `학생 목록` + 인원수, 그 옆에 (없음 — 필터 칩 제거됨).
- 컬럼: 체크박스 · **번호 · 이름 · 강점 요인 TOP 3 · 보완 요인 TOP 3 · 작성 상태 · 최근 수정일 · 편집**.
- **헤더 클릭 정렬**: 번호(숫자) / 이름·강점·보완(한글 ㄱㄴㄷ, `localeCompare('ko')`) / 작성 상태(미작성→작성 중→작성 완료) / 최근 수정일. 오름·내림 토글, 활성 열은 ▲/▼·비활성은 ⇅.
- 이름·편집 클릭 → 학생별 작성(화면 2). 편집 열은 상태에 따라 **수정**(작성 완료·작성 중) / **작성**(미작성).
- **최근 수정일**: `savedAt`(작성 중 포함 — 임시저장 시각). 이력 없으면 `-`.

### 2-3. 선택 · 다운로드 · 미리보기
- 체크박스로 다중 선택. `선택 학생 문구 만들기`: 1명이면 학생별 작성, 2명 이상이면 일괄 생성(화면 3).
- **문구 다운로드**: 선택 학생 중 생성 문구 보유자만 CSV(Excel 호환, BOM 포함) 저장 — `download.ts`. 파일명 `생활기록부_문구_{반}.csv`.
- **문구 미리보기**: 선택이 있으면 선택 학생 중 문구 보유자, 없으면 반 전체 완료 문구를 모달로 열람. **선택 학생 중 1명 이상 문구가 있으면 활성, 모두 없을 때만 비활성화**.

## 3. 화면 2 — 학생별 작성 (`StudentWritingView.tsx`)

전체폭 레이아웃. 상단은 학생 상세 헤더(← 뒤로 + `N번 이름` + 학교/학년·반 + 처음부터).

### 3-1. ① 검사 결과에서 살펴볼 요인
- **강점 요인 TOP 3 / 보완 요인 TOP 3**를 각각 한 행(3열 그리드)의 **체크박스 카드**로 표시. 카드에 요인 **정의 설명**(`FACTOR_INFO.description`) 병기.
- 선택한 요인만 아래 관찰 질문으로 이어짐(체크 해제 시 해당 요인의 행동 선택도 제거).

### 3-2. ② 선생님이 관찰한 모습
- 선택한 요인별로 **관찰 질문**(`FACTOR_INFO.question`) + **추천 행동**을 옵션 그리드(2~3열 체크박스 카드)로 제시.
- **구체적인 장면**(자유 입력, 최대 100자, 선택) 텍스트영역.
- **임시저장** 버튼: 입력이 있을 때 활성. 누르면 저장 + `savedAt` 기록, 미작성이면 **작성 중**으로 전환("임시저장되었습니다" 표시). 자동저장은 하지 않음.

### 3-3. 상담·관찰 기록 (참고, 번호 없음)
- 해당 학생의 상담·관찰 기록(`MOCK_COUNSELING[scopeId]`)을 체크로 선택 → 문구에 반영.

### 3-4. AI 생성 문구 (번호 없음, 결과물)
- **문구 생성** 버튼(요인의 관련 행동 1개 이상 선택 시 활성) → mock 생성.
- 결과 박스(글자 수 표시) + 액션(우측 정렬): **다른 표현**(rewrite) / **복사** / **문구 수정**(인라인 편집) / **저장**.
- **입력 변경 감지**: 생성 시점의 입력과 현재 입력이 달라지면 상단에 **`다시 생성`** 안내 배너(primary 톤) 노출.
- **이전 문구 보기**(헤더 우측): 직전 저장 문구 확인 + `현재 문구로 복원`.
- 저장 시 이전 문구를 `previousSavedText`로 보존, 편집 저장은 `EDITED`.

## 4. 화면 3 — 일괄 생성 (`BulkGenerateView.tsx`)

2명 이상 선택 시 진입. 단계: **방식 선택 → (공통 상황 폼) → 진행 → 결과**.

### 4-1. 방식 선택 (`GenerationSource`)
| 방식 | 설명 |
|------|------|
| **검사 결과만으로 초안 만들기**(`TEST_ONLY`) | 강점·성장 가능성 중심 초안을 빠르게 생성(관찰 입력 없이) |
| **공통 상황을 추가하여 만들기**(`COMMON_CONTEXT`) | 학급 프로젝트·발표 등 함께한 활동 반영(공통 상황·행동 입력 폼) |
| **학생별 관찰 정보를 확인한 뒤 만들기**(`INDIVIDUAL_OBSERVATION`) | 학급 참여 기본값으로 각 학생 생성 |

- **공통 상황 폼**(방식 B 선택 시): **공통 상황**(수업 참여·과제/학습 준비·모둠 활동·발표/의사소통·친구 관계·학급 역할·어려운 과제/도전 상황 중 택1) · **활동 또는 장면**(자유 입력) · **공통 행동**(상황별 목록, 최소 1개) 입력 → 선택 학생 전원에 공통 적용해 생성. 상황 변경 시 공통 행동 목록이 갱신됨.

### 4-2. 진행 · 결과(자동 저장)
- 진행 화면: 학생별 대기/생성 중/완료 표시.
- **완료 시 전체 결과를 즉시 자동 저장**(`DRAFT`, `savedAt='방금'`). 결과 화면은 저장 확인용:
  - "✓ 생성한 문구가 자동 저장되었습니다" 안내 + 학생별 **✓ 저장됨** 배지 + 문구 + **수정** 링크.
  - 우측 상단 **목록으로** 버튼으로 복귀.

## 5. 요인·행동 데이터 (`data.ts`)

- `FACTOR_INFO`: **검사 전체 38개 요인** × { `description`(정의) · `question`(관찰 질문) · `recommendedBehaviors`(추천 행동) }. 긍정 요인(자아강점·학습디딤돌·긍정적공부마음)은 강점 관찰, 부정 요인(학습걸림돌·부정적공부마음)은 **'스스로 조절·회복·노력한 모습'** 중심의 성장 관찰로 순화(생기부 긍정 기재 원칙).
- `MOCK_RECORD_CLASSES`: 4개 반(group-1~4 / 2-3~2-6반)이 **공통 26명 로스터(ROSTER)** 를 공유(LNB·검사 mock과 동일).
- `MOCK_COUNSELING`: **스코프 id 기준**(s1·s2·s4·s12) 상담·관찰 기록 — 반과 무관하게 학생을 따라감.
- `FREETEXT_PLACEHOLDER` / `LPA_COLORS` 등 표시 보조 데이터 포함.

## 6. 기재 유의 표현(금지어) 검증

`checkForbiddenWords`가 문구에서 다음 패턴을 검출해 결과 박스 하단에 경고 표시:

| 패턴 | 라벨 |
|------|------|
| TOEIC/TOEFL/TEPS/HSK/토익/토플 | 공인어학시험 |
| 대회/수상/상장/입상 | 대회·수상 표현 |
| 학원/과외/사교육 | 사교육 기관 |
| ~인 것 같음 / ~할 것으로 보임 / 듯함 | 추측성 표현 |
| 반에서 N등 / ~보다 뛰어(우수) | 비교·서열화 |

## 8. 개발 이관 시 확인사항

1. **문구 생성 연동**: `generateRecordText` / `generateTestOnlyDraft`를 실제 LLM 호출로 교체(반환 형태·문체 유지 시 UI 무수정).
2. **학급/학생·상담 데이터**: `data.ts` → 실제 API. `scopeId`(LNB 학생 id) 매핑 규칙 확인.
3. **저장 영속화**: 현재 메모리 상태(새로고침 초기화). 서버/스토리지 연동 필요.
4. **PII 마스킹**: 실제 전송 경로에 마스킹 적용.
